# 银行卡开卡 UX 样例

从[跨页流转与来源](bc-openCard-2.flow.ux.yaml)开始。四屏是[卡种](bc-openCard-2.card-type.ux.yaml)、[具体选卡](bc-openCard-2.card-picker.ux.yaml)、[短信验证](bc-openCard-2.sms.ux.yaml)和[结果](bc-openCard-2.result.ux.yaml)。`sources/` 保留开卡 PRD、入口 PRD 和四张原始设计图。`prd:20` 指开卡 PRD 的第 20 行。

双击[静态看图页](../../viewer/index.html)，选择本目录。也可以一起选择五份 YAML 和相关来源文件。同名文件用目录选择区分。审阅时点击原图编号，展开对应元素规则。编辑 YAML 或替换原图后，重新选择即可读取改动。解析库使用 npm 发行的 [js-yaml 5.5.0 浏览器 UMD 构建](https://www.npmjs.com/package/js-yaml/v/5.5.0)，许可随[看图页](../../viewer/js-yaml.LICENSE)保留。

## 后续对照口径

五份 YAML 中编号 01–12 的 `acceptance_examples` 是公开场景。待决的预选、半模态关闭、返回落点、选择保留和失败文案单独记录。键盘展开时的可用性是图 5 的观察项，是否计分需要共同的产品决定。

- 两种模型各跑一对。每对用同一宿主起点、模型、预算、工具与产品决定。两组都拿同一份 1-2 PRD、1-1 入口 PRD 和四张图，其中一组同时拿五份 YAML。
- 测试方在开跑前根据原始材料和共同的产品决定冻结预期，另换模拟银行、卡号和写入结果。从首次可验收交付中，逐项记录通过、失败或未验证，以及依据与原因。通过数以 12 为分母。
- 比较首轮通过数、需求误解返工轮数、交接到验收的墙钟、设计调用和质询阻断数。计入生成、复核和更新交接的耗时，分别记录人工与模型成本。试验开始之后建结果记录。
