# UX 行为说明取用指引

## 蓝图设计前复用已有稿

1. 优先核对本次显式提供的 `*.ux.yaml`。未指定时，从本次原始需求文件所在目录查找。有效的本次蓝图 `ux/` 草稿也可续用。按需求范围、屏幕 ID 和流转引用选择，避免为不相关的旧稿扩大范围。
2. 多屏场景打开相关流程、屏稿及其原始出处与裁决。按所在目录跟随引用。发生冲突时记录双方依据和待决问题，上游稿保持只读。
3. 将读到的 `屏幕ID.元素ID`、实际行为和待决项引用到蓝图的用例、运行流程和验收。PRD 明示规则可形成验收。推断保留依据，待决项沿流程、用例和验收继续待决。代码入口、设备定位和技术契约沿蓝图既有字段。
4. 在本次蓝图作者交回中列出实际复用的稿件、引用元素及缺口。

## 按本次作者实际收到的材料提取

每条实质规则用 `evidence` 关联 PRD 条款、设计节点、观察区或产品决定。来源路径相对于声明该来源的 YAML，屏幕可以继承流程中的来源。动态列表或选项组复用一条行模板。元素的 `copy_ref` 是单条来源引用，写法与 `evidence` 的单项一致，例如 `fig3` 或 `fig3:协议行`。文案正文用 `label` 等内容字段。

数据来源和跨页携带值写业务含义，例如所选银行支持的卡种、所选银行和卡种。拟绑定的代码方法、字段和技术契约在蓝图中说明。

逐张核实当前作者确实收到图像并能定位事实，才写 `visual.observation: observed`。在 `visual.source` 注明图源，可用 `bbox_format: normalized_xywh` 和原图左上为原点的 `[x,y,w,h]` 标出可定位元素。截图中的勾选态等以元素 ID 为键写入 `visual.depicted_state`。业务默认值按需求和产品裁定核对。单帧截图和技术惯例仅用于观察或提出带依据的推断。仍无产品依据的规则写 `status: open`，列出待决问题。

图像未送达、路由无视觉或读取失败时，在来源清单和 `visual.source` 保留图源，写 `observation: unobserved` 和可选 `reason`。省略元素截图坐标、原图尺寸和截图示例状态。本次提取的 `evidence` 和 `copy_ref` 不得引用未观察的图源 ID，包括 `图源ID:区域`。可从 PRD 与结构化设计节点继续提取；结构化设计的几何和变体写到对应 `design` 节点及设计源。只能由未观察的图确认的内容留作缺口或待决，例如协议全名与逐字文案。

复用上游稿的观察时，保留其原始出处。本次稿引用上游 UX 文件及其相应元素或区域，并记录本轮实际读图情况。输入路径、文件名和适配器声明仅说明材料或能力存在。上游产品与 UX 负责定稿。外部 provider 供料仍走既有 `requirement-source-materialization@1`，M7 校验在材料生成之后执行。
