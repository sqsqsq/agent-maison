# UX 行为说明取用指引

## 蓝图设计前复用已有稿

直接和受管的蓝图作者都先查看本次发放的绑定和原始需求。使用 `material_sources`、`requirement_sources`、`reference_images` 及真实用户指定的项目内材料。相对引用以当前文件所在目录为基点。只读已解析到宿主根内的来源、草稿和引用。

1. 优先打开本次显式提供的 `*.ux.yaml`。未指定时，仅在已知原始需求文件的直接父目录一层查找同类稿。本次蓝图写入目录下 `ux/` 已存在的草稿也可续用。按需求范围、屏幕 ID、元素和流转引用判断适用性。只影响某个控件或条件时，读取它和受影响的引用，保留其余范围。
2. 用本地 YAML 工具实际解析候选稿，按[随 Skill 分发的 Schema](../schema/ux-behavior.schema.json)校验。若没有可用的 Schema 校验工具，按 Schema 逐项检查适用结构并说明实际所做的检查。多屏场景打开相关流程、屏稿及原始出处与裁决，检查被引用的 ID 和证据确实存在。候选解析失败、结构不合法或与本轮无关时，记录原因并排除该稿。适用稿有证据缺口或冲突时，只采用可核实的部分，保留双方依据和待决问题。
3. 将已有稿及适用的 `屏幕ID.元素ID` 引用到当前蓝图的用例、运行流程、验收或验证引用，保留原出处、元素 ID 和产品待决项。上游稿和需求原件只读，保留其字节。旧稿齐全则沿用，已存在的交付不重生成。单行与多行选择、是否选中及后续动作由实际数据与规则决定，逐项保留相应验收。
4. 使用已发放的 `read-upstream` 时，在作者交回用 `extension-result` 记录实际复用的文件、已引用的元素及缺口。动作单独发放时也先执行前述核对，以确认是否需要补稿。

## 蓝图写入前判断是否补稿

只有本次已发放 `fill-missing`、涉及需要设计或验收的界面行为、用户允许，并且适用旧稿仍有缺项时，才自动提取。缺少该动作或用户排除提取时，已有稿照常可读和引用，缺稿不得自动写入。已有稿已覆盖时报告复用，无关请求报告跳过。手动调用时沿调用者给定范围和输出目录处理。

动作触发时，仅在本次已授权的蓝图写入目录 `write_dir/ux/` 写当前屏、元素、条件和必要的流转，保留上游原件和无关范围。按 [Skill 的生成步骤](../SKILL.md#生成和回读)先生成有效 YAML，再从磁盘解析回读、校验结构及实际引用，随后才把落盘稿的元素引用进蓝图用例、验收或验证。按本次作者交回的 `extension-result` 记录动作、实际文件、引用和结果。若未能解析回读或无权写入，交回具体缺口。

## 按本次作者实际收到的材料提取

每条实质规则用 `evidence` 关联 PRD 条款、设计节点、观察区或产品决定。来源路径相对于声明该来源的 YAML，屏幕可以继承流程中的来源。动态列表或选项组复用一条行模板。元素的 `copy_ref` 是单条来源引用，写法与 `evidence` 的单项一致，例如 `fig3` 或 `fig3:协议行`。文案正文用 `label` 等内容字段。

蓝图引用本次生成稿时，把 `屏幕ID.元素ID` 放在用例、验收或验证引用中。要在蓝图声明某项产品规则为权威，`provenance.source_ref` 直接引用可核对的原始 PRD 条款或已有明确授权的裁决。已获上游确认的原稿可沿其原始出处和裁决作为有据材料。只有推断依据时保留推断，依据不足时记未知并保留待决问题。文件名和本地位置不赋予产品权威。

数据来源和跨页携带值写业务含义，例如所选银行支持的卡种、所选银行和卡种。拟绑定的代码方法、字段和技术契约在蓝图中说明。

逐张核实当前作者确实收到图像并能定位事实，才写 `visual.observation: observed`。在 `visual.source` 注明图源，可用 `bbox_format: normalized_xywh` 和原图左上为原点的 `[x,y,w,h]` 标出可定位元素。截图中的勾选态等以元素 ID 为键写入 `visual.depicted_state`。业务默认值按需求和产品裁定核对。单帧截图和技术惯例仅用于观察或提出带依据的推断。仍无产品依据的规则写 `status: open`，列出待决问题。

图像未送达、路由无视觉或读取失败时，在来源清单和 `visual.source` 保留图源，写 `observation: unobserved` 和可选 `reason`。省略元素截图坐标、原图尺寸和截图示例状态。本次提取的 `evidence` 和 `copy_ref` 不得引用未观察的图源 ID，包括 `图源ID:区域`。可从 PRD 与结构化设计节点继续提取；结构化设计的几何和变体写到对应 `design` 节点及设计源。只能由未观察的图确认的内容留作缺口或待决，例如协议全名与逐字文案。

复用上游稿的观察时，保留其原始出处。本次稿引用上游 UX 文件及其相应元素或区域，并记录本轮实际读图情况。输入路径、文件名和适配器声明仅说明材料或能力存在。上游产品与 UX 负责定稿。外部 provider 供料仍走既有 `requirement-source-materialization@1`，M7 校验在材料生成之后执行。
