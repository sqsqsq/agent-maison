# UX 行为说明取用指引

## 适用范围与来稿

有界面行为的请求才提取 UX。范围取本次请求涉及的屏、元素、条件及直接受影响的跨页关系。只改一个元素时，只补该元素和确受影响的引用，保留其他标识和裁决。非 UI 请求沿原流程，显式提交的文件可作为普通需求材料。

优先读显式提供的 `*.ux.yaml`。未显式提供时，从本次原始需求文件所在目录读 `*.ux.yaml`，按需求、屏幕 ID 和流转引用选用。多屏稿读流程、所涉屏和相应来源与裁决；直接复用有效内容，只有缺项或需求变更才提取。发现已确认规则与新材料冲突时，保留两方依据并提出待决问题。可选交接稿缺失时，使用当前会话从原材料继续。

## 按图记录当前作者的观察

逐张核实当前作者确实收到图像并能定位事实。实际读到才写 `visual.observation: observed`，注明图源，可以记录原图尺寸，用 `bbox_format: normalized_xywh` 和原图左上为原点的 `[x,y,w,h]` 标记可定位元素。截图示例状态以元素 ID 为键写到 `visual.depicted_state`，业务默认值写在行为规则中；未裁定的默认值继续保持 `open`。原图的选中态只描述图中事实。

图像未送达、路由无视觉或读取失败时，只在 `visual` 保留图源、`observation: unobserved` 和可选 `reason`。省略元素截图坐标、原图尺寸和截图示例状态。可从 PRD 与结构化设计节点继续提取；结构化设计的几何和变体写到对应 `design` 节点及设计源。缺乏依据的事实保留缺口。沿用上游稿的观察时，以文件和区域为出处，并在本次作者记录中如实说明本轮是否读图。输入路径、文件名和适配器声明仅说明材料或能力存在。

## 写稿与设计前接入

- 独立调用把新稿或更新稿写到调用者指定目录。声明来源时，使用相对于声明该来源的 YAML 的文件路径；屏幕文件可继承流程中的来源。使用可移交的相对目录保留这些路径。
- 安装此扩展的 Maison 宿主在蓝图事实发现与写作前于同一作者会话执行上述取用。受管初设把需要补的稿写到本轮已签发蓝图目录的 `ux/`，并按上述范围续用该目录的有效草稿。上游原稿只读。只复用时直接引用有效稿，缺稿时当场提取。上游产品与 UX 负责定稿。
- 把相关 `屏幕ID.元素ID` 和业务意义带入现有蓝图用例、运行流程和验收条目。代码入口、设备定位和技术契约沿用原字段。PRD 明示转入验收；合理推断保留依据；影响本次承诺的待决项沿原设计决定或缺口处理。蓝图用例和验收应体现实际规则。外部 provider 供料仍走既有 `requirement-source-materialization@1`，M7 校验在材料生成之后执行。
