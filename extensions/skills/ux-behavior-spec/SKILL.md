# UX 行为说明

提供本次涉及的 PRD 或设计、已有 UX 交接稿（如有）和独立使用时的输出目录。只有文字也可提取有依据的行为。

> 用 ux-behavior-spec 读取 `需求.md` 和 `选卡.png`，只写选卡类型屏，把一份 `*.ux.yaml` 放到 `handoff/`。区分图片选中态和业务默认值。
>
> 用 ux-behavior-spec 更新 `handoff/选卡.ux.yaml` 中的协议文案，只改协议元素及确受影响的引用。

## 手动调用与蓝图缺稿动作

手动调用由调用者指定输出目录。蓝图作者收到启用的 `fill-missing` 绑定后，仅在本次要求涉及界面行为、用户允许、且仍缺适用稿时执行，写入该次已授权蓝图目录的 `ux/`。处理范围以本次涉及的屏、元素及条件为准。已有适用稿沿 [intake.md](reference/intake.md) 核对复用，保留上游字节、元素标识和裁决。

定范围时，目标页包含本次待验收规则（如标题显示所选银行）就写单独屏稿。目标页只作跳转去向时，在按钮动作或流程注明去向和携带数据，并在 `existing_screens` 登记。只改一个元素就补对应元素及实际受影响的引用。独立调用在存在实质性范围歧义时问一次并给出基于现有材料的默认范围；用户未答或明确不问时按该范围继续，将假设记为待决。受管作者沿已签范围执行。

1. 参照[屏幕模板](templates/screen.ux.yaml)、[流程模板](templates/flow.ux.yaml)和 [Schema](schema/ux-behavior.schema.json)。每屏或弹层一份稿，稳定标识为 `屏幕ID.元素ID`。动态列表或选项组用 `items_from` 指向该组数据，用 `row` 定义共用行模板。多屏流转统一在流程稿登记，屏幕入口与跨页动作引用流转 ID。
2. 按 [取用指引](reference/intake.md#按本次作者实际收到的材料提取) 核对作者实际读到的源。每条实质规则关联 `evidence`。把可定位截图区域写入 `bbox`，结构化节点写入 `design`。推断标 `status: inferred`，未定项标 `status: open`，保留问题及依据。可观察的验收例写清给定数据、操作和预期。
3. 落盘后，用本地 YAML 工具实际解析并回读。可用时校验 Schema，按[核对清单](reference/checklist.md)检查适用规则和引用。缺解析工具时，用[静态看图页](viewer/index.html)回读并说明实际检查范围。独立调用交回稿件、读图情况和待决项。蓝图作者回读后把相关元素引用到用例及验收，按本次作者交回记录实际产物和结果。

[开卡样例](examples/bc-openCard-2/bc-openCard-2.flow.ux.yaml)演示完整的四屏、一份流程和测试例子。
