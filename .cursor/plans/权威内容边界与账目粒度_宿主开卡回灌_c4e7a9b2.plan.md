## 2. 三档判定

| 项 | 档 | 理由 | 失败时的动作 |
|---|---|---|---|
| A1 手写产物与设计权威不一致 | 一档（产品真值：会按旧验收宣布完成） | 完成判定 fail-closed；**执行不拒绝** | 义务 uncovered → 责任阶段 spec/plan 入链对齐，下游按链序等待；只有身份损坏、越权、缺授权才拒绝执行 |
| A2 视觉返修越权 | 一档（产品真值：改出需求明确不要的东西、改坏相邻布局） | 返修授权 fail-closed | excluded 退出缺陷与返修；范围不明交 spec 澄清；缺陷格式不全走既有 unverified 重评 |
| B1 预算周期 | 二档（账本） | 统计边界错误不改变产品真值 | 自动按周期计；文案改准；证据血缘不动 |
| B2 纯身份变化 | 二档（形状） | 业务内容相同 | 等价则不重验；不能证明等价（解析失败/旧记录）回落字节口径 |
| 进度投影 / assess 推荐 | 二档（诊断投影） | 不参与裁决 | 投影改为与事件、评估入口同源 |

## 3. 设计

### 3.1 A1：手写产物按稳定 ID 对齐规范化投影

**唯一比较函数**（新增于 `utils/blueprint-skill-projection.ts`，与投影同模块，不新建文件）：

```ts
authoritativeContentDrift(projectRoot, feature, frameworkRoot, kind: 'acceptance' | 'contracts', handwritten: unknown)
  : { state: 'aligned' | 'not_applicable' } | { state: 'drift'; items: Array<{ id: string; field: string; expected: unknown; actual: unknown }> }
```

- 权威侧走**纯投影读取**（codex 二轮 P1，已实测；三轮修正定位）：`deriveBlueprintSkillInput` 只有一处会拿**待比较的手写产物**反向校验——`:266-272` 读磁盘既有 `use-cases.yaml` 与投影比对（`!refresh` 守卫），手写一不一致投影就 `invalid`，A1 永远读不到新验收。给它加一个只读选项（与 `refresh` 同一参数族，如 `pure: true`）：**仅跳过 `:271` 的既有文件冲突检查**，其余一律保留——`:233`「CU 映射来源 stale」核的是蓝图投影**自带**的 `change_unit_ref` 是否指向当前 CU（权威侧，若跳过则 `:234` 会先覆盖错误引用、`:262` 投影门再也看不到它），`:262` `validateChangeUnitFeatureProjection` 与 `SpecLoader` 规范化照跑；带来源戳文件的整份比对（`capability-resolution.ts:226-234`）不走该选项。
- `absent`（蓝图不携带机器内容，宿主当前形状）→ `not_applicable`，A1 不判。`invalid`（投影自身坏：蓝图/CU 解析失败、蓝图侧投影门不过）→ **不跳过**：产生具体责任缺口 `authority_projection_invalid`（acceptance→owner spec、contracts→owner plan，reason 带投影错误原文），候选不写 `satisfied_by`、assess uncovered/binding、责任阶段门 FAIL；同样不拒绝启动执行。
- 手写侧：同一 `SpecLoader.loadFeatureSpec` 规范化结果（`resolveArtifact` `:242-252` 已做）；带 `derive.blueprint-*` 来源戳的文件不经本函数（`:226-234` 现有整份比对照旧）。
- 规则（结构化，不做文本包含、不猜强弱）：
  - 记录数组按**投影合并已用的同一身份函数**匹配（`:208-212` `identity(row)` = `[module, file, holder, id ?? name ?? class ?? data]`，提取为模块内具名函数复用）；投影里的每个身份在手写侧必须存在，否则 `drift{id, field:'<missing>'}`。
  - **无稳定身份的对象数组**（codex plan review P1，2026-09-27）：身份函数取不到值的行（如 `acceptance.performance` 行的 schema 字段为 `ut_layer / ut_focus / device_focus`，`specs/artifact-schemas/acceptance.schema.yaml:13-21`，不要求 `id`、允许额外字段）按**精确 canonical 行值**比对——投影里的每一行必须在手写侧存在逐值相等的一行，否则 `drift{id: '<canonical 行>', field: '<missing>'}`；手写多出的行是补充。不为此改 schema、不猜行间对应关系。
  - 标量叶子逐值相等（`expected_result` 变了即判出）。
  - 数组分两类（codex 二轮 P1）：**有序数组为默认**（`ordered_steps`、`steps`、criteria 顺序等）按**保持顺序的子序列包含**比对——投影元素须按权威顺序逐个在手写侧出现，允许在其间或末尾插入补充元素；顺序颠倒即 `drift{field, expected: <权威顺序>}`（权威 A→B→C、手写 B→A→C 不是补充）。**集合字段**只按 artifact schema 显式登记（如 `files`、id 列表、`tags`）用集合包含。不做语义 diff。
  - 对象：投影有的键逐个比；手写多出的键是补充。
  - 顶层 `feature / source / version / change_unit` 不比（`change_unit` 由既有 `changeUnitMappingIssues` 负责）。
  - `contracts.files` 手写多出的路径不由 A1 判——写集越界已有 `findUnauthorizedContractFileReferences` 与 `cu_scope_matches_blueprint`（`change-unit-feature-projection.ts:633-645`）。

### 3.2 A2：视觉缺陷有锚点 ≠ 修复有授权

### 3.3 B1：预算以可信完成为交付周期边界

**边界**：上一次**可信的完整交付完成** = `assessFeature(...).record.state === 'ok'` 的那份完成记录的 `run_id`（`feature-completion.json` 投影指向的最新原件）。完成记录只在签发时 complete 才会生成，所以 `record ok` 即"签发时完整交付、记录至今未被篡改"；**不用** `complete`（后继之所以存在正是因为现在不 complete，见 §8 待裁决 1）。不是"源 run 有完成记录"、不是阶段 PASS、不是 `CHAIN_SLICE_COMPLETED` 终态。

**计算一次、写进既有事件**：出生时（`goal-phase-runtime.ts:5977-6034` supersede 循环前）调用 `assessFeature`（`resolveChangeUnitExpectedExecution` 取 chain/track，同 `assess.ts:49`），得 `boundary`；若 `boundary` 落在本次折叠血缘内，`buildSupersedeAuditEvent`（`goal-run-creation.ts:285-303`）为本次写出的每条 supersede 事件加字段 `delivery_cycle_boundary: <runId>`。不建周期账本、不改 events 协议形状（只加可选字段）。

**折叠**：`foldBudgetLineage`（`goal-runner-phase.ts:654-681`）增可选入参 `cycleBoundary`（fresh 出生显式传，同 `seedTargets` 先例——出生时 supersede 事件尚未进 `priorEvents`），并从 `currentEvents` 的 supersede 事件读 `delivery_cycle_boundary`（resume / progress / heartbeat 路径）。
`ancestorEvents = 祖先(seeds) − ({B} ∪ 祖先(B))`：从 B 出发同样沿 supersede 取其祖先集合，只用于求差、不计入。ae92d8：B = f829b8 → 折叠 = 97af3f + 0457a6（各 0 次回退）+ 本 run；0457a6 引用 f829b8 的边被差集吃掉。多目标 supersede 带上旧成功 run 不会清掉本周期失败 run 的消耗（它们不是 B 的祖先）。**只看当前 run 自己事件里的边界字段**，祖先里的旧边界字段不参与（避免旧周期标记误切本周期）。

四个消费方同源、零额外改动：`goal-phase-runtime.ts:4085`（heartbeat）、`:6053`（legacy 恢复）、`:6207`（runner 熔断：回退计数 `:6347`、turns、活跃时长）、`goal-progress.ts:850`。回退、轮次、活跃时长三者同一边界（#6 的 27/30 同样是上一周期残留）。

**文案**：`:6961,:9873,:9925` 等"共用预算 N 次/run"改为"本交付周期共 N 次（自上次可信完成起，含 supersede 链；已用 x）"；`backtracks_used` 字段语义随之为本周期计数。

**不变**：证据血缘、supersede 审计、`transfers[]`、completion 原件一概不动；runless（feature 载体）完成后的 fresh run 本就不折叠，无需边界；`DEFAULT_MAX_BACKTRACKS` 仍为硬常量。裁决所说"用户明确设定的跨周期硬预算"当前不存在（#7），本 plan 不新增；若将来加，走 manifest 字段并在此处豁免。
