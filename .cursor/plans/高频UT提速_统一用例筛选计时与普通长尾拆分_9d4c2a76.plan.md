## 2. 统一选择契约

统一为一个纯匹配函数：`canonicalName.includes(selector)`；未设置 selector 时全量。一个值就是一个字面串，保留大小写、标点和逗号，不按逗号/正则切分。输入是屏幕显示的完整 canonical 名字；successor-exit、DAR、lifecycle 的显示前缀也参与匹配，名字生成只留一处，执行/筛选/打印用同一个名字。

九套范围：goal-runner-testing-integrity、execution-scope、successor-exit、standalone-coding-review、real-chain、blueprint-stage-delivery、lifecycle-evolution、design-authority-repair、reliability-scenarios。删除其 9 个 `*_ONLY` 变量、独立规则和兼容别名，迁移活动调用方/当前说明；历史 plan 与 ignored 验证记录保留原貌。

模块统一导出 `runSelectedCases(selector)`，入口存在即声明前置选择能力，复用同一底层循环与病例清单；不在 runner 外再建 suite→能力/环境变量注册表。`runAll()` 未设置 selector，保持原全量语义；现有分组 wrapper 直接转发相同能力和组边界。

runner/worker 用纯参数传递 selector；不新增 selector 环境变量或模块全局 selector。因此无 selector 的之后全量、嵌套 CLI、独立进程自然不继承选择状态。直接调用方也显式传参，不靠残留环境改变 `runAll()`。

- `--case <literal>` 必须同时提供能明确命中 suite id 的 `--filter <suite-id/substr>`：先找完全相等的 id，有 exact 时只选它，没有 exact 才按子串选择；完全未命中即在派发前报错，不能回落全部套件。`--filter real-chain --case X` 只选 real-chain，不误选未迁移的 real-chain-seams；RS/DAR 公共前缀没有总 id 时仍选择全部分组。模块加载后、调用 case 之前核对 `runSelectedCases`；不支持的模块明确失败，不能忽略或调用其全量入口。
- 旧单独 `--filter` 保留 id 子串选择；未命中 id 时仍兼容显示名后置过滤。九套支持模块可用统一入口减少无关执行；未接入模块仍按原后置语义执行，不为全仓 300 余套改接口。legacy 后置过滤保留旧成功选择语义，基础设施失败始终保留；回退 case-name 后全局零命中的退出码有意改为失败，不能继续 PASS=0 假绿。
- 新 `--case` 路径对模块前置筛选后返回的所有结果统一汇总、参与退出码，父层不再按名字二次筛选；RS 共同块未命中 outcome、必要 self-check 及 driver/missing 失败不会因此被藏掉。用户目标零命中只看实际 matched 数。
- 执行前打印请求的 suite 范围、case 值、运行方式及 releaseOnly 跳过。模块加载取得能力后，在任何 case 执行前打印该 suite 实际前置/后置选择方式，不把未知能力或后置筛选说成未跑无关用例。
- 保留原汇总行、失败报告、releaseOnly、缺 CORE 失败、serial/workers1 区别、12 worker 缺省、裸 ts-node 白名单与 strict trust 清理。

## 3. 零命中、结果与计时

前置选择入口返回已有 case results，加本次真实匹配数及最小执行计时；复用现有 worker IPC 和 results-out，不解析日志判 PASS。合法空分片返回空结果/匹配数 0，不单独失败；父进程在所有选中分片结束后汇总。无论显式 `--case`，还是旧单独 `--filter` 回退到 case-name，用户指定用例筛选而实际目标全局零命中均非零，并给出明确选择范围。这一错误退出码是有意修复；旧 id 子串/回退执行/有命中结果语义保留，无用例筛选时合法空 suite 的行为不变。

匹配数只由实际 canonical 用户目标贡献；附带且不匹配的必要 self-check 不贡献命中，但 selector 真正匹配某个已显示 self-check 的 canonical 名字时，它是合法可选目标并计匹配。合成 driver/missing、worker/加载/清理失败永远不充当命中。基础设施失败不被筛选吞掉，正常断言失败照原名字/错误汇总，不自动重跑洗绿。

共用小计时辅助只包住现有执行闭包，计入 fixture 准备、执行和 finally 收尾，成功/失败都有时间，不吞清理错误。普通 case 一条时间；共享执行块一条时间关联实际产出名字，不能把相同 flow 时间复制到多个 outcome 后再求和。数据只存显式 results-out；suite 加载、启动和完整进程占用继续用上一批计时。无自动报告目录、benchmark 系统或新依赖。

## 4. RS 的共同执行块

RS 保留现有 SCENARIOS/runner/collector/registry 结构，不强塞普通 case 框架。在已有执行注册处只补必要的产出关联（引用 registry 的 scenario/branch key），完整显示名仍由 registry 的 title/label 派生，不复制标题、分支规范或另建 case 名单。按统一名字匹配选出必要 flow，仍按原次序在一个私有宿主内执行，不做 flow 并发调度。

两个已知反例必须覆盖：一 flow 产多个 outcome（如 S7），只执行一次并只记一条完整时间；S10/new-format 由 S3 的同一宿主产出，选择该名字必须执行 S3 共同块，不能只跑 S10 旧快照入口。共同块可能产生必要的未命中 outcome，这些不冒充用户匹配，也不取消原断言。

missing 校验按本次选中的共同块及其依赖确定应有分支；应有而未产出的仍失败，不把合法未选分支计成 missing。必要 self-check 继续按原责任组运行，仅其 canonical 名字真正匹配用户 selector 时计目标命中；附带自检不冒充匹配。原 `RELIABILITY_RESULTS_OUT` 单 writer/JSON 语义、RS/DAR 已有四组拆分保持；本轮不再优化 release 总耗时。

## 5. 普通前三套：实测后拆

对象只限 goal-runner-testing-integrity（现有约 160 case）、execution-scope（约 121）、successor-exit（约 28），数量以当前清单为准。先取 case/共同前置耗时，再确定少量分片，不预先承诺分组个数或精确时长。每 case 恰落一组、组内顺序和断言不变；昂贵共享前置留同组，不共享可写宿主，不建跨进程缓存。

每套一次 profiling 同时取得 case 时间和分组前单 suite 墙钟；goal-runner-testing-integrity 前后墙钟使用明确相同入口/机器条件。迁移前先用旧专用入口记录一条代表性单 case 墙钟，迁移后用 suite+case 同名对照，旧变量随后删除。不要重复多轮大集合或全量来取数据。

旧 suite id 子串仍选到全分片；canonical case 名、同名次数、结果覆盖不变。分片只在既有登记/模块处接线，耗时仅更新上一批扁平排序提示；未知条目继续优先，不新增时长注册表、调度策略或选择真源。

## 6. 新增机制的场景与收益

| 最小机制 | 已批准场景/真实问题 | 收益 |
|---|---|---|
| 纯匹配函数与模块能力入口 | 九套专用筛选的前缀/精确/逗号规则分裂，显示名与内部名不一致 | 一种字面语义，前置跳过无关昂贵 fixture；删除旧规则，不引入 env 映射/第二登记表 |
| case CLI 校验与全局匹配数 | real-chain/seams 前缀碰撞、错 suite 静默全跑、错 case 假绿；分片单独零命中被误判 | exact 优先保住定向入口，合法空分片自动继续；真实自检可选，附带自检/合成错误不伪造命中 |
| 小计时辅助和 RS 产出关联 | 不知单 suite 长尾所在；S3→S10、多 outcome 会漏执行或重复计时 | 复用结果找到真实成本，以必要共同块正确筛选，不另建 branch 调度系统 |
| 三套普通长尾的少量分片 | 现有 12worker 下最长任务仍约 773s | 缩短普通 UT 决定下限的任务，保持所有 case 与共享前置收益 |

不改生产预加载白名单、默认 worker 数；不扫描并发档位，不加自适应、自动改动选测、编译缓存、typecheck 并行化、报告锁或过程门禁。

## 7. 验收与收口

- CLI：错 suite/错 case 非零，legacy case-name 回退零命中也非零；无用例筛选的合法空 suite 不变。`--filter real-chain --case X` 只选 exact real-chain、不执行或报错 real-chain-seams，单独 `--filter real-chain` 仍按旧子串选二者；RS/DAR 公共前缀仍覆盖全部分组。显式 case+不支持模块在 case 执行前失败；合法空分片不失败，父全局零命中才失败；case 含中文、括号、标点和逗号按单一字面串。
- 用轻量模块/既有 runAll/assert 证明前置筛选没有执行无关 case/fixture；附带 self-check 不计命中，显式匹配其显示名则可选择并计匹配，synthetic driver/missing/worker 错误永远不计命中。`--case` 所有返回结果均参与退出码，无父层二次过滤；共同块未匹配 outcome 失败和真实基础设施失败均不能被吞掉。nested CLI 不带 selector 时全量，serial/worker 两路一致，清理复用上一批本轮持有资源证明，不扫删历史 trust。
- 九套都有相关目标验证；RS 包含共享多结果 flow、S3/S10-new-format、missing/self-check 与结果单 writer，DAR 原分组与显示前缀覆盖保留。活动入口中的旧 ONLY 引用清零，历史记录不作为失败项。
- 三套分组按 `(旧 suite id, canonical case 名, 同名次数)` 比较 case/结果多重集；分组映射单列，差异 0，新增或当前 HEAD 的合法变化注明。保存单重 suite 和 suite+单 case 前后墙钟，如实报告加载开销和未达目标的瓶颈。
- 目标通过后由调度者统一收口一次 `cd harness && npm test`，含 typecheck/普通 UT/fixtures 全 PASS。不自发再跑 release 或全量；只有真实失败/直接相关后续改动才补相称验证。Claude review 按首轮范围及后续直接回归收口，不借返修扩大本轮范围。
