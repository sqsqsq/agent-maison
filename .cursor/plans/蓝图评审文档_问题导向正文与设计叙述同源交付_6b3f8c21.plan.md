reader_guide 是解释性投影，不承载 acceptance/contracts/use_cases/调用事实。CU 直接引用整份蓝图时，现有摘要会展开整份目标；必须在这种**蓝图目标**进入 identityNeutralDigest 的位置，仅去掉 `review_summary.reader_guide`，同时覆盖 CU 引用和 Feature 内蓝图引用两条路径。不能递归删除任意同名对象，不能顺便剔除 rationale、alternatives 或其它既有事实字段。

纯改 guide 后，文档的精确蓝图 SHA 与正文必须变化；CU 的业务摘要不变，既有指针调和照常处理。改现有流程、契约、验收等设计事实仍影响原摘要与施工恢复，不以“写作”绕过。纯 guide 改动不反向创建 closure 决策或新义务，不要求重做原设计质询；独立读者发现事实有误时必须回原字段修设计，再按已有 revision/准入规则处理。

这里不能只验证 identityNeutralDigest。`capability-resolution.ts` 对带 `derive.blueprint-*` 戳的文件还会比较包含蓝图原始 SHA 的完整 source；已有 spec/plan 文件必须通过原调和与安全刷新接线更新来源身份，之后实际解析仍为 resolved。正例先经现有消费/冻结路径建立原完整 contracts 的等价依据，不手造摘要、不在测试中手改戳；正文及合法阶段补充保持原字节，只更新来源戳与相应身份指针。缺少原有安全刷新依据时仍沿既有责任阶段重建规则，不借润色放宽刷新条件。真实 ordered_steps 内容变化不得按说明润色刷戳放行，反例见 §7。

## 4. 渲染与参考：一个函数、一次编排

保留 collectBlueprintReviewInputs、共用目标选择/合并、renderBlueprintReviewMarkdown、原子物化与发布校验的职责。renderer 不读产品源码、需求文件内容或 Feature 派生产物，不调用模型；图片继续使用已登记路径。新 reader_guide 在 canonical 蓝图内，因此现有来源字节复核和文档精确绑定仍覆盖它。

正文优先放当前有效的作者说明，在相同位置补事实表、截图和图；不要再把同一段 summary 在概述和总览印两次。缺少说明时也使用新的阅读顺序，并明确素材局限，不保留第二套旧版渲染器。

**第8节不再由有无导读决定是否展示决策。** 作者的 decisions 导读只负责开场与跨项解释；无论有无有效导读，renderer 都按 canonical 决策顺序输出名称、按类型取的选择、rationale，以及已声明的 alternatives（option、rejected_reason、defect），复用现有结论/取值函数。被否理由与缺陷同值时只展示一次；缺失如实说明，不补造选项，不将被否方案缺陷改称所选方案代价。所选方案的代价若已写在原结论或理由中则保留，未写就不声称已经解释。

已完成的第8节确定性文案规则保留，本轮不重做：组件选型决定没有label时，标题优先取已解析target_ref节点的label/name，已有中文目标名直接显示，不生成翻译或新设计事实；无法取得时沿现有名称/id回退。按[组件资产五级选型](../../docs/concepts/component-assets.md#五级选型)显示中文，custom为“自定义实现”，未知值不猜译；custom没有component_ref是正常状态，不输出“组件：未记录”，确有引用仍保留。被否理由/缺陷的字段不同则均保留、相同只显示一次；按分列或分行组织避免表头/前缀重复和“。；”拼接，只处理该展示位置，不全局改作者标点。无备选仍如实说明，不补造方案。已有锚点、正文/参考归属及内容完整性不变。

逐项解释只在正文出现一次，原决策稳定锚点随该条目放置；参考保留类型、状态、责任方等元数据及指向正文的回链，原设计引用仍可解析，不重复整段理由/备选表。参考区及稳定地址表只链接正文锚点，不再次生成相同id；全文所有显式锚点id必须唯一，不能只验证链接存在目标。写作指引不再要求在 guide 复制逐项问答；随包样例与真实写作由作者整理开场。存量 guide 的多个段落仍按原顺序保留，不通过文字相似度删段或推断其覆盖了哪些决策；如有重复由既有阅读修订处理，不能因此隐藏 canonical 条目。不加新字段、语义去重器或覆盖登记。

**第13节同样不允许导读遮蔽待确认事实。** 在有效导读之后（无导读或过期时也一样），直接从当前 discovery.facts 中选 subject 为 term: 且 provenance.extraction_method 为 headless_assumed 的条目，展示术语名、当前假定解释及“作者自行假定，待确认”；不要求作者把它们复制进 must_review，不因章节文字声称已裁决而移除。另列 review_summary.must_review，以及 decisions_and_gaps.gaps 的问题、现有状态、已有责任方和解除条件；状态缺失据实说明，已解决项明确区分，不统称待确认或根据段落猜状态。缺少 must_review 不能隐藏术语或 gaps，空集合不造缺口。

第13节只负责把已有事实展示给评审人，不能机器判断导读与事实语义一致；两者冲突由既有读者要求作者修订，未明确确认不能抹去 headless_assumed 或把偏离需求的提议标成已授权。参考仍保留完整术语/来源与精确gap记录，正文链接沿既有来源/参考锚点；must_review 全文正文一次展示，参考保留入口回链。复用当前输入，不解析会话记录、不生成新的审批清单文件，不加确认状态或准入/readiness门。

**共用展示支持一层扁平记录数组（8261c322已完成，本轮保留）。** 在blueprint-review-projection.ts现有prose/meaning共用取值链处理，不只特判errors，也不要求作者把semantics改成items。直接数组及业务对象的数组值均按原顺序逐项展示：记录的业务键值均为字符串、数字、布尔值或null时，输出“键：值”；记录之间清楚分隔，不丢code/meaning等已声明值。沿现有所在结构的来源/验证引用分列与元数据过滤，不把provenance等混进业务说明，也不将业务字段按名称全局删除。

标量数组维持原行为，false、0、显式空字符串、null和空集合保持区别；空数组/对象仍为“无”。若某个记录含更深对象/数组，或数组成员自身是嵌套数组，仅该深层成员沿既有占位，不递归展开、压平成新字段或把其它扁平成员一起隐藏。不改canonical，不以模板/模型改写业务语义；沿现有Markdown转义及cell链接分段，保留管道符、换行和显式空串的既有保护。ad508cb9的三条错误代码与处理均应可读，来源/验证引用仍可查。

参考仍直接取蓝图和 CU，必须保留精确集合。迁移现有渲染能力而非另写 acceptance/contracts/use_cases 解释器；禁止用模型重新生成字段、默认值、方法、文件或验收明细。共享目标、多 CU 同名编号使用“来源目标＋条目编号”身份；正文编号指向正确条目，参考全量保留。

目录树合并公共前缀，能还原全部精确文件路径。用途只用已声明组件/接口说明；长说明可链接接口明细，不自动归纳成新责任。作者需要短说明时，放在其已有职责说明里；本批不加 files 用途映射字段。同名 index.ets 显示所属模块，目录不扩成授权。

业务施工段逐个当前 CU 讲交付、模块、依赖和安全中间态。精确谓词、provides 编码、继承验收集合、文件授权映射、替代历史在参考可查；不把整体一并隐藏。ready、run 状态、完成结论继续在原输出/closure，不混进设计事实。

图沿用 generated_graphs 和现有 parser。代表性流程的选取、拆图与标签由设计 agent 完成，node_refs/已有调用设计与图文一致由原质询/独立读者核对。静态图只画已经声明的调用；不得从 ui_bindings、data_boundaries、名称或目录猜调用者。图的放置用 graph_ids，不造另一份图真源；旧图是否搬至参考按它的阅读目的决定，不能重复画两份充数。

P1用例键名清单明确schema_version：最终产物必须有，分散片段可由其中一个提供，feature/source由派生补写而版本不补。说明specs/artifact-schemas/use-cases.schema.yaml是兼容身份/形状，不是完整语义必填表，并链接已发布profile的业务UT用例模板与原消费规则，作者按适用模板填写；P1不写死版本数值、不增加全局默认值或支持版本集。HMOS模板与sample-flow示例目前版本不同，本轮不顺带统一其值，也不扩大只看版本有无的检查。MIGRATION、blueprint-design-inputs、宿主指南和相关规格中“不新增整图缺失扫描”的旧句原位替换，不在文末叠加相反规则。

新问题只在蓝图入口映射为WARN，复用现有issues、默认文本/JSON及评审参考诊断输出；原拆CU派生、readiness和后续阶段继续按原id、严重级别和责任处理。`--write-review --json`同轮能看到路径与缺键，作者沿现有一轮定向修订纠正，未解决如实披露；不新增停机门，不由renderer加steps/expected/name等别名，不自动修正canonical。无材料或合法分散片段不得因本接点被报成必须补齐整份Feature产物。

新格式提升既有 BLUEPRINT_REVIEW_FORMAT；旧 review 只提示按当前格式重建。复用原来源变化/集合变化/格式升级诊断，不新增准入状态。所有自动生成接点继续调用相同的确定性 renderer。

## 5. 谁写、何时写、怎样控制成本

|---|---|---|

| B1 自动修复 | 修复 agent 仍只改授权草稿，可按 source_refs 在授权内定向复核；当前公开摘要命令只读 canonical，框架发布时还会改根 provenance，因此 B1 不记录新说明摘要。成功发布使原摘要失效后提示“评审说明需更新”、展示当前事实与完整参考；后续设计 owner 复核已发布 canonical 后刷新说明摘要 | 框架持锁段零新增模型调用；不扩 B1 授权、不自动盖戳、不加通知机制、不因文档观感停止 run |

八问中适用于当前请求、但正文答不出的问题，作者必须在既有一轮定向修订中逐项处理：事实已有则补解释或图，事实矛盾则回原设计承载修正，材料不足则明确未决及所缺依据，不编答案。不能把“正文没有逐项取舍”等缺失降为非关键表达而只在最终报告提一句；仍未解决的适用问题须明确披露，不能宣称人读验收通过。请求只到蓝图、尚无 CU 时如实说明未拆分/本次不涉及，不为凑八问擅自开工。已能回答问题后的措辞偏好可以如实报告后继续交接，不要求额外签字，不新增 readiness/准入门、评分状态或无限改稿循环；真实授权或事实错误仍按原责任修正。

**派出质询时必须转达规则。** 新要求原位放进P1 §4既有派发条目，主agent写进实际任务：先正文八问再核源、核已有页面/入口证据对应、首次对原需求、删减建议保住要求，以及每次作者修订并重渲后的当前正文通读。不能仅写作者收尾段或依赖质询者自行打开P1。传达的是通用规则、材料位置与当前文档，不是父设计结论或宿主正确答案；无新增任务协议、文件、状态、回执或固定调用轮次。派单原文不可见时仍按既有实际行为验收口径，不因此卡t5或声称读过加密原文。

**已有页面/入口的证据识别（本轮，落P1§1发现与现有术语/事实条款）。** 需求提到已存在的页面或入口时，按当前范围把名称对应到实际页面、路由或入口调用位置；不能只有业务模块映射。按需核标题字符串资源的真实使用位置、路由注册/调用与入口链，必要时读同系列前序需求解释上下文。名称相近、同名多处时按触发路径与证据消歧；不靠类名猜测或“否则无法满足”的循环理由。只查本次相关对象，不全仓登记所有页面，不要求三类证据必须同时齐备，不为识别页面启动编译或真机测试。

识别结论及依据沿已有discovery.facts的value、provenance/source_ref与现有视图/说明承载；term.canonical_module继续表示模块，不能塞页面类名，也不新增page_id、路由映射字段、glossary页面注册表或机器校验。区分当前对象身份与未来目标行为：代码证明需求指向哪个已有对象，不据此取消用户要求的改变；前序需求只作相关上下文，不替代当前有效要求/裁决。

证据足以确定时由Maison据证定，不把可自行查清的问题交用户；证据缺失/矛盾且不能确定时如实记假定/未知，沿既有must_review/未决承载表达，不写成已调和或已确认。新页面不得伪装成已有事实。允许设计owner在授权范围内自主作设计取舍，但须说明是方案选择，不能冒充原文事实或用户裁决。质询首次核原需求时一并核本次已有页面/入口对应，不新增独立scope或确认门。

**首次核源从原需求出发。** 保留先正文八问、之后才读YAML/需求的顺序。在既有scope核源中逐条对照本次适用原需求、有效人类裁决、最终设计与验收；一条需求含多项行为，不能以“目的地正确”概括其它携带数据/清理要求也满足。沿既有报告引原句/出处及设计/验收位置，追溯表可导航，但来源路径、scope齐全或检查PASS不证明行为满足。明示交接核原句、持有者/接收者、渠道及清理时机，不新增字段、表单或持久账本。

**质询建议本身须保住原要求。** 质询者因安全、分层、简化等理由建议删除/收窄明示交接、跳转或清栈前，必须引用受影响原句和适用裁决，说明风险，并提出兼顾原行为与约束的替代做法。无法兼顾或缺依据时，沿已有未决决定/待确认说明原要求、拟变更、理由和影响，不能直接建议删后称已解决。已有明确人类裁决按其真实范围生效，不扩大到未裁决的行为。一次性内存交接只能作为设计可选做法，不固化银行样本答案或统一实现。

**作者核对接受建议的授权。** 质询意见不等于用户变更授权；优先换实现同时满足原行为，必要偏离沿原待确认承载报告，未获明确授权不得删除或标成已裁决。步骤、旅程、图、生命周期和验收同次保持一致，不改测试工程原需求迁就产物。

**返修复核受影响的原要求。** 保留旧意见与修法直接影响的原行为/验收复核，防止安全整改删交接、导航整改改变清理范围；不每轮重审全部需求或追加无关架构意见。本轮增加的每次修订后正文通读按下段执行，两者侧重点不同，不能用只核被点名位置代替跨段一致性阅读。仍沿已有报告/流程，不增加状态、签字门、停机原因或评分循环；未解决如实披露，不冒称t5通过。

**每次修订后通读当前正文（本轮，落P1§4派发与§5修订收尾）。** 每次作者完成本轮修订→按现有摘要规则重渲review.md→独立质询方在该轮返修复核中都从头读到“技术与追溯参考”之前，不依赖事先判断哪轮是最后一轮。不能只看diff、旧意见定位或凭初稿记忆；实际读到的是修改后的文件。只核两件事：改过行为在导读、流程、恢复表、待补问题等各处是否一致；没有事实/授权依据的推断或待确认处理是否被写成已调和、已定或已确认。需要判断依据时仅定向查相关原文/事实/精确验收，不重读全附录源码、不重新回答完整八问或开展全新架构评审。

这不是新增固定阅读轮次、独立reader或签字流程，而是规定每次修订并重渲后的既有复核都通读当前正文。初稿未改且该轮已经通读的就是当前正文，不要求无变化再读一次；复核之后作者又改稿，包括改根契约再重渲，旧阅读不能冒充新稿通过，应按同一规则复核当前正文。每轮增加的是正文阅读，不无限重启整套八问。通过/剩余矛盾沿原质询答复自然语言报告，不新增回执、哈希登记或机器门。主agent在P1§4实际派发任务中明确转达此顺序和两项范围，不假定质询者自行打开P1；仍不附父设计结论或样稿答案。

入口“质询前先渲染、改canonical结束前重建”的顺序已实现。本批入口Skill不改，保持既有148/150行；新增责任只原位落在P1 §4/§5及现有引用文档，不挤入口或增加入口调用。

这里的草稿结构可用指已有加载/渲染入口能生成文档，不要求先通过含质询结果的完整准入。现有 `--write-review --json` 可在 checker 未准入时仍返回已生成的 review_document；应分别看文档生成状态和准入问题，不能以整体非零退出码一概判没有草稿，也不能反过来把文档生成成功当准入通过。尚待质询的草稿可交读者，实际解析/来源或其它设计错误仍按原规则修，不新增检查种类或吞掉原 BLOCKER。

独立读者需具体标出缺少图示解释的关键链路、普通宽度仍需放大的图、位置与解释不相符的图，以及只有一段且没有回答本章问题的位置；段落少本身不是缺陷。先读实际正文再核YAML，不能用YAML已写齐代替正文已讲清。按§2核内容边界：打开验证码是一段；用户提交、保存并显示结果是一段；结果页点击完成后清栈、首页刷新是新的界面步骤。保存链内的调用返回不指导航返回，不按层或方法继续拆。成功/失败须分别讲清，可同图分支，不要求两图；图放第4节相关小节旁本身合法。默认总览只在简单场景说明原因后省略，不实现计数门禁。无图像仍审图源，只有字号/布局/缩放标未核验，不提前读YAML或冒称视觉通过。沿原质询输出记录，不新增图校验或自动评分。

写作要求：段落讲完整因果；首次解释代码角色；避免斜杠串、省略主语和“已实读/F1 已修复”等过程话术。指引只纳入写法规则：导航清理用前后页面栈的例子说明，S4 与加密分开写，验收主题标注原编号；不放目标样稿原文或银行卡开卡栈例子，避免 t5 写作者提前看到答案。

首屏必须使不了解本项目实现的读者知道现状、变化、结果与边界；先使用可读的原字段，仅改表达时优先写 guide，不强制填满所有 guide 小节。中文名优先：决定和generated_graphs填现有中文label，稳定decision_id/graph_id保持原值，缺label沿既有回退、不自动翻译或新增检查；App根问题和独立质询回答使用中文，代码/API名可保留。图中消息先讲调用意图、必要时括注原方法；关键取舍的选择、理由、被否方案与已有代价写回原决策字段，guide 只开场，不复制逐项问答或用编号串代替解释。产品非目标与本次只执行设计的阶段状态分开。独立读者第一项先只读首屏复述方案，再沿正文回答八问，不靠熟悉框架替正文补全含义；页面栈例子继续保留实际 source_refs。

发布件写作指引附一对明确标注“仅示例”的好坏表达，使用与本次宿主无关的场景，不把目标样稿当提示词。示例先给定事实“用户点击保存；Repository 写入成功才通知页面；写入失败保留输入”，再对照坏写法“保存/成功/失败由 Repo 处理”和好写法“用户点击保存后，页面等待 Repository 写入。写入成功才显示保存完成；失败时保留输入，供用户重试。”示例只示范表达，不为消费者增加业务要求。

来源原文和截图只供设计阶段核读；新事实先进入原设计承载，不能只写在 guide。素材不支持的解释按 C 类列为缺口。独立读者先只看正文回答，再有针对性核源；机器只能核编号/引用/集合，不能保证“解释无新增事实”。沿用既有质询输出/报告存问题，不新增一份签章记录。

成本记录随 §7 的真实 component-design 回归完成：记录原设计任务、既有独立质询和定向修订的起止/调用次数，以及首次文档生成、派出质询和正文读取的实际顺序；底层模型请求数不可见则标明，不以工具次数代替。不另派写作 agent 做成绩更好的样稿，不另建计费仪表、A/B 基准系统、阅读凭证或预算状态；不以耗时长短解释质量，自动物化接线仍零新增模型调用。
