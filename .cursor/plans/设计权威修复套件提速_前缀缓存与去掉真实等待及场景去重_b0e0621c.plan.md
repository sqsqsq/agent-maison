## 1. 目标与范围

目标：design-authority-repair 单跑墙钟从约 49 分钟降到 20 分钟以内；一次完整发布测试（unit --release + fixtures）少 30 分钟以上。

范围只在 `harness/tests/`（套件、共享 helper、夹具）与必要的测试缝。不改任何运行时判定、生产缺省值与发布流程；不删检查、不减断言、不改场景期望；不引入多进程并行。

## 3. 方案

### 3.1 共用前缀走同路径缓存（t1）

- 缓存放在共享 helper 里（`lifecycle-evolution.unit.test.ts` 的 `withHost` / `handWrittenCompletion`，以及 design-authority-repair 的 `derivedContractsCompletion`），三个套件都经它们取前缀。
- **同路径**：同一进程内，宿主根目录改为固定路径（例如系统临时目录下按进程号命名的一个目录），每条用例开始前清空再装入。首次遇到某段前缀时真跑，跑完把整个根目录（含 `.git` 与 run 内的 `trust-cp`）复制一份到缓存区；后续用例把缓存复制回**同一路径**。这样前缀记录里的绝对路径原样有效，不需要任何重定位。
- **缓存键**：前缀名 + 快照夹具版本。缓存只在本进程内有效，约定进程内源码、夹具与相关环境不变（反向变异一律在新进程里跑）；不另建源码身份机制。复制失败、恢复后目录哈希与存档时不同，一律回落真跑并在日志里写明原因。
- **隔离**：缓存只在本进程临时目录里，进程退出即删；不落到仓库，不跨进程复用。实施第一步按下表逐项核对前缀会碰的状态，查不全的前缀不缓存：

  | 状态 | 处理 |
  |---|---|
  | 环境变量、工作目录、argv、测试缝 | 驱动已有 finally 恢复；新加的测试缝按目标调用安装、恢复，不被前缀真跑的复位提前清掉，也不漏到下一例 |
  | 场外检查点 | 真链驱动用的是宿主根下的 `trust-cp`，随目录复制；外围 runner 另有进程临时 trust 根；不碰真实 `~/.maison` |
  | 模块级缓存 | 除配置缓存外还有技能索引、Hylyre schema、动态 profile 的 require 缓存；只处理实际被消费且可能变化的，逐项列出；不清空整个 require 缓存 |
  | 锁、线程、子进程 | 运行时已有释放锁与清心跳；用例里起的 worker 与子进程在用例结束前等待退出（S16-r2 / r2b 的空转子进程补等待） |
  | Git、链接、文件属性 | 只用仓库本地 Git 配置；夹具里指向源码与依赖的 junction / symlink 复制时保留链接语义，哈希按链接目标字符串计；内容哈希不证明 mtime 等属性等价，凡依赖 mtime 的判定逐项核对 |
- 收益估计：约 30 条 × 30 秒 ≈ 15 分钟（design-authority-repair），reliability-scenarios 与 lifecycle-evolution 另有收益。

### 3.2 去掉真实时间等待（t2）

- 冷却：S16-c3a 的等待来自显式 resume 的冷却守卫 `checkTerminalResumeGuard`。只在这一次调用期间，由测试侧临时包装既有守卫、传入几秒的 `cooldownMinutes`，`finally` 还原；不增加全局可变的冷却配置。断言全部保留：等过冷却后同一 run 真正再次执行（第二次 `run_start`）、调用计数、回放 attempted 后不再派发、后继判重。S15 等"冷却期内不回拨时间、不带强制旗标"的用例继续用生产缺省值，不受影响。
- 心跳：只缩短 `goal-phase-runtime.ts` 里驱动真实心跳定时器的间隔（按调用安装、恢复），保留真实回调；S16-r3 在编写调用里等到本 run 的 heartbeat 事件、锁、beacon、`progress.json` 都实际更新（受 4 秒进度节流，约等 4 秒加一个间隔），再断言不判越界。不为节流另加测试缝。
- 两处改动各配一条检查：不安装时取生产缺省值；安装后异常退出，缺省值已复位。
- 收益估计：约 5 分钟。

### 3.3 与可靠性场景去重（t3）

- design-authority-repair 里与 S14–S16 场景分支跑同一流程函数的 11 条注册用例（A2 主线与两个反例；S15 的 rejoin（含未修）、successor、supervisor、B2；S16 主线、两个绑定失效支、`S16-c1` 无预授权）移出，只在 reliability-scenarios 里跑。
- 移出前逐条核对并迁移，给出"原用例 → 断言与注入现在在哪"的映射表，一条不丢。已知要迁的：A2 主线的 `onFirstPlan` readiness 竞争注入（不在共享流程的缺省行为里）、精确 verdict 序列、CU 写入不归因给 agent、报告渲染、指针与绑定有效性；两个 A2 反例的"不重评、跳过原因、兄弟错误码"；`S16-c1` 外层的 B1 分类断言。S15、S16 主流程的大部分断言已在共享函数里。
- 本地只验这几条时，用既有的 `RELIABILITY_SCENARIOS_ONLY=S14,S15,S16`。
- 收益估计：约 18 分钟（发布测试中两套件合计）。

### 3.4 不做

- 多进程分片：用例依赖进程级测试缝与全局状态，改造面大，收益依赖机器核数，先不做。
- 删除用例、合并断言、放宽判据、跳过真链。

**§3.1 状态核对表的落实**

| 状态 | 落实 |
|---|---|

| Git、链接、文件属性 | 只用宿主仓库本地 Git 配置（随 `.git` 复制）。junction 用 `readlink` + `symlink(…,'junction')` 复制，哈希按链接目标字符串计、不跟随。文件与目录 mtime 随复制保留（相对先后与真跑一致）。依赖 mtime 的判定逐项看过：相对比较（本 run 起点之后、两文件先后、取最新目录）不受影响；与 `Date.now()` 比较的只有 run-control / 收口互斥文件的陈旧判定，这些文件只在操作期间存在。 |

**放弃的准确性**

- 目录哈希不含 mtime 等属性；mtime 由复制保留（毫秒精度），恢复后文件的绝对"年龄"比真跑时更老。与 `Date.now()` 比较的判定只涉及操作期间才存在的互斥 / 锁文件，前缀结束后未单独列目录核对它们不存在（按运行时收尾释放锁判断）。
- 宿主根固定后，`resolvedBlueprintRefs` 原有的"蓝图之外的文件变化不使缓存失效"上限从单例扩到同进程的后续用例；`cachedHeadShaByRoot` 若将来有 withHost 用例在进程内写 summary 会跨例取到旧 HEAD（表现为变红而不是假绿）。
- 恢复后的进程内运行时模块状态是"上一例最后一个 run 之后"，不是"前缀 run 之后"；运行时在 run 开始时重置这些状态，未逐项证明。
- 缓存键不含源码身份，依赖"进程内源码、夹具不变"；反向变异都在新进程里跑。本次工作区同时有其它代理在改源码，进程启动之后源码被改不会使缓存失效（与 plan 约定一致）。
- 测得的耗时在宿主对照实验并行、测试进程为 BelowNormal 的条件下取得，与 final2 基线的机器负载不同，数字只作量级比较。

### 2026-10-03 返修（codex 实施检视：1 项必修 ④）
