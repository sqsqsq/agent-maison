发生），拦下的是自己：把一次工具崩溃放大成整场致盲+判死。

## 1. 减法原则（用户裁定 08-14 + 既有顶层哲学）

1. **能力 = 一次实测**。金丝雀说了算，run 级生效；不存在第二套「策略轴」可以否决实测
   结果。能力答案全框架唯一。
2. **产物问题 = 反馈，不是罪**。检查不过→告诉 agent 改哪里；绝不因「产物没验过/没写完」
   剥夺能力、钳档、判死。halt 只留真冲突（Auto-match over fail）。
3. **防伪造默认零成本**（08-06 裁定存量执行）。账本/hash 链/锚/世代/receipt 全删。
   fake-pass 的真防线 = 金丝雀能力真值 + contradicted 确定性反证（OCR 实锤矛盾仍 FAIL）
   + testing 阶段设备实测证据链（f3a8c6d2 产物，不动）——不靠 spec 期的自声明审计。

## 4. 风险与边界（诚实推演）

- **删 attestation 后 agent 谎称看图怎么办？** contradicted 扫描仍在（OCR 实锤矛盾
  = FAIL），testing 设备实测仍在；spec 期「未验」不再连坐。曾经的 fake-pass 事故
  （semantic_layout 自声明绕门禁）由「声明==SSOT 投影」机械校验 + SSOT 由 runner
  产出承接——agent 改不了 SSOT，抄错即 FAIL。
- **真盲宿主跑强 1:1 需求？** 钳档仍会发生（金丝雀 none/unknown），由盲档地板告知
  流程承接；不再有第二刀判死。

  噪音结构性消失。
