# 扩展按插件分目录，存量按需手工接入

**交付目标**是在 Framework 3.1.0 首次对外发布前确定唯一的按插件布局。已对外发布的 Framework 3.0.0 使用平铺的清单 1.0。旧宿主只升级框架时，原有扩展保留在磁盘上。是否接入存量能力、在哪个宿主使用、哪些资源组成一个插件，由使用方和提供方决定。[3.0.0 发布说明](../../RELEASE-NOTES-v3.0.0.md) · [3.1.0 发布状态](../../RELEASE-NOTES-v3.1.0.md) · [总纲 §11.2](../goals/复杂能力建设目标_能力架构蓝图到部件演进与变更单元闭环_75411223.goal.md#112-稳定内核与-provider-接缝语义)

## 1. 为什么由提供方确定边界

旧布局按类型列出 Skill、知识、Hook 和规则。一个 Hook 引用了某份知识，只能确定两者存在依赖；资源应随哪个插件升级或退出，需要提供方明确声明。

| 场景 | 改动及可观察收益 |
|---|---|
| 一个插件要一起管理脚本、知识和 Hook | 来源包与宿主副本按插件同形组织，能在一个目录找到声明和资源，单包生命周期可验。 |
| 平铺资产缺少可靠的插件归属 | 保留旧资源，维护者可按实际需要自行整理来源包，再走通用安装入口。 |
| 用户更新框架或运行普通业务 | `framework-init` 不承担扩展升级。运行时只消费新注册的包，旧根不会触发搬移、命令执行或业务全局阻断。 |
| A 启用、升级或删除后，B 拉取同一份代码 | 调用前核对本工作区实际产物。缺档和旧版知识都能自动准备，停用能立即停止新投递，删除后可清理 B 的本地残留。 |

本期撤销原草案里的通用 1.0 迁移器、暂存换根、自动路径改写，以及“迁移扩展目录”“刷新扩展入口”两个 init 专用任务。`1.1/2.0/2.1` 属于未对外发布的内测清单，同样按需要从来源整理。**新格式插件自身的同源版本升级**仍属于 `/extension` 的正常管理能力，沿用动态退出、替换和重新启用语义。[既有启停计划](实例扩展协议增量_动态启停与生效阶段选择_ee85b0d3.plan.md)

## 2. 唯一运行布局与清单分工

以下用默认 `doc/extensions/` 举例，实际使用宿主 `paths.extension_dir`。插件 ID 是稳定的包名，目录名与该插件清单的 `name` 一致。新的公开清单采用 `schema_version: "2.0"`。宿主清单与插件清单具有明确且互斥的结构，通过清单角色及字段区分内部旧版 2.0、合法插件和损坏的新清单。Framework 开发窗口为 `3.1.0`。

```text
doc/extensions/
├── .gitignore                           # 稳定的通用规则及删除插件后仍需生效的本地忽略范围
├── manifest.yaml                        # 宿主登记已安装的插件与宿主选择
└── <插件ID>/
    ├── manifest.yaml                    # 提供方对本插件的声明
    ├── skills/<Skill ID>/               # 下列资源目录按需提供
    ├── knowledge/
    └── hooks/
```

- **顶层清单由宿主写。** 按插件 ID 记录安装来源、团队开关、绑定选择与阶段覆盖、导入文件归属和指纹。插件版本只由提供方在插件清单中维护。宿主清单不持久化 `activation_result`、`pending_cleanup`、升级暂存或本机启用版本。检视从团队选择、插件声明、现有在途请求和磁盘上的产物判断当前状态，操作中的暂存由该操作管理。
- **插件清单由提供方或自有插件维护者写。** 一个包可提供多个 Skill。安装、整项启停、升级、卸载、漂移核对以插件 ID 和目录为单位，单个绑定仍可选择或改投阶段。保留业务入口、原作者 `extension-result` 和请求追溯。裸 Skill 在安装副本生成最小包清单，初装仅供手动调用。按描述推导的动态命令沿既有明确确认流程。
- **路径按插件定位。** `ref`、`cwd`、`outputs` 和脚本资源相对该插件根解析。`MAISON_EXTENSION_ROOT` 对该插件命令指向包根，业务交付继续使用项目相对路径与原写权。不同包可有同名内部文件。对外 Skill 名、独占能力及同一规则槽的冲突沿既有消费者的次序或冲突语义处理，诊断点名相关插件。
- **管理边界一致。** 安装将本地来源导入 `<扩展根>/<插件ID>/` 并登记宿主选择，消费者读取已登记包。重装、动态 `run/undo`、在途占用的非阻塞待清理回执和重试均按该插件处理。外部包只清理归属明确的受管资源，原地自有来源、宿主改写和已交付业务产物按原归属保留。

### 工作区准备与退出

- **一个版本源。** 插件改动时由提供方升版。同源、同版本的受管来源内容发生变化时提示先升版。插件声明所需产物和可观察的就绪判据。知识包可用既有索引中的生成版本与插件清单的 `version` 比对，成功生成整包后写入。纯静态知识核对其原文，其他格式可声明只读检查，npm 可按锁定依赖和本机安装结果判断。协议不要求额外的 `.local/` 或每插件健康检查脚本。
- **消费前准备。** 手动 Skill 与自动时机在正式交给消费者前，核对本次要用的已启用插件。命中正确版本且必需产物可用时复用。同名旧版、缺失或无版本依据的可重建产物，先清除该步独占的已声明本地产物，再在插件目录内执行已声明的可重复生成步骤并复查。同一工作区并发准备一次。失败指出原因，本次停用相关投递，其他插件继续，后续调用可重试。普通请求不改团队开关。后台作者消费已准备的材料。裸 Skill 从描述提议出的动态命令沿用先展示、确认后登记的边界。
- **逐 clone 自动执行只产生包内文件。** 每步按声明区分 `local` 与 `repo` 产物；已跟踪文件、来源文件、手工资料、其他插件及项目根均在自动清理范围外。跨目录链接不能扩大范围。仓内共享知识由维护者更新。非文件和项目级效果由维护者显式执行一次，并按声明退出；读请求不会替维护者执行。升级按原团队开关保留动态退出、替换、重新启用语义。终止新投递后，未完成请求占用的资源保留到交回。
- **Git 归属。** 稳定的扩展根 `.gitignore` 在插件删除提交后仍须覆盖本机依赖和提供方声明的本地产物，安装和升级维护框架段，保留手写段。可将插件附加规则绑定到该插件路径。裸 Skill 仅使用通用规则，额外忽略由维护者选择。源清单、脚本、锁文件和 `repo` 产物应可正常提交。
- **跨 clone 删除。** 插件被 Git 删除后，下次从 `/extension` 发起操作（包括查看）或正式准备请求时，由入口在配置的扩展根清理仅剩受管忽略文件且没有在途占用的已删除插件目录。无法确认是已删除插件、仍被注册、含跟踪或未忽略文件、宿主改写或有效在途引用时，保留并说明。清理前后 `git status` 都应干净。底层检视和校验只读；入口做过的残留清理可以在回执看见，查看本身不执行插件启用命令。

## 3. 旧宿主与 framework-init 的处理

- **空根或新根**沿正常 `/extension` 管理流程安装、校验和刷新入口。检视与校验区分入口残留清理和插件启用。通用 loader 只接受新宿主清单和已登记的插件清单，删除按旧清单语义执行、扫描旧根级维度目录和合并来源声明的分支。
- **遇到旧根**时沿已有格式诊断指出路径，并提示“旧版扩展未加载，请按需手工整理后重新接入”。普通业务继续使用框架和 profile 自身输入。明确需要旧插件的请求能看到具体缺口，不能报告已投递。管理命令不会把非空旧根当空根覆盖，也不更改旧桥、运行记录或宿主手写资料。无需逐版本解析旧清单来给出这个提示。
- **`framework-init` 不办理扩展升级。** S1/S2/S3/S4 和 [init 任务计划](../../harness/scripts/utils/init-task-planner.ts)无需新增扩展任务或依赖。初始化已有的通用适配器渲染若读取扩展信息，只使用新 loader 返回的已登记包。人工接入后的入口物化由 `/extension install` 或现有 `materialize` 负责。
- **手工切换入口**由 `MIGRATION.md` 说明。选好需要接入的包，待使用旧路径的工作结束，再自行留存旧根并建立干净的新根，或按现有配置指定一个新的扩展根。按正常安装回执核对宿主清单和受管入口，检查旧桥中的遗留路径。保留旧副本供维护者对照，运行时只认当前配置下的新登记。

## 5. 验收与完成条件

| 场景 | 通过条件 |
|---|---|
| 旧根遇到新发布件 | 在保留 3.0.0 平铺资料的隔离副本执行只读检视和一次普通业务请求。有手工接入提示，旧清单、脚本、业务资料及旧入口指纹一致。新运行没有投递这些旧项，普通业务继续。配置了新根后，旧资料不再参与查找。 |
| 插件接入与包间隔离 | 在任选的验证宿主安装两个测试插件，检视能区分两者。核对一次真实消费与交回。停用、升级或卸载其中一个时，另一个仍可用，宿主自有资料和已交付产物保留。 |
| 两份真实 Git clone | A 用管理入口装、启用并提交。B 首次正式使用可准备，第二次复用；A 升版后 B 同名旧文件仍在，下一次使用只重建一次。删除必需产物可补齐，脚本失败不投递旧材料，其他插件仍可用，重试能恢复。用 `git ls-files` 核对共享文件，用 `git status` 核对本地产物。 |
| A 删除插件后 B 拉取 | B 的忽略文件仍在时状态干净。下一次管理操作或准备请求清掉仅剩受管忽略文件的残留目录。含未忽略资料、仍被跟踪或有在途引用的反例不误删。停用、卸载均保留已交付产物。 |
| 新协议与发布内容 | 空宿主安装来源包及裸 Skill，回归阶段选择、动态启用、逆序退出、在途待清理、漂移与按包隔离。随包示例可直接安装，源码仓的可选插件未进主包。正常用户不需要先运行专门的迁移或 init 任务。 |

实施收口运行 `npm run openspec:validate`、仓根 `npm test` 和上述隔离宿主验收。本次计划修订只校验计划结构、引用及文档差异。
