# 盲档意图自动定档——三正交轴与「非关键冲突不阻塞」 (f6b2d9a4)

状态：**v7 已实施完毕（2026-07-24），未提交待用户 review**

## 背景（2026-07-24 宿主实测，银行卡需求）

启动语句：「/goal-mode 开发添加银行卡需求。需求描述在 doc/features/原始需求/1-银行卡/
原始需求.md，参考图就在该 md 同目录。结构/颜色/布局尽量一致；没有高保真，logo/图标/
插画等资源就从这些原始截图里裁剪获取。开始吧。」

被解引用的原始需求.md（ground truth）：
- :3 「同目录参考图为 UI 真源；结构/颜色/布局尽量一致。**无高保真素材**时，logo/图标/
  插画可从原始截图裁剪获取」——素材声明，非验收口径声明；
- :85 「对照同目录参考截图保真实现（**pixel_1to1 意图**）：结构、颜色、布局、文案位置
  **尽量**与参考图一致」——质量目标 pixel + 严格度 best-effort。

现状故障链（全部实核）：
1. 意图三态无「严格度」「素材」概念：「尽量…一致」命中 ambiguous 词表
   （fidelity-shared.ts:196），「pixel_1to1」字面量不被强意图正则识别（:175，
   `\b1\s*to\s*1\b` 被下划线挡词边界）；
2. 含混+盲+有参考图 → await_human_fidelity_tier 阻塞求人（goal-runner.ts:3665 +
   check-spec pregate）；
3. `--fidelity` fresh CLI 路径静默丢弃（override/transition 被 if(argv.manifest)
   圈住 :2905）；buildGoalManifestFromInput 本身不保留 fidelity/fidelity_receipt
   （goal-manifest.ts:345-364）——手写 manifest 同样丢；
4. 盲+acquisition:crop 每项恒需真人确认（checkBlindCropProhibition c3 :613）——
   「素材从截图自动裁剪」在盲档无自动化出路；
5. pixel 硬门禁不区分「目标高」与「验收硬」：19 处 isPixel1to1 消费面把 WARN 抬
   BLOCKER/要求人确认/封顶 completion，best-effort 需求即使过了 preflight 也会在
   下游被拦（v3 P0-1）。

## 用户裁决（产品哲学，冻结为设计原则）

> 最重要的不是随便给用户反馈失败，而是根据用户的描述，自动匹配到框架能支持的最合适
> 方案来进行；不是非常重要的冲突，不希望随便给用户返回失败。对用户侧要做到智能化和
> 自动化，交互体验和交付质量是终极目标。

## 数据模型：三正交轴 + 两谓词

| 轴 | 取值 | 来源 |
|---|---|---|
| 质量目标 desired_fidelity | pixel_1to1 / semantic_layout / reference_only | 需求意图检测（解引用合并文本） |
| 严格度 acceptance_strictness | best_effort（默认）/ hard | 需求措辞检测（视觉邻域限定） |
| 素材策略 asset_acquisition_mode | auto_crop / user_dir / approximate | 需求输入/显式用户声明（ui-spec 仅为投影） |

- **三段式路由公式（v4 P0 冻结）**——CLI/manifest/receipt 真实进入决策，不再只保
  「字段不丢」：

  ```
  inferred_fidelity  = 需求文本推导（T1；ratchet 锚点，永不被洗掉）
  selected_fidelity  = resolveRequestedFidelity(inferred, manifest.fidelity,
                         downgrade_receipt_valid)   // 只升不降；有效降档 receipt 才许降
  effective_fidelity = clampFidelityByCapability(selected, capability_snapshot)
  ```

  fidelity-intent.json 三值全存（inferred / selected / effective）。CLI 合法升档
  真实进执行目标；有效 receipt 降档后真实按低档执行且下游 pixel 硬门禁不再被激活。
- **两谓词拆分（v3 P0-1 核心，判据 v4 定稿）**，经既有单点收口
  （context.fidelityTarget 同链）下发全部 19 处消费面：
  - `isPixelExecutionTarget(ctx)`：**effective**=pixel_1to1——驱动**执行类**逻辑
    （高质量提取、diff/度量、视觉轮次严格度）。best_effort+有视觉照样全力执行；
  - `isHardPixelContract(ctx)`：**effective**=pixel_1to1 ∧ strictness=hard——驱动
    **裁决类**逻辑（质量缺口 WARN→BLOCKER 抬升、crop pending→FAIL、placeholder
    禁令、requireConfirmedIdentity 真人确认、completion 封顶）。不用 desired 判
    ——有效降档 receipt 放行 semantic 后，desired 不得重新激活 pixel 硬门禁；
  - **确定性完整性错误不受 strictness 影响**：文件损坏/路径逃逸/伪造证据/账本篡改
    等恒 BLOCKER——strictness 只调质量缺口的严重度，永不豁免诚实性防线。
- **唯一阻塞形态**：**selected**=pixel_1to1 ∧ strictness=hard ∧ clamp 降档 →
  DEFERRED（出路=换视觉模型 / fidelity_downgrade receipt / 改需求）。其余一律 proceed。
- 银行卡需求预期裁决（冻结为 fixture）：desired=pixel_1to1、strictness=best_effort、
  asset=auto_crop、effective=按能力钳制、action=proceed、零询问零 HALT；
  质量缺口全程记视觉债务，不触发 pixel ratchet HALT、不要求真人终验。

## 任务

### T1 意图检测升级（质量目标轴 + 严格度轴 + 优先级规则）

- 强意图词表补规范枚举字面量：`pixel_1to1`（词边界修正）/`semantic_layout`/
  `reference_only` 显式声明各自直接落轴；
- 旧 ambiguous 词类（「与截图一致/按截图/参考截图还原」）→ desired=pixel_1to1
  （瞄准截图；严格度另算，能力 clamp 兜底）——**ambiguous 态删除**；
  无任何视觉措辞 → desired=semantic_layout（现默认不变）；
- 严格度词表：hard=「必须像素级/不接受降级/达不到不得继续/严格验收」类；
  best_effort=「尽量/尽可能/接近/当前条件下最优」类 + **缺省默认**；
- **优先级三规则（P1-5）+ 对应 fixture**：
  1. 显式规范枚举声明 > 「参考截图」类推断（:85 型「pixel_1to1 意图」优先生效）；
  2. 否定表达优先：「不要求 pixel_1to1，semantic_layout 即可」不得先命中 pixel
     （否定邻域检测先于关键词命中）；
  3. hard 词须与视觉/保真语义在有限邻域内关联——需求其他章节的「严格验收」
     不得翻转视觉档位严格度；
- 「没有高保真（素材）/没有设计稿」不进质量目标轴——进素材轴（T4）；
- desired 每次由需求文本推导，effective 永不回写 desired（ratchet 不变）。

- **单点初始化（v4 P1-1，v5 扩素材轴）**：路由决策抽纯函数
  `resolveFidelityRoutingDecision(...)`（输入=需求合并文本 + manifest.fidelity/
  receipt + capability snapshot；输出=三值 + strictness +
  **selected_asset_acquisition_mode** + decision）：
  - goal 模式：canary 完成后、agent invoke **前**由 goal-runner 调用，
    落 snapshot + fidelity-intent.json；
  - phase-driven 模式（v6 顺序修正 + v7 责任唯一冻结）：
    **唯一流程所有者=skills/feature/spec Step 1**、**唯一执行实现=runner-owned
    initializer（CLI/纯函数）**——在生成 spec.md **之前**解引用 $ARGUMENTS/
    需求文档写 fidelity-intent.json，并把决策注入 **spec 工作上下文**（首次产出
    不依赖 agent 自觉理解）；cursor/claude/codex 等薄入口**只透传用户输入+引导
    读取 Skill**，不初始化、不写 artifact（agent-adapters spec「薄入口不含
    skill 逻辑」约束；防单 adapter 特修与双写 intent.json）；harness-runner 只
    **加载+复核**已落盘决策供 CheckContext，不承担 phase-driven 首产；
  - check-spec pregate 降级为**复核**同一决策（决策漂移=BLOCKER），不再首次生产；
  - 无 goal run_id 时定义显式 phase execution identity（如 `phase:<feature>:<phase>`
    形态）参与 decision_id——禁 `undefined+requirement_sha` 的含混 ID；
- goal preflight 与 check-spec pregate 同步改（两模式拉齐）：
  await_human_fidelity_tier 分支删除；非真冲突一律 proceed；
  真冲突（selected=pixel ∧ hard ∧ 降档）保持 DEFERRED；
- **strictness 下发（P0-1）**：经 fidelity-intent.json → harness context 单点收口
  （与 fidelityTarget 同链新增 acceptanceStrictness），19 处消费面按两谓词改判：
  执行类照旧读 pixel target；severity 抬升/人确认/封顶改读 hard contract；
- **capability snapshot 同源硬约束（P1-4）**：hasVision/ocrAvailable 由单一

  routing_input_digest 至少覆盖 manifest.fidelity/receipt 与 capability snapshot，

  source ∈ requirement_self_declared / auto_default / explicit_cli /

## 不变式（冻结）

- ratchet 锚点=inferred_fidelity（selected/effective 永不回写 inferred）/
  视觉债务与 completion 诚实记账：不动。
- 人确认主背靠**重新定界**：hard contract 与「声称 pixel 已达成」的判定仍须人确认；
  best_effort 不声称达成、以债务记账达成诚实——两条路都不许假称质量。
- 确定性完整性错误（损坏/逃逸/伪造/篡改）恒 BLOCKER，不受 strictness 影响。
- crop verified 生产者语义不降；c3 免除仅限严格生产者产出+绑定复验有效的消费态。
- 范围纪律：消费既有 clamp/单点收口 context/裁决器/绑定复验，不新造阶梯、
  不新造信任机制、不动 receipt 链。
