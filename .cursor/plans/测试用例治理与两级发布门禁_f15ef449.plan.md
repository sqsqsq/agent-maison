创建日期：2026-11-05（America/New_York）。开发窗口：3.1.0。起草基线：main / 85372eab，加当前其它任务的未提交改动；不是干净发布切点。

本轮授权仅起草、检视及修改本计划。实施待另行启动；不修改源码、测试、AGENTS 或旧计划，不运行测试、基准、打包，不操作宿主/设备，不干预任何在途全量。计划不绑定实施者、执行模型或调度安排，检视调用和原件留在验收记录。

## 1. 目标、事实与边界

依据[四条总设计原则](../../docs/overview.md#121-四条总设计原则)，目标是缩短正常迭代到宿主回灌的时间，同时让测试保护真实交付行为。减少数量是去除重复、过时机制及无效前置的结果，不按删例比例验收。

- 测试树为 D:/1.code/am-h58-accept，HEAD 85372eab，实际受测输入快照为 992c93a23df9f888aa1ee6e07820459ce1b067f1d767d5994da8b644cbd85774，含该树的HMOS补修，不能只凭HEAD当作干净基线源码。

按完整报告 groups[].totalMs 重新求和：最慢20组占累计worker时间34.98%，最慢60组占64.44%；208组至少一分钟。79组至少五分钟，共1,162.31 worker·分钟，占71.87%；938组不足一分钟，仍合计179.46 worker·分钟。移去最慢60组后，余下累计仍575.08 worker·分钟，按同耗时12槽位估算47.93分钟。因此不能只后移最长链，小组总量及每组固定开销同样必须下降。上述是累计进程耗时及调度模型，均不是墙钟归因或新性能承诺；先前“20组占97%”“其余都是短组”的估计不作为方案依据。

### 1.3 先定性剩余44项，不先跑第二轮长测

以原67项失败中扣除已定向处理的9项直接回归及14项目录问题后的44项为本次清理输入，不把它们直接命名为“HEAD上的44个生产缺陷”。先读原失败及现有4个干净基线对照，按共同根因将每项关联到“生产缺陷／测试问题／待定”、证据、受影响日常承诺和最小下一步；同一根因只需一个代表性最小复现，不能用4个代表代替全部44项的归属说明。

优先核查“[execution-scope] 适用控制依赖存在环”的未捕获异常：区分合法生产输入生成的错误依赖、可反馈给责任方却直接终止的恢复缺口，以及夹具手造非法依赖/旧迁移前提。若属生产，先报告具体触发、用户后果和最小修法，取得授权后再改；未知保留原红，不能改catch、删边或手填合法范围让测试通过。已确认的测试前提/环境问题可在本计划实施范围内修正。

日常域的基线红项按责任收口：测试侧的过时前提、环境准备和夹具问题属于本批修复，不作为长期排除项；初轮已确认的生产侧问题按共同根因汇总一次，逐项列触发、后果、最小修法及目标回归，统一报用户授权，不为每个重复红项逐次询问。等授权期间可继续独立的登记/测试侧治理，生产源码不先改，相关日常红项及“不可称可回灌”的边界保留。后续若出现此前无法合理发现的真实新生产问题，另报新证据，不把初轮授权扩大到新范围。

不执行已生成的904组选测，也不为基线返修重新跑一遍 test:changed 的宽集合。只复跑原失败组、同根因的最小替代红例及修复确实影响的直接依赖；生产代码变更另做必要typecheck。未受影响绿组复用原有效结果。除§4.3明确的一次初始日常试跑外，完整验证统一并入§9最终集中验收；正式 npm test 仍留正式发布阶段，不再插入一轮小时级选测或正式全量。每项从原红到新位置或已修证据的去向保留在既有本批记录中，不新建运行时状态或平行缺陷系统。

## 2. 两级门禁的产品契约

| 维度 | 日常回灌门禁 | 正式发布扩展门禁 |
|---|---|---|
| 用途 | 普通开发、plan收口和中间候选包；通过即可按原授权打候选包交宿主回灌 | 正式发布前补齐日常域之外仍有价值的边界、复杂恢复、兼容和组合场景 |
| 保留 | 核心函数/解析/真实授权与数据完整性短测，正常交付与常见恢复，近期宿主事故的有效回归，全部现存有效fixture；候选构建另加消费者安装/更新冒烟 | 深历史捕获、多代迁移、多故障组合、全部中断点和完整运输对照等 |
| 默认 | 其余未列入热点的真正短组默认日常；不能仅因名为历史事故、异常、capability就后移 | 已标releaseOnly继承原归属；热点治理后保留的长组合明确登记，不能变成无效测试收容区 |
| 完成依据 | 本次必要日常项通过；候选包另须包校验及同zip消费者冒烟 | 正式 npm test 覆盖两域全部现存有效组和fixtures，通过后才满足完整测试门禁 |
| 时间 | 测试总墙钟目标10–15分钟，含一次编译、枚举、typecheck、执行、归并和清理；包/安装冒烟另计 | 单列耗时与慢组，不预设另一个虚假分钟数 |

日常全集另设工程验收的总量指标：沿现有口径 W = Σ groups[].totalMs / 60000，目标不超过150 worker·分钟，上限180 worker·分钟，基准仍为12个worker。W不是CPU时间；150–180分钟除以12只对应12.5–15分钟的理想工作量下限，不能替代真实10–15分钟墙钟验收。父进程编译、枚举、typecheck、覆盖归并及清理单独对账；现有totalMs在worker close时取值，随后发生的父进程归并/清理不包含在W内，不能漏报或与其重复计算。预算是改造验收目标，不新增运行时强杀、截断或跳过用例的开关。W或墙钟不达标都不能把提速目标标完成。

## 3. 固定开销和阶段检查的有限拆解

先用既有逐组totalMs/startupMs/loadMs/executionMs及footprint.mergeMs，对function、capability、fixture和938个短组作一次汇总，不逐条审计。startupMs量到run-start，已经包含loadMs，二者不可相加；executionMs包含测试自身setup/teardown，剩余差额列为bootstrap/回收余量。全量覆盖归并累计约24.74分钟，发生在父进程，其值不是CPU耗时，也不能直接和W相加推墙钟；应核其队列阻塞和文件I/O成本。每组附加清理时长当前未单独记录时，先说明未知，只在下述有限样本测量补必要时标。

从一个普通短组和一个有共享前置的组观察固定成本：fork/模块加载、反复建立框架工程、依赖扫描、快照/哈希、覆盖采集归并和清理，分别区分每组固定开销与业务断言执行。优先合并重复断言和真正共享的setup、复用现有共同执行块、去除反复解析和无用拷贝，不为每个小断言重新建立完整业务链。合并仍保留原断言、精确选择及来源归属；有全局状态/可变fixture冲突的组不得硬塞同一执行块。不新增通用批处理平台或关闭必要验证换速度。

从已结束全量的真实测试run读取 harness_start/end、调用日志和原材料，排除被复制进夹具的历史宿主events。核对阶段、invoke和当前运行目录，区分模拟作者、正式门禁和读取/评估，不把旧现场时间线当本轮耗时。

在稳定隔离副本上，最多选一个常见coding检查和一个慢恢复中的检查，单worker各做一次小型观测；优先利用已有时标。只在需要区分成本时使用一次性开发测量，报告以下互不重叠区间：

1. 创建进程/guardian到门禁入口；
2. TypeScript加载及启动初始化；
3. 真正检查，包含必要工具子进程；
4. 材料解析、文件哈希、快照/绑定读取、报告写入及回收；无法直接分离的列为未分解余量。

总时长与子区间对账，说明采样开销；12路争抢的对照复用本轮原件，不为测量再起整批长链。既有报告的只读汇总可先做，实际样本观测放在§4.3初始试跑之后，与针对性拆短一起进行，不作为调整登记和首次试跑的前置。首轮固定开销与阶段检查调查合计限约30分钟，不能靠连续等待45分钟超时来“测成本”。

源码已有 affectedCheck、readCurrentCheckObservation、checkWorkConditions 和有效结果跳过分支。逐次判断重跑是实际输入/源码/义务改变、材料被框架输出误判失效，还是检查前评估本身昂贵；不预先认定“每轮必重跑六阶段”。能在测试夹具/前置/重复读取边界解决的，归测试治理；若需要改生产缓存、检查适用性或完成语义，另报授权，不删检查或放宽绑定换速度。耗时调查先做，但未经授权的生产优化不成为完成分层的无限前置。

## 4. 热点去留和拆短规则

### 4.1 有限审查范围

附表A是本轮最慢60组的实施去向提案，保存原组身份/完整用例名的对应摘要用于核对。实施时核实独有断言与实际消费点，不能只按名字删除。保留行为与去向写在同一份结果表，更新为已落实/真实阻塞；不先另开一轮清单审批再重做plan。

其余组不逐条审，按现有套件家族批量处理。§2.1的七个家族治理覆盖各自全部组，包含与附表重叠的热点、30–60秒组和更短组，不能把低于一分钟当作治理豁免。全家族原始累计分别为：goal-runner-testing-integrity-late 79.48、goal-runner-testing-integrity-early 67.38、execution-scope-runtime 44.88、design-authority-repair-content 110.27、design-authority-repair-runtime 59.82、execution-scope-prepare-late 28.76、lifecycle-evolution 131.26 worker·分钟；这是全家族数，已含附表对应行，不能重复相加。

家族只登记代表行为、公共前置、日常/正式分界和预算差额，不要求对全部组写独立价值报告。按规则把历史组合和长变体后移，把正常边界提取短测，治理共用启动/复制/读取开销；不能把整个混合套件一刀切后移。

剩余确实小于一分钟的组默认日常；明显守着已删机制或完全重复的顺手合并/删除，不展开千组价值审计。但938组的179.46 worker·分钟已接近日常总量上限，不能把“单组短”当作零成本：必须按§3的家族汇总减少重复启动/前置/采集成本，先列治理后预计W与组数，再作一次实际验收。若日常W仍超过180或墙钟超过15分钟，复用耗时结果在同一家族作最多两轮窄调整；仍不达标就报告实际时间、剩余热点和最小选择，不静默扩成全仓重构、不提高承诺阈值冒充达标。

### 4.2 拆短的执行边界

- 原全量的ok/status及原失败输出是去留前的依据。附表60组中25组原红或未完成；删除、合并、换短测或改层级之前，先按共同根因作最小定性。可复用已有后续定向结果，不要求重新跑原长链或逐条复现44项。测试过时/环境/夹具原因修正后再迁移；生产原因或尚未定性的，不得并入绿组或由绿色短例替代，必须保留原红例，或先证明最小新例仍复现相同错误行为及相关生产接线后再替换。属于日常承诺的保留在日常并维持真实失败，生产返修另报授权。超时只能说明未完成，须保留其原件和最小定位任务，不能改名后消失。
- 例如控制依赖环不得因直接从其后构造合法状态而被绕开；初始Q否定后无改善的红例必须保留真实公开入口的反馈/交回/重读时序。只有原问题已修且对应最小回归通过，才可按覆盖去向删除原链；已删机制的原红，先证明其仅依赖退役行为而非仍存的产品错误。
- 单一判断直接测生产函数，以独立输入/预期行为验证，不用同一个函数生成预期答案再自证。
- 接线用例从被测步骤前最近合法状态起跑，必要前置由生产writer、解析器、准入/出生入口生成。可复用现有不可变fixture及原件，按当前真实绑定重核；不能手填PASS、伪造完成记录/调用血缘或关闭独立核验。
- 已证实可重用的前置不要在每个变体重新走完整设计→施工→验证。只替换真实外部工具/模型边界；被测发布、权限、恢复、材料消费和完成函数保持真实执行。
- 一条运行的多个有效断言保持共用；仅因文件或历史编号不同而重复的链合并。独有断言迁移通过后删原重复链，不在两域各保留一份同义长例。
- 共享执行块不可人为切断。包含日常必要行为时先提取该行为或缩减前置；未完成拆分前不能靠整组后移丢掉日常保护。
- 已退役的默认预算、阶段派工和旧闭环步骤只删对应断言；用户明确截止、取消、真实授权、当前范围绑定与合法恢复继续保护。不因旧“closed/六阶段”前提而强迫现行工作单元回到旧管线。

每组两轮仍不收敛或调查/返修超过一小时就停该组，报告价值、已花成本和下一步最小方案。日常必需行为未落实仍算未完成，不能为省时间自动改为正式域。

### 4.3 实施顺序：先登记和一次试跑，再针对性拆短

1. 先只读归属原红和现有独有保护，按两域契约调整既有登记，补最小日常过滤/结果作用域接线；此时不重写业务长链。原红不能因调整登记被藏掉，混合执行块未拆前按§4.2保留必要保护。用必要的执行器短哨兵和typecheck验证过滤没有漏组、空跑或把daily记为full。
2. 在稳定隔离输入上跑一次初始 test:daily，保存组数、红项、W、各预算桶与每组开销、墙钟和仍缺的正常代表链，摸清差距。该次是明确允许的诊断试跑，不是904组选测或正式全量；有红、未补必要主线或未达预算时不称可回灌。不为获得漂亮时间中途改测试或强杀慢例。
3. 试跑结束后，依实际差额做§3的有限成本观测、最慢60组与七家族全部组的拆短/合并、正常代表链补齐和测试侧基线修复；日常生产侧问题按§1.3汇总一次等授权。每轮只复跑失败组和直接受影响的最小单元，不能每次返修重跑日常全集。
4. 最后冻结治理后的输入，按§9跑一次最终日常全集验收。若初始试跑已满足全部必需行为、预算和稳定输入要求，且之后没有改变源码/测试/登记，则直接复用，避免重复。通常本批是一次初始诊断加一次最终验收；纯文字返修不增加全集，真实执行改动只按新增影响决定必要复验，不自动无限重测。

## 5. 日常的正常主线和常见恢复

日常固定保留3–5条彼此不重复的代表链；可在一条运行中合并有关断言，不按组合数铺开：

代表链按既有可独立执行的用例组计数：3–5条即3–5个代表执行组，同组多个断言仍算一条链。单条直接用该组的实际起止/totalMs核验，不能把合并组耗时除以断言数，也不在共享运行中猜测拆出多条链的用时；无需新增逐断言计时系统。

每条代表链的工程耗时上限为3分钟，3–5条合计不超过§2.1的15 worker·分钟。单条从worker启动、合法setup、被测调用/门禁到teardown及子进程结束计时，父进程额外归并/清理仍按§2单列。初次试跑可记录尚未达标的旧链，最终代表必须自然完成且满足上限；超过上限就继续缩减无关前置或报告目标未达，不把timeout改为180秒后强杀、跳过真实检查或按快返回错误冒充达标。

| 代表 | 必须观察到的真实生产行为 |
|---|---|
| 从零设计到当前原请求的合法终点 | 空特性目录和真实形态原始需求进入公开prepare/next/report路径；专用作者产出蓝图，独立质询、准入、canonical CU及必要施工/检查真实接线；至少一条到Feature/CU正式完成，原请求要求的testing不能被跳过 |
| 缺引用及无改善收敛 | 输入包含暂不存在的引用，质询缺引用不能反复购买调用；完整反馈到原责任作者，实际修稿后重新核验并推进；同条件无改善保全暂停，重复report/next不重派；不伪称缺必需证据也完成 |
| 常见产品失败后修好 | 从合法最近前置制造真实小型编译/断言失败，反馈到合法作者，实际改源码后原验证通过并继续；保留原失败，不手填期望报告 |
| 一次调用/进程异常后接续 | 受控网络失败或实际子进程中断后，沿现有恢复入口保留授权、成果及必要独立验证，避免已完成工作重跑；重复变体放正式域 |
| 需求真实变化与审查返修 | 按影响仅补必要工作，旧有效结果保留，真实不匹配不能借旧PASS完成；可与上一代表合并，保证最终仍只有3–5条 |

初设用例复用 initial-design-delivery/repair 的公开入口及当前质询修复证据；补的是该事故形状与从零到真实终点的接线，不声称仓库此前完全没有初设测试。模型替身按收到的真实请求/反馈行动，不预填下一轮答案。

“真正编译/测试”明确使用仓内已声明依赖与自含工具链：从harness依赖解析TypeScript编译器（或其API）实际编译临时小工程，再用Node及仓内现有自含测试执行实际产物/断言。测试profile/provider沿既有注入边界明确受控，不依赖本机hvigor、DevEco、Java/签名服务或设备，不凭发现某个全局命令就改变用例路径。缺仓库必需依赖应报告准备失败，不改成SKIP/PASS。HMOS真实工具链效果留给既有专项/宿主验收，不混入这3–5条日常代表。设备及模型边界可受控，不能把夹具成功宣传成真实模型或HMOS设备效果。运输的基本签发/接收/恢复契约各保留短例，完整双运输长对照归正式域。

本批不建设符号级选测或新的调用覆盖服务；更细粒度优化仍依真实成本决定。文案选择的最小正反验证见§9，不为证明这一条再跑独立整仓全量。
