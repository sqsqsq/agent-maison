# 复杂能力建设 3.1：M6 真实宿主准入与回灌契约

## 1. 计划定位与边界

M6 是本总计划**核心链中、除 M0/m5 发布收口外的最后一个实质 todo**（3.1.0 窗口内另有 5 个
provider plan 仍有开放 todo，按总计划 §7 各自 `deferred_to` 顺延，不归本 plan）。它固化的是
**契约**，不是跑宿主：材料未到位也能完成。真实宿主验证（AI 记账 H1A/H1B/H1C）是 H1 的事，以
本契约为入口；本 plan 不宣称任何宿主语义 PASS。

codex 起草前裁决（2026-08-22）：先冻结三件实施事实——SSOT 放哪、哪些入口只链接、M6 怎样算
完成与 H1 的边界——再动文档；严格裁剪，不做成第二个 M5A；默认不新增 schema、CLI、manifest、
状态、门禁或 ledger；不新开 OpenSpec change。二轮修正：SSOT 必须自包含（发布件拿不到 `.cursor/`）、
blocker 三级路由、provider 事件落发生阶段的既有证据、入口盘点在批准前完成并冻结。

## 2. 设计来源（不是运行时依赖）

- 总计划 §8.1 准入按 Change Unit 判断；§8.2 宿主批次 1 最低证据与八条运行时验收场景；
  §8.3/§8.4 借款与保单的观察指标；m6 todo 正文；
- 总纲 §10（真实宿主驱动）、§10.3（首个真实宿主最低证据）、§11.2（provider 自然事件的 G8
  验收分工）。

`.cursor/` 被 `scripts/release-excludes.json` 排除，消费者拿不到这些文件。因此 SSOT 对上述内容
**精炼后自包含成文**；本 plan 与 SSOT 可在 maintainer 注释中标注来源，但 SSOT 正文不得以"见
总计划 §x"代替规范性内容。

## 3. SSOT 落点裁决（已冻结）

唯一发布态 SSOT：`skills/reference/real-host-admission-and-feedback.md`。

理由：`skills/reference/` 是发布件内 agent 直接消费的共享 reference 集（`host-harness-readiness.md`
回答"harness 能不能跑"，本文回答"真实宿主复杂需求能不能进、进了怎么回流"，平级互补）；不放
`docs/`（维护者视角，agent 不读）、不放 `.cursor/`（不进发布件）、不塞进 project SKILL（会产生
多份副本）。

## 4. SSOT 文档固定结构（十节，自包含）

正文写成"对 agent 说的话术 + 预期回报"，不写 CLI 清单（宿主工程指引口径）。

1. **适用范围与边界**：何时必须走本契约（单次 spec/plan 无法承载的 App 单部件大型需求，已有
   演进工作区 `<features_dir>/<blueprint_id>/`）；与普通 Feature、与 H1 的边界。
2. **CU 级准入最小输入清单**：仓库/入口/构建方式、当前需求切片与可确认的验收意图、SE 契约/
   全局不变量/App 责任、代码/数据/接口/测试事实可发现、当前 CU 引用的蓝图设计切片已合法
   disposition 且达设计可施工门、UI 单元的高保真与页面验收口径、外部事件场景的模拟注入/测试
   数据/contract fake；逐项写"谁提供、缺了算什么"。
3. **缺失输入的三级路由**（不为记录 blocker 先造 CU，不复制 P1 gap）：
   - 蓝图设计 / 外部权责问题（外部契约未裁决、产品语义未定、风险未接受）→ 蓝图
     `decisions_and_gaps`（既有 `open_decision` / `blocker` disposition，带 owner、needed-by、
     解除条件）；
   - 已存在 canonical CU 的 design / execution 阻断 → 该 CU 的 `blockers[]`（既有字段：id、影响
     门槛、责任方、原因、解除条件、事实来源；`observation=machine` 必须声明 probe，`observation=human`
     可无 probe 但必须声明 `authority_ref` 与 `source_revision`——与 `change-unit-validator.ts` 既有
     校验一致，不得以 `resolved: true` 自报）；
   - 尚不能形成 canonical artifact 的仓库/访问/构建问题 → 当前入口（Skill/CLI）halt 并 report，
     不创建任何持久化对象。
   明示"不因其它远期页面高保真未到阻塞已具备条件的非 UI 单元"。
4. **参考实现与跨仓依赖**：仓内/已登记惯例由 Agent 自行发现；只有当前设计明确依赖跨仓权威实现
   或兼容基座时才由 SE/用户提供可解析定位；已声明依赖但无法访问 → **按所处阶段沿 §4.3 路由**：
   蓝图已存在则记蓝图 `decisions_and_gaps` blocker，canonical CU 已存在则记该 CU `blockers[]`，只有
   尚不能形成 canonical artifact 时才 halt-report；不存在参考实现本身不阻塞。
5. **SE 人工契约输入口径**：已有权威契约只引用并校验；缺失时只形成消费需求/提案（蓝图
   `open_decision`/`blocker`），"需求/提案 ≠ 已冻结契约"，Maison 不替云侧裁决；契约链形状引用
   发布件内 `skills/project/app-component-blueprint/SKILL.md` 的既有表述，不复制。
6. **三批宿主目标与证据口径（自包含）**：批次 1 AI 记账"证明能用"的最低证据清单；必须真实验证的
   八条运行时场景（冷启动/恢复、后台自动写入、晚订阅、多页面刷新、分类修改、重复事件、进程重建、
   账号隔离）逐条写"证据长什么样、落在哪个既有产物"；批次 2 借款"证明能复用"、批次 3 保单
   "证明可复制"的观察指标精炼成文；不预定施工队列。
7. **缺口回流路径**：宿主发现问题 → 分类（框架缺陷 / 输入缺口 / 宿主问题）→ 框架缺陷走
   `consumer-framework-boundary.md` 的"上报回灌源仓"通道（不本地热修；带 harness 报告完整栈/漂移
   清单）→ 源仓以 OpenSpec change + 回归防线沿原建设链修复；输入缺口回到 SE/产品 owner；宿主
   问题回宿主。写成话术与预期回报。
8. **provider 自然事件记录**：宿主期自然发生的 provider 缺失降级/替换/退出及其真实代价，**写入
   事件实际发生阶段的既有 report/evidence**（该 phase 的 reports 目录/证据清单）；closure 只按既有
   obligation 派生引用，不手改、不充当通用事件容器（`provider_observations` 仅承载三类证据 adapter）；
   未自然发生的类型不阻塞宿主完成声明。
9. **材料未到位的诚实口径**：不造假宿主、不伪造语义 PASS、不阻塞 3.1.0 机械能力发布；发布说明
   标注"G8 语义验收待完成"。
10. **H1 完成声明的最低证据（自包含列出）**：真实蓝图与 SE/开发/测试共同评审、至少一次真实质询
    frontier、多个真实依赖的 CU、至少一次受控调和、单元级与部件级闭环、真实构建/测试/界面/真机
    证据、缺口回灌与回归防线、稳定知识归位。

## 5. 入口盘点结论与冻结清单

盘点（2026-08-22，批准前完成）：发布内容中**不存在**真实宿主准入 SSOT——`host-harness-readiness.md`
是 harness 工具链前置（Tier_1/2）；`goal-mode-operations.md` 无宿主准入段；`agents-entry-detail.md`
是守门规约与路径术语表；`templates/AGENTS.md.template` 的 4 处 `skills/reference` 引用均为通用条目、
无真实宿主专用入口；三个 `skills/project/*/SKILL.md` 中的"准入"是蓝图可送评审门；
`consumer-framework-boundary.md` 已有"上报回灌源仓"通道（复用，不另造）。

冻结入口（只加"一句话 + 链接"，不复制）：

1. `skills/project/app-component-blueprint/SKILL.md`——进入蓝图前的材料准入；
2. `skills/project/change-unit-progression/SKILL.md`——选中 CU 前的准入与三级路由；
3. `skills/project/component-closure/SKILL.md`——闭环前的宿主证据口径与 provider 自然事件落点；
4. `skills/reference/consumer-framework-boundary.md`——回灌通道处回指本文的缺口分类。

不加：`agents-entry-detail.md`、`templates/AGENTS.md.template`（避免所有普通任务全局加载 M6）。
