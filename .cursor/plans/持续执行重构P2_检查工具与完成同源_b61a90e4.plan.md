# P2 检查工具与完成同源

## 1. 范围与单一落点

> 架构对齐：[architecture.md](../../docs/architecture.md) §2、§3.1；I1、I3、I6。

依赖[P1](持续执行重构P1_专用会话与恢复底座_4d8e7c12.plan.md)，执行[总goal](../goals/持续执行与单一完成闭环_原生会话及证据同源重构_72b6f0d9.goal.md)的D2–D4/D7/D10、K4–K8和相关M表。P3删除旧调用路径，本阶段不在旧循环外围再新增一次“自愈管理器”。

输入组装沿`verify-feature-completion.ts:readCurrentDispositionInput`原位收编，移除“必须已有全部phase summary/closure才有事实”的前提；唯一处置继续由`check-disposition.ts:resolveCurrentDisposition`给出。完成评估接在`verify-feature-completion.ts`，返回适用终点是否满足、未完项及责任对象/动作/证据、披露和release readiness；Feature/CU/root/request都传入各自终点，不能各重算结论。名称若调整，原函数只留下薄兼容读取或删除，不能两个权威长期并存。

`GoalPhaseRuntime`消费该结果：有当前可修工作→把同一份反馈交专用作者；有设计修订→交设计单元；欠验证→执行缺失/受影响的工具或独立核验；外部条件→保留缺口，继续无依赖工作；只在goal定义的出口停止。不能在执行层另按check ID、phase、exit code推业务成败。

## 2. 检查即工具

> 架构对齐：[architecture.md](../../docs/architecture.md) §3、§4、§6；I1、I3、I5、I10。

给作者的公共命令统称 `maison check`，在既有harness CLI/runner上提供薄入口；调用现有checkers/provider和同一当前事实视图，不复制规则。作者中途检查与最后完成检查使用相同授权、适用性、输入规范化、异常归因与缓存条件。完成触发本身不强制真跑全部工具；先查看有效证据，只补缺失和受影响部分。

这里的 `maison check` 是能力名称，不要求安装新的全局命令；实际复用 `harness/package.json` 的 `npm run check -- ...`（`harness-runner.ts`），构建复用 `npm run compile -- ...`。由协调器按当前工程/单元生成可直接执行的完整命令。现有 `--phase` 只作为检查族选择兼容参数，不再触发phase作者/收口编排；未显式选检查族时从当前义务选适用工具，不能默认跑全套。

检查族仍可称spec/plan/coding/review/ut/testing/catalog等，职责是“验证什么”，不是“哪个作者现在有资格工作”。Skill `produces/verifies`继续描述输入、产物和核验能力，移除阶段身份写入许可、必须先取得上游回执/closure的要求。真实输入前置与安全控制边保留：没有设计决策不能猜测试期望，没有可执行包不能伪设备结果；但可以先做不依赖该输入的代码/文档工作。

`harness-runner.ts`、`report-generator.ts`、`phase-closure-finalizer.ts`收齐机器/独立发现再生成下一步；工具的原始FAIL、未执行与当前剩余任务分开呈现。未分类旧SKIP不全局升级FAIL；checker异常是验证缺口，不冒充产品失败或PASS。阶段回执/closure不再由作者填写以获得循环资格；必要原始报告和正式签发继续由机器维护。`sync-closure`等旧接口在P3收编，不能成为新作者的隐藏关卡。

同一次评估复用同一事实视图，写入/发布/影响证据的事件变化后重读；不跨变化缓存准入结论。证据复用沿现有输入哈希、实际读写归属、执行键和当前验收，不因phase名相同重用，也不因里程碑切换一律作废。设计文字同步而实现/验收未变只做必要记录校验；真正接口、验收或依赖变化必须重验受影响部分。

## 3. 机器生成与作者判断分工

> 架构对齐：[architecture.md](../../docs/architecture.md) §3.1、§4、§6；I3、I8、I9。

以现有schema字段定义为SSOT：writer、作者指引、校验和比较都读同一份定义。迁入b84机器边界时明确业务provenance与机器观测时间/身份不同，不能把所有来源声明一刀切删去。

机器负责稳定技术ID/版本与源摘要、admission整块及current_slice、已有明确关系的引用闭包和投影、视图容器、发现来源目录、正式结果外壳、命令参数和报告路径。作者负责需求理解、业务决策、契约语义、适用性、未知的引用关系、实现与测试设计。独立Q/verifier负责实质回答/反证、验收覆盖、断言强度和可测试性；真实调用结束且产物合法后机器生成身份/只读/完成外壳，不能靠作者写`isolated_context: true`自证。

生产接线必须包含`createAppViewInstances`、`buildDiscoveryBundle`、`createIndependentQuestioningResult`、`writeBackAdmission`/`currentBlueprintSliceId`和`materializeBlueprintSkillInputs`。新run的技术编号在作者动笔前给出，已有编号稳定。空容器或未知适用性不得生成pass；业务冲突保留，不以“机器投影”自动覆盖权威决策。

设计/CU准备一次收集所有**能够独立判断**的问题，去掉`change-unit-design-preparation.ts`“constructable才看契约投影”的遮挡；`blueprint-skill-projection.ts`不得一个映射错误抛出就隐藏其它可判定缺口。真的依赖未知时给出“因X未能检查Y”，不补假的通过。已知节点/flow关系唯一时机器完成状态契约等机械投影；含糊或矛盾才交设计作者。业务字段完全相同、只是搬记录位置不应再启动整轮作者＋Q。

范围准备工具直接从原请求、当前蓝图/CU、适用义务生成需求、请求动作、design refs及哈希，再使用既有准备/检查/签发。作者不手拼长`--prepare-scope --requested-phases ...`命令；不把机器已知参数遗漏当作设计失败。原先scope候选过期时重算本身是确定工作，不重做无关业务设计。

按b84已有清点覆盖实际生产设计检查集合，而非全仓所有约200行文本：产品真值/结果依据保留；账本/格式按可重建事实机器修或回具体产物，不单独终止整单；能力缺口保留未知。清点结果复用现有检查处置表与报告，不建立新运行注册表，不为减少阻断把实质缺陷归成账本。

## 4. 独立核验、增量复核与正式证据

> 架构对齐：[architecture.md](../../docs/architecture.md) §3.1、§4；I1、I3、I4、I9、I10。

作者可以同时写实现和测试，但不能自己批改通过。独立核验必须查看当前验收→用例→断言及失败路径，比较旧断言是否被删弱、跳过、mock替真值；已有机器保存/对比检查继续作核验材料。真正获授权的规格变更先由设计单元重签，不能以“修测试”消除原验收。真实构建/测试/设备/视觉结果只有对应工具执行器可写，testing正式证据写保护由P1接入，P2全链验证不能被绕过。

修订复核输入必须有：上一轮公开报告及未闭合项、实际改动、受影响的契约/依赖、已有效证据与新反证。无关结论沿用；受影响结论重评；缺可信原报告时说明后完整核验，不能凭作者“只改两处”自行缩小范围。Q外壳格式错误只修外壳或让独立Q补格式，原作者业务未变不重写；内容否定全部回作者；机器不得改Q回答。

旧发现如果已被当前有效实现与真实测试反证解决，先交原验证职责核实；有据驳回后关闭发现并披露文档漂移，不为了台账一致重跑全部下游。只有文档同步且验收语义未变时重新绑定即可；反例是接口或真实期望变了，必须保留重新验证。证据路径解析复用既有路径规范化，坏引用精确诊断且保留其余有效证据，能打开文件不等于发现已证实。

## 5. 反馈、共享设计与收敛

> 架构对齐：[architecture.md](../../docs/architecture.md) §3.1、§4、§5；I2、I3、I4、I5、I10。

### 5.1 一份反馈交原会话

> 架构对齐：[architecture.md](../../docs/architecture.md) §3.1、§5；I3、I5、I10。

当前处置包含每个未完项的事实对象、验收/发现引用、责任单元或验证职责、需要的动作、证据与影响。作者提示、工具输出、报告、恢复、停机说明都渲染这同一份；下一次执行者输入必须带本次可处理的全部必修项，不只给“FAIL请重试”。本单元可修直接继续，不再构建“下游发现才回退”的专用路径。报告中他方工作明确交接，不能当本阶段必修或让发现者假改权限。

问题是否必修与“谁有权改变该对象/谁验证”分开：运行栈落在测试文件不代表应改测试，先核实真实原因。保留现有结构化候选、独立核实与拒修理由；作者拒绝后将证据交独立核验并回流，不能用拒修自动结案，也不能让对方永远不读理由。内容重复且无新事实归收敛判断，不靠新增候选ID获取无限重发。

### 5.2 跨单元变更

> 架构对齐：[architecture.md](../../docs/architecture.md) §2、§3.1、§5；I1、I4、I9、I10。

CU发现范围不足或共享设计需变时，结构化问题回设计单元原会话；原CU保留成果，仅等待确实依赖该变更的工作。设计单元依据原请求和已有授权修订，进行独立Q、完整检查、发布并重绑受影响CU；无需人为重启整单。真正需求/验收变更或不可逆行为仍请用户，授权与是否有人看屏幕无关。设计发布失败保留候选，不删草稿让后续恢复读不存在的original-context。

不新增“临时不受约束阶段”、owner/角色注册表或万能路由。改造现有责任解析去掉phase链裁剪，保留对象和验证职责，结合当前root/CU即可定位。其输出若找不到合法责任对象，记具体缺口，不能派队首兜底或自授写入。

### 5.3 以完成定义判断无进展

> 架构对齐：[architecture.md](../../docs/architecture.md) §4-I10、§5；I2、I3、I7、I10。

同一授权与适用验收下，作者两次检查之间没有相关改动、只是原样重跑时，复用同一有效结果，不构成新的可比评估，不推进比较窗口，也不能据此触发新的无进展中断。作者改动后，受影响检查实际完成仍无验收改善，才参与无进展判断；新的有效独立证据解决子项也可构成进展。结果复用、比较资格与基线更新由同一入口处理，不能清掉既有FAIL、必需未知、未满足验收或P1未恢复越权约束，不能以复用代替完成。

在每个有真实结果的完成评估点，比较同一请求/验收版本下未满足义务、已核实发现及相关证据。评估覆盖专用会话运行中：作者在会话内调用的检查结果与相关产物变化进入同一事实视图，不能等作者报告结束才比较。沿现有工具结果/事件和运行观察触发，消费已完成的有效结果，不为监控重复执行工具或全量检查。复用现有事件/结果与`shouldHaltNoProgress`入口，不新建指纹账本、分值或完成百分比。

连续比较沿现有重复判断窗口（相同问题连续两次完整评估）起作用：上一份反馈确已送达、执行者有机会处理、该验证已实际完成，仍无证据改善时可暂停。同一问题集合在已完成的评估之间往复出现也应识别，使用既有可比历史；不能通过改编号/描述或来回修改文件规避。若核验发现新的子问题或证实已有子问题已解，即使总数量暂未减少也可继续；不能仅用计数大小决定。作者进程仍在运行不构成豁免；只有所需检查仍未完成、尚无可比结果或缺有效事实时，不能据此断言无进展。

运行中已判定无进展时，协调器立即经P1既有中断通道停止该会话并停止派发新工作；确认实际停止后保全成果与调用事实，进入可续暂停。不能把“进程还有输出/文件仍在改”当成验收进展，也不能以结果尚未知为由捏造无进展；不新增配额或计数器。

每次暂停保留具体未完项、最近收到的反馈、已经尝试的修法和可继续条件；用户明确继续或真实条件变化接回同一工作单元。不把无进展写成不可恢复终态，也不因冷却到期在同条件下自动重拉。模型持续改字节但所有验收原地踏步仍应暂停；无产物变化但新的独立证据关闭问题可以推进。

## 6. 验收与消费清单

> 架构对齐：[architecture.md](../../docs/architecture.md) §1、§4、§5；I1–I10。

必须实际走生产入口：设计准备/校验→CU投影，公共检查→当前处置→作者输入，原生执行结果→核验/检查→完成签发。最小组合覆盖a21473的机器current_slice、Phone缺口同时发现状态映射、真实invalid_otp矛盾、只改两处引用时增量Q、坏Q恢复、编译缺陷修好后继续、末尾新发现仍回原会话。模型替身只按收到的反馈行动，不预知应该改哪一处。

必须补一对运行中回归：同一专用会话连续改相关文件、反复调用检查且可比验收/发现无改善，作者尚未退出时即被协调器中断，成果保留且可续；相同运输下检查结果/独立证据证明有进展，作者继续，不被输出频率、改动次数或调用数误停。判断和中断接线走生产入口；验证尚未完成时不误判无进展。

反例包括：作者删弱断言、手写测试PASS；metadata-only假进展；同样数量但已有子项有据解决；未评完先停；只改文档却重跑真机；真实接口变化却复用旧结果；存在框架缺口而无依赖工作仍被停；测试与完成入口对同事实得出不同结论。

本阶段统一接口必须列清P3全部消费点：`harness-runner`/request-phase/compile及其它工具、report-generator/NEXT、phase-closure-finalizer/receipt、goal runtime、assess、feature-track、upstream gate、质量轴/债务、verify-feature-completion、change-unit-completion、component-closure-runtime、progress/report/status、独立verifier输入与Skill模板。未接消费者不能宣称完成同源；P3逐个切换并删除旧重算。

对有重复真跑风险的UT/真机/视觉用计数替身验证“只补受影响”，真实执行能力由既有provider及P4实际任务验证。关键返回旧错误分支应使对应场景变红，不做无意义全矩阵。目标回归/类型和本批官方npm test通过；不运行宿主整单、不把开发组合当业务终验。
