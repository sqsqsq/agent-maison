## 3. 返修中断接续（t2）

责任入口为 `goal-phase-runtime.ts` 的 `pendingBacktrackCompletion`、completed 补发、`replayAttemptedSignalIdentities`、
`restoreBacktrackCandidatesFromEvents`、`applyInvalidationsToResume` 与 advance；invocation 真值复用 `agent_invoke_end`/`agent_process_settled`、
completion/timeout/failure、既有 continuation 和原 request 候选。原 `related_input_snapshot` 与 decline/rebuttal 是消费源，不重算旧基线。

完成事实的生产点为 runtime 的现有 `agent_invoke_end` writer：与 `terminal_failure_observed` 并列持久化可选 `completion_observed`，
不等到 gate 后的 verdict 才留证。共享判据按当前 `invoke_id` 精确读取本次 end，不能借同 phase 其它 invocation 的成功。
历史 end 缺字段时，先用同一 invoke 的 `phase_verdict.completion_observed`/`agent_failed` 作为完成或失败 fallback；
连对应 verdict 也没有且 exit 非零、无 timeout、无失败终态时才是 unknown，仅在最新返修窗口内有界重跑 owner。
正常完成观测＋清理非零＋gate 前崩溃据 end 走 validation-only，signal attempted 照常计入；timeout/turn.failed 据本次 end 回 owner。

建立一处可复用的窗口判据，先区分三件事：进程已经结算；owner 返修尝试完整结束；缺陷经相关 verifier/独立下游验证解决。
completion observed、明确正常终态及自然成功退出保留原完成语义，非零 exit 本身不决定失败。timeout、API/工具终止或 unknown interruption
且无有效目标证明时，不把 settled、有 exitCode 或普通 compile/static PASS 当作完成返修；不依赖网络原因词表。

窗口未完成时：

1. 原候选（native/provider/legacy/signal 均含 evidence_refs）和 request 原始相关输入继续保留；目标 phase 仍是待完成的 owner，不发新的 `phase_backtrack_requested`，不增产品回退数，不重置任何计数。
2. 同进程续作与跨进程 resume 采用同一判据；不给未完成窗口计 signal attempted，不发 completed，也不以新 static PASS 清该窗口的失效或 advance。
3. 对历史“中断 settled → 错误 completed → static PASS”只重评最新且未被后续 request 替代的窗口真值，旧事件字节不改；若无目标处置证明，恢复到该窗口 owner。较早窗口已有新 `phase_backtrack_requested` 时由新窗口取代，不能一直拦 advance。已封卷的可信完成 run 仍遵守原封卷，不改完成边界算法。
4. 使用既有 interrupted continuation、partial artifacts 与有界恢复额度：timeout 走现有连续 timeout/未完成 advance/阶段重试统计，已识别 transient 走 events 回放的 `transientRetriesUsed` 与 `max_transient_api_retries`，unknown/其它执行失败走现有失败恢复与阶段重试上限。静态 PASS 事实可保留，但未完成返修的 action 必须经过这些现有计数分支，不能因 PASS 跳过计数，也不为 pending window 另造额度。恢复计真实下一次阶段调用和活跃时长。耗尽总资源、真实授权/完整尝试后的 no-progress/one-shot 等仍可停止，不能无限续作。

正常 owner attempt 的源码变化只证明实际尝试，`phase_backtrack_completed` 不能声称产品已修好；独立下游重新验证决定缺陷是否消失。
目标已被既有有效逐条验证证明满足，或全部当前轮候选有来源核验通过的成立拒修，允许零改动收口。普通静态 PASS、随便改一个文件、日志变更不替代目标证明。
完整 signal attempt 后的累计 one-shot、首次成立拒修豁免与第二次拒修规则保持；本批只纠正中断被误计为完整尝试，不改变真实完整尝试后的资格。
相关输入 unknown 不证明零改动或完成。取消固定 2 后，unknown 快照、legacy/provider 候选和 scope replan 在没有其它现行熔断事实时，
只受剩余总调用/总活跃时长兜底，最坏可以耗尽剩余硬预算；不承诺不存在的额外收敛，也不据此新造熔断。
真实 invocation 中断仍消费第 4 点的现有恢复计数；不把所有无改动一律判失败，也不把所有非零终止洗成 transient。

## 4. 资源预算与视觉裁决

### 4.1 同任务资源预算（t3）

总阶段调用 `max_total_turns` 和总活跃时长是本周期的硬资源边界；沿 `foldBudgetLineage`/`partitionExecutionSessions` 跨 resume/successor 累计。
可信完成周期边界维持现有算法。删除 `DEFAULT_MAX_BACKTRACKS=2` 在 runtime 各回退路径、`tryScopeReplan` 与 `adjudication.backtrackBlocked`
的硬停机资格；若常量与 max 参数已无有效消费者，删除它们，而非用 Infinity 伪装现行额度。
`backtracks_used` 继续从请求事件计数，并用于原 transaction id/诊断；旧 `backtracks_limit` 可读取为历史政策，不展示为本轮剩余硬额度。

原 run 能执行的同任务修复在原 run/原责任阶段继续。保留既有相关输入完整可比且未变＋同缺陷集合的整轮重复熔断、完整 signal one-shot、
拒修/反驳、越权重复、transient/timeout 等其它有界恢复。unknown/legacy/provider/scope replan 没有其它有效熔断时可以耗尽剩余总资源；不引入新的所有熔断统一系统。
纯文本变动、correction 文案或 successor 身份不新增授权，不刷新总调用/活跃时长，也不作为已经修好的证明；真正新增需求与模型切换仍按原权责/出生机制处理。
撤掉“固定次数耗尽后写 requirement increment 换机会”的 runtime/prompt/Skill/运维文案，实际硬预算耗尽仍按既有授权入口调整，不自动扩大。

历史兼容放在当前裁决/接续边界共享，不在 reducer 下游另建 halt_reason 分类表：仅当最新未完成停机唯一失效原因是已退役 `backtrack_limit`，
且原范围/owner 可执行、原总调用/活跃时长有余量、无其它当前终局时，允许按当前规则接入原 run。
旧显式 TERMINAL 不作为永久拒绝这个已退役政策的依据，但原事件、report 历史诊断不改写。普通重发、显式 `--resume`（前台/detach）、
attended `prepare-run`、supervisor 的接续必须消费同一重评结论，避免一个入口放行另一个入口仍看旧 TERMINAL/冷却而永久不唤醒。
本批先保证公开接续正确；不新增旧 backtrack_limit 停机专用的 validation-only 优化。
重评不越过 owner CAS/liveness、sealed/superseded、testing 越权写、真实授权、总资源耗尽、已证明无进展等边界；latest 其它原因或混合终局不能通过旧原因豁免。

### 4.2 视觉有效裁决同源（t4）

以 `visual-diff-check.ts.effectiveScreens` 承接授权视图，再把 severity/`isHardPixelContract`/既有 `isTierDowngradedResidual` 的消费收编到该有效结论。
原 `visual-diff.json` 中 provider 观察、must_fix、缺陷 source/hash 与真实载荷留存；provider 仍不输出 verdict。writer 对 minor-only 与 soft 档可降级屏给 `warn` 候选，保留 `pass` 候选要求 defects 为空的规约，
但最终 gate 仍检查当前身份、覆盖、region/receipt、确定性信号，不因 writer 候选通过而略过它们。

有效屏按以下固定边界消费：

| 有效事实 | gate/channel evidence/candidate/debt 行为 |
|---|---|
| 授权结构化 minor，且每条 must_fix 都只被 minor 支撑 | 报告 WARN；不因 raw fail/must_fix 阻断产品证据，不产 coding 候选，不开启 blocking debt；hard/soft 同现行 minor 规则 |
| soft 自报 major（含合法独立 provider），非 blocker/非 T8 major，指令完整锚定 | 沿既有档位降级与 downgraded_screens 记债务/阻断发布，不产候选；不因 provider 自动 raw fail 绕过降级条件 |
| hard major、T8 major、任意真实 blocker | 按现行 ratchet、独立证据与候选规则消费；短信 clipping/blocker 继续阻断并交 coding |
| excluded/scope_unclear | 原授权过滤和披露/交 owner 澄清；不能据意见扩范围或擅删实现 |
| legacy 未结构化 must_fix、未知锚定/严重度、原始 fail 另有独立失败事实 | 保留既有保守产品失败/legacy 候选或结构补证路径，不能因有一个 minor 就整屏放行 |
| 缺/旧 screenshot/build/覆盖/receipt 或无效 provider | 不宣称产品 PASS；testing 重采/重评或现有能力处置，不凭不可信证据发 coding 修复 |

soft provider major 的降级来自既有 plan 6644ea45 和现行规格，不改变原授权/独立 critic 规则；实际消费行为会从旧 blanket fail 回 coding 变为按档位记债务且阻断发布，MIGRATION 必须披露。

gate 的 failScreens/must_fix hits、productTruthIntact/channel_evidence、blockingDefectPass、候选 collector、visual-debt 与报告沿同一有效视图/当前 gate structured 产物。
runtime 继续只读取与当前 run/attempt/gate 时间匹配的报告，不自行复制保真决策。不单把 fail 改成 warn而让 must_fix 的独立拒证残留。
同屏/同 must_fix 有 blocker 与 minor、重复 screen_id、未锚定指令和其它确定性 placement/T8 失败按保守现行规则处理。
TC-007 四屏声明与 AC-8 仅两屏的宿主产物矛盾仍交用户，不为此扩覆盖 schema；本批按实际授权与声明目标一致消费。
