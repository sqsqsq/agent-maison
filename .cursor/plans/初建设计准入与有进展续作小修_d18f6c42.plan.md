# 初建设计准入与有进展续作小修

## 修改与删除点

1. **机器准入。** admission 整块（含 current_slice 和编号）由机器生成；新请求在作者动笔前分配并提示技术标识，作者仅在业务 gap.needed_by 引用。已有编号和关联保持。旧蓝图缺编号且 gaps=[] 时按 blueprint_id 补齐；仅缺编号且有 gap 的旧输入由机器一次分配标签、使旧质询失效，保留原 needed_by/status，交真实独立质询核归属；歧义回作者修业务 gap，不猜当前/远期、不靠新编号洗掉 blocker。写回、完整 checker 与消费者同源，元数据缺失不得误报“契约未冻结”。
2. **完整反馈。** 每轮合并全部机器问题和当前独立质询否定，一次交真正责任方。删除 readInitialDesignDelivery 的 denied 早返回及 admission 前缀猜归属；框架异常走框架处置，设计语义仍由作者和真实独立质询负责。
3. **有进展续作。** 删除 runtime 原5486（初建）、5618/10530（设计修订作者）三个局部次数停止点，以及 design-repair-unattended 原649（事务for上限）/777（否定后次数终止）两个事务停止点，保留原请求总预算。复用 shouldHaltNoProgress：签名覆盖全部当前问题，比较正在改的草稿/蓝图/CU候选/scope，精确排除机器元数据，缺文件为已知不存在，读失败或无可比基线为 unknown。不递归删除同名业务字段，不新增状态、停机原因、登记表、计数账本或指纹系统。

## 验收与边界

1. a21473 副本经公开 next/resume 在 0 新增作者/质询后进入 CU 分解签发；不执行分解，不算 Feature 完成。
2. 超过原 3 次后，问题或相关产物仍有进展且总预算足够即可继续；覆盖事务内部、未发布草稿及 CU-only 变化。
3. 同问题且可比相关产物确无变化时沿既有 no_progress_guard 暂停；metadata-only 不算业务进展，unknown 不误判；supervisor 不因时间到自动重拉。
4. 用户通过既有 force-resume/force-takeover 明确继续或真实条件变化可沿公开入口接回，保留累计预算与历史；旧 TERMINAL 原件不手改 events/manifest，不把人工起后继作为机械问题默认恢复。
5. 真实设计缺陷仍不准入，总预算耗尽不新增调用；保留来源、独立性、写界、授权与总预算。
