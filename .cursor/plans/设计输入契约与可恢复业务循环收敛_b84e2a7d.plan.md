# 设计输入契约与可恢复业务循环收敛

## 1. 两步边界、目标与权限

本计划服务于原始目标：Maison在用户目标、授权、真实质量和硬预算内尽最大可能完成请求，可恢复的机器字段、描述冲突及工具问题应交回正确责任方，不把恢复工作频繁交给用户。四条总原则以docs/overview.md §1.2.1为SSOT。

用户于2026-10-29改为两步：

1. 独立前置[初建设计准入与有进展续作小修 d18f6c42](初建设计准入与有进展续作小修_d18f6c42.plan.md)，负责机器admission整块及稳定编号、完整问题反馈、初建与设计修订取消局部内容次数终止、实际候选进展和既有no_progress_guard恢复。其实施、返修与验收以短plan为准，不在本计划重复登记开发。
2. 本计划只承接剩余的设计输入契约、确定投影、设计检查三档处置，以及普通阶段和剩余消费者的全阶段续作政策。当前只修订计划范围，不实施第二步；所有todo保持pending。

统一停止政策取代本计划旧版的“作者选择slice_id”和“保留1+max_retries_per_phase内容上限”：任何阶段/职责都不再只因内容调用次数终止。仅在目标达成、原请求总预算耗尽、真实授权边界、需要人/框架修复的故障或外部条件、无进展暂停、用户取消时收口或停放。只有存在可检测探针且已检测到条件变化时自动续作；无变化不自动重拉。真实能力/验证缺口不是产品FAIL；不依赖它的工作继续，必须依赖它才能安全执行的工作停放，完成必需证据不齐不能通过。

约束：有人/无人共用业务判断，运输与呈现可以不同；设计、施工和单职责请求保留适用输入与终点，不强绑蓝图/CU/六阶段。授权只来自可信原请求；范围/验收实质变化仍回权责阶段重签。复用现有准备、调用事实、处置、恢复、预算和投影，不新建运行器、状态机、注册表、进度账本、指纹系统、停机原因或人工确认点。

本次计划修订只修改本文件及a47末尾追加。9f t4、f3 t7/t9、a47 R5/H1及其它未覆盖联合项不因开发回放变绿。旧4a最多34轮为旧样本的单独授权，不执行或计入本计划；不提交、打包、改版本、操作真实宿主/手机。

## 3. 实际设计检查的三档清点

以当前设计生产入口真正执行的检查集合为范围（现有数量约200，仅作定位参考，不写死数字）。在既有报告中按检查ID、实际消费点、保留/删除/改出口、最小理由形成一份清单；已有检查够用不新增检查。清单服务本次实施，不建运行时登记表或逐文件证据矩阵。

| 裁决档 | 处理 | 必须守住的边界 |
|---|---|---|
| 产品真值、真实结果依据 | 保留需求/范围、契约与设计引用、真实独立质询、关键验收及发布完整性；真实缺陷返责任方，阻断依赖它的动作或完成 | 不能靠模型自报、旧部分PASS、外壳完整或运输退出码放过实质缺陷；真实授权/硬预算照原边界 |
| 账本格式与可重建过程材料 | 确定值由机器生成；格式错误回真实责任方修复/重建；只影响记录美观的删除硬阻断、保留披露 | 字段若同时承载实际范围、关联或真实结果依据，保留其业务核实；不能把业务内容机械填绿 |
| 能力/验证缺口 | 沿既有verify/defer/wait出口保留未知及责任，不判产品FAIL；无依赖工作继续，依赖工作停放 | 必需检查没执行或结果未知不能PASS；只有可检测变化才自动续，无变化不重复耗资源 |

## 4. 作者输入、确定准备与真实质询

作者提供需求解释、适用性、设计取舍、接口/数据/状态/恢复、验收及gap业务关系；Q负责独立问题、证据、答复与disposition。机器提供已知容器、身份、来源/hash/时间/路径、可计算引用、调用事实与确定投影。来源可读不等于语义已核实，observed/inferred或业务映射不能自动转成通过。

admission整块（含current_slice和编号）遵循第一步机器所有权：新run作者动笔前已分配并告知技术编号，业务gap.needed_by引用它；已有编号不换。旧缺编号且有gap时不猜当前/远期关系，语义歧义交作者澄清；机器编号本身不交作者选择，不靠新编号移走当前blocker。这里只对齐剩余schema、比较器和消费者，不重列第一步生成算法与实现任务。

剩余切片消费者包括blueprint-discovery.ts:validateTerminologyFacts（当前约176行）：术语gap的当前/远期停放仍直接读取admission.current_slice.slice_id，第二步改为消费currentBlueprintSliceId，与准入、写回使用同一有效切片解析。保留当前gap不得停放、合法远期gap可披露的原语义，不因读取入口不同误拦或放过术语缺口；本次只补消费清单，不修改生产。

createAppViewInstances与buildDiscoveryBundle接入原草稿准备/修订事务。真实输入不足时明确缺口；不能为调用helper把适用性默认填绿、覆盖已有作者材料或造已准入空蓝图。重复准备无变化不重写。调用前准备在原pre_snapshot之前；结束先保存原输出、post_snapshot及写界检查，再机器派生，不改原调用快照、签请求或报告补证。会话与后台顺序相同。

derive/validate、写回、CLI、人读投影、修订发布、CU/readiness读取同一完整准入结果。诊断按实际字段/条件报告，不以“契约未冻结”掩盖缺技术标识。作者误填可重建机器字段时按真实输入重算并披露，不因不同就终止；不能重算保留验证缺口，真实设计/质询否定不能被覆盖。

复用requiredQuestioningScopes、DISPOSITIONS，将createIndependentQuestioningResult接入受管调用：模型只交实质items，真实独立调用成功结算、写界及形状核验后机器生成provider、隔离与完成外壳。调用事实缺失走能力/验证缺口，不填true、不删除管理上下文降级。question_id按现有scope规则生成；有语义的owner/证据不能从名称推断。

## 5. 全阶段统一处置与可恢复续作

### 5.1 当前观察、责任与动作

沿readInitialDesignDelivery及既有处置输入组装入口，一次汇总当前机器问题、全部Q项、有效设计/P2/CU/阶段事实；复用resolveCurrentDisposition、resolveRepairResponsibility及共同转移策略。无CU初建使用真实request事实，不伪造phase summary、receipt或closed。P1/P2仍是领域步骤，普通施工仍走原Feature/CU；同一动作复用读取，发布或相关事实变化后重读。

| 当前事实 | 下一动作 |
|---|---|
| 可确定机器材料缺失/过期 | 原writer准备/重建后检查，不派作者机械填表 |
| 当前职责可修的实质设计/输入问题 | 完整合并送责任方，保留有效草稿和原证据；不按次数截断 |
| 作者有效，只欠真实Q或Q格式/覆盖 | 原事务只补Q，坏Q不得反复当成功缓存；设计变化仍回作者 |
| 完整准入/当前阶段已成立 | 进入原下一职责；蓝图PASS、CU ready、child签发均不等于原请求完成 |
| 真实能力/验证缺口 | 记录未知与受影响依赖；无依赖工作继续，依赖它才能安全执行的工作停放，必需证据不齐不完成 |
| 真实授权/外部条件或需人/框架修复的故障 | 原等待/授权/故障出口，说明责任方与解除条件；有可检测探针才自动观察恢复，无探针不伪造自动唤醒 |
| 同问题且相关可比业务产物无进展 | 沿原no_progress_guard暂停；无变化不自动重拉，显式继续或真实条件变化接原请求 |
| 原总预算耗尽、用户取消、目标完成 | 按真实终点收口，保存原成果/未决项，不清历史或偷增预算 |

next/self-check、派发、status/progress/report及恢复说明共同消费上述事实，展示层不另定动作。正常退出不等于业务通过；框架异常不能一律送作者空转。原请求完成只认全部适用正式完成证据。

## 6. 机制准入与范围裁剪

本计划的收益分别对应：机器字段无人负责→确定准备；部分PASS/反馈遮挡→完整结果和反馈同源；自报过程计数拦停→退役无可信来源的阻断；有进展却因局部次数停止→全阶段续作与原预算/无进展恢复。均优先修接线或删平行判断。

不新增持久字段、状态/事件类型、停机原因、manifest、注册表、owner表、进度账本或协议。若实际发现既有通道确实不能表达已批准场景，先回计划评审说明具体场景、收益与不可复用原因，不藏进实现。检查ID能原位更正诊断就复用。
