## 1. 背景与问题定义

用户原始问题链（2026-08-07 收敛；claude 两轮 + codex 两轮 + 用户场景裁决）：

1. AI 开发端侧 UI（Android/鸿蒙原生）不考虑大字体、适老化、异形屏；高保真单案例表达不了
   变体；内网无多模态。业界调研结论：变体不靠画、验证不靠看——规则化 spec + 参数化矩阵 +
   结构化验证；**约束生成的前提是组件库承担适配下限**。
2. 但 maison 全程不认识消费者工程的组件库：开发阶段从不分析可复用组件；找到了也无判据
   判断适用性。
3. 三场景全覆盖：完全无匹配（新建落位）/大致相同（改 vs 新写）/完全一致（直接复用）；
   台账全工程视角，跨模块引用**不得打破 architecture DSL 依赖约束，除非用户主动要求**。

**v1 只解决三个问题**（codex 首轮 review 定案）：工程里有哪些可复用共享组件；本需求为何
选择 reuse/configure/adapt/evolve/custom；AI 新建共享组件时能否发现绕过已有资产。**本期不
宣称已证明组件支持大字体/适老化/异形屏**——静态检查只提供风险提示，真正证明留给后续
渲染/契约/真机证据。

归属分类学（与 e4b9c2d6 §1 五类载体表互认）：

| 问题 | 归属 | 本 plan 范围 |
|---|---|---|
| 「开发前必须先检索复用」 | conventions（e4b9c2d6 dogfood 首批条目） | 否（条目内容归彼） |
| 「工程里有哪些组件」 | component-index（源码派生、可重建、git 入库） | t2 |
| 「组件是干嘛的/怎么选」 | component-catalog（人逐条 y、增量策展） | t3 |
| 「本需求选了哪个/为什么」 | 既有 contracts.components 内嵌 asset_selection | t4 |
| 「组件适配风险的静态信号」 | index.static_checks（诚实命名，非能力证明） | t5 |
| 「组件真支持大字体/读屏吗」 | 渲染/契约/真机证据 | 否（后置） |
| 「设计稿组件对应哪个代码组件」 | 可选 Figma bridge | 否（不立项） |
| 「AI 偷偷平行造轮子」 | 未登记=确定性门禁；语义重复=review verifier | t4 |

1. **仓内现状核实**：module-catalog 停在模块粒度；ui-spec 组件树是设计侧产物，与仓库

## 6. 验收方向（对齐 codex「最小验收标准」）

- **机制侧**：无 component-index.yaml 的工程 spec/plan/coding/review 行为完全不变
  （零惊扰，文件存在=唯一开关）；相同源码生成字节一致的 index（幂等）；index 过期能被
  --phase catalog 检查发现；catalog 合并时只能引用 index 中存在的组件；有 index 时
  页面/UI 组件类 components 条目必有 asset_selection（强制谓词，工具类 kind 豁免）；
  五级裁决在钱包 dogfood 三场景（无匹配/部分匹配/完全匹配）各走通一例。
- **门禁侧**（fixtures 命中全部目标分支——「测试须命中目标分支」硬学习）：
  component_ref 引用不存在 FAIL / resolution 值域外 FAIL / adapt|evolve|custom 缺
  rationale FAIL / reuse|configure|adapt|evolve 缺 component_ref FAIL / 依赖边实时计算
  非法 FAIL（提示三出路）/ custom 落入库模块出口导出但重扫 index 无此组件 FAIL /
  custom 落 feature 内部不触发登记 PASS / index 有 catalog 无 → uncurated WARN /
  新共享组件适用检查项 fail|unknown FAIL（含「交互组件热区静态判不出 → unknown →
  FAIL」负例，防 not_applicable 洗白）/ 存量组件 unknown 不阻断 PASS / curated
  staging 合并引用不存在 id FAIL / dangling（重扫后）WARN 不阻断 / index 过期 MAJOR /
  export * 出现 WARN / 一跳具名 re-export 组件被正确收录 PASS / **强制谓词三分支**：
  无 index 旧合同 PASS · 有 index 页面/UI 组件类条目缺 asset_selection FAIL · 工具类
  kind 缺省 PASS / index 文件不存在 SKIP；不误伤存量工程。
- **既有消费方回归**：spec-loader（归一化）/coding-host-rules（nav_destination 页面
  注册判定）/plan-visual-parity-check（组件 name 映射判定）/check-exit（空缺省构造）在

  组件真的翻 fail）；检查名与报告措辞不得出现 verified/supported/已验证字样。
- **verifier 接线侧**：review 上下文装配含 index 摘要与相似组件 live 调用点（文件存在
