## 3. 八项有界改造

### 3.1 统一有效义务与证明，收编分散的完成判断（t1，④兼①）

**结构评估结论**：采用 §8 的 B 方向，保留既有义务、证据和冻结/修订载体；执行队列、复用和完成从同一次有效判定派生。完整 workflow 继续提供责任归属与依赖顺序，不把序列化的 `phase_chain` 改成固定全链，不新增阶段状态表。本节替代原先“在四处各补一次同步”的实施方式；原四种事故均保留为验收。

**复用入口**：`execution-scope.ts::resolveExecutionScope`、`feature-track.ts::collectResolvedScopeFacts/resolveScopeRevisionProposal`、`goal-run-creation.ts` 的有效范围/修订读取、`harness/scripts/utils/goal-runner-phase.ts::rebuildOutcomesFromEvents` 及现有失效事件处理。两种范围载体继续通过 `resolveEffectiveScopeSource` 选择，既有真实质量验证器继续提供证据结论，不搬到另一套检查里重写。

统一含义：**已满足＝本次有效义务有适用、未过期、且未被后来修复请求或失效事实撤销的证明**。不是“阶段曾 PASS”，也不是“现在不在剩余队列”。判定保留 required / unknown / not_applicable 及输入定义证明；后两者不得冒充测试 PASS。

- 区分授权域、待执行队列和历史记录。Feature 的责任归属沿已授权 workflow；request 仍按原冻结授权范围，不随队列缩短丢失已授权责任，也不借全工作流扩大单职责授权。
- 新增或重开真实修复义务时，由现有修订/回退事实确定其责任阶段和受影响的后继。旧 PASS 不能证明后来新增或重开的工作；未受影响的初始合法复用不因证据早于本 run 而误失效。重跑产生的新 PASS 经真实闭环核验后可以收口。
- 同一可信问题再次出现时，依据当前有效证明重开对应义务，不按“id 已存在”直接跳过；尚未解决的同一次请求仍幂等。保留拒修裁决、重复回退与无进展熔断，不重置计数。
- 普通回退与范围修订共用证明失效/责任入队的判定。`backtrack_to_phase` 即使没有修复候选、没有修订提案，也按授权域判断目标是否可达，不以 `chain.indexOf(target)` 的当前快照裁定。已授权目标经同一判定使自身及受影响下游失效、重新入队，再走原回退事务；不要求虚构候选来取得恢复资格。只有目标超出授权域才使用 `backtrack_target_absent`，按 t2 说明责任方及所需确认。继续使用既有合法事件/修订入口，不合并或重写历史事件，不直接改冻结链。
- 状态重算在阶段结果、修订、恢复和完成边界执行，PASS 与 FAIL 同入口；不在心跳上重扫全仓，不引入常驻缓存/失效图。按原输入/输出所有权区分正常下游产出与上游真实变更：UT 合法新增测试文件、testing 写报告不能让 plan/coding 证明过期而反复回卷；真实契约或被测源码变化仍使相应证明失效。
- 生产者和消费者同次调用复用已解析输入与有效证明结论。run 依据原事件顺序和闭环证据；无 run 依据原 feature 修订及阶段闭环证据，不伪造 run 事件。无 run 的新证明必须能与本次修复对应，不能只因磁盘 summary 为 PASS 自动补证；复用既有修订 `applied_at`、证据 `generated_at` 和输入绑定核对先后/适用性，不能用文件 mtime。定义在本次裁定中合法补齐的 InputBinding 不套用“必须在修订落盘以后才存在”的执行证明规则。
- 已冻结的 manifest/历史 scope 原字节与指纹校验保持；先验证原记录，再派生当前可执行视图。不能把派生视图回写出生记录，或用它冒充上一条记录的指纹；真正修订仍走原通道。不为每次 PASS 另写一条持久范围事件。
- `outcomes` 保留作执行、耗时及报告历史；不能再独立决定跳过工作。剩余队列、复用视图、完成核验及状态展示消费相同有效结论；保留现有 post-agent/validation-only 恢复，不能为清理完成判定而删除已跑完 agent 只需补验证的恢复能力。

**必须替换的旧决策，不能在旁边叠加新函数后仍让旧逻辑裁决**：

| 现有分叉 | 收编结果 |
|---|---|
| `feature-track.ts` 按 completedPhases 给所有旧义务补磁盘证明 | 只接受对当前义务有效的证明；不再凭阶段级 PASS 批量关闭后来工作 |
| runtime 修订后按 outcomes 的最后 PASS 选游标 | 由同一次有效义务/证明判定选下一可执行阶段 |
| `revokedPhasesByRevision` 仅识别“有证明变无证明” | 新增、重开、撤销及受影响后继共用判定；实时与恢复不另各算一版 |
| runtime 仅在 PASS 后补回过期 reused 阶段 | 取消 PASS 特例，阶段结果的共同出口处理有效证明变化 |
| repair-candidates 遇到同 id 立即跳过 | 区分重复登记与问题重新出现，不保留“已存在＝已解决”的捷径 |
| runtime `backtrack_to_phase` 用 `chain.indexOf(target)` 判断目标是否存在 | 先按授权域判定；已授权目标经共享失效/入队判定恢复，包含无候选、无修订提案的上游缺口；越授权仍停放 |

修正 `trigger.check_id` 错标，记录真实候选/来源，不用首条 `node_options_injection` 充当触发者；不新增检查或触发账本。正式完成仍须通过原真实质量/权限核验，不能把队列为空当作交付完成。

**验收**：t8 用 b9ac66 #3/#4、b5ada8、b23184 的真实输入调用生产判定；同时证明 spec 合法复用、plan 实际执行、coding 随上游修改失效、新 PASS 可收口。另走生产 `backtrack_to_phase` 入口：无候选、无修订提案，目标在授权域内但不在当前队列时仍恢复；单职责 request 的目标越出请求阶段时仍停放、请求确认；71c521 的链内普通回退保持。实时、resume、无 run 的共享判定口径一致；合法既有证明、未知定义、not_applicable 反例保留。UT 测试文件和 testing 报告的合法生成不令上游重跑，真实上游输入变化仍失效。旧记录原指纹不变；10-12 后继不能丢必需义务，10-14 原件缺失如实披露、不以手写事件替代。交付时附 §8.2 的逐读点处置表，不以抽查少数调用点代替完整接线核对。
