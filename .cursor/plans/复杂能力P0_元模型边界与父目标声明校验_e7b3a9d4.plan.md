# 复杂能力 P0：元模型、边界与父目标声明校验

上位约束：总纲 `.cursor/goals/复杂能力建设目标_能力架构蓝图到部件演进与变更单元闭环_75411223.goal.md`
§2/§3/§12；总计划 `.cursor/plans/复杂能力建设3.1_单部件复杂需求闭环首期总计划_6f2a9d8c.plan.md` §6.1。

## 1. 范围与非目标

**做**：

1. 三类对象最小契约成文（OpenSpec spec，normative）：对象身份、引用方向、双入口语义、
   五类信息权威边界、unknown/open-decision 与非法输入的失败语义、稳定内核与 provider
   接缝语义（总纲 §11.2 的 change 化）——P1/P2/P3 的 change 必须在此契约内建设，
   不再各自发明；
2. 父目标声明机器校验：并入 `scripts/check-plan-version.mjs` 既有入口与测试通道，
   兼容语义与现有扫描器一致（声明了才校验、未声明零行为、legacy allowlist 不受影响）；
3. AGENTS.md 人工核对节收编。

**不做**（对应总计划 §6.1「禁止长出」与 §11 准入清单）：

- 不建蓝图/CU 的运行时 schema、loader、目录结构（P1/P2 的活）；
- 不建 goal_requires/goal_provides 注册表、依赖图或进度聚合器（advances 是非累加
  追溯标签，语义已写入 spec）；
- 不建 plugin loader、插件注册表、插件包分发或动态发现——接缝语义零实现增量，
  本 plan 代码面仍只有扫描器；
- 不建跨单元运行状态、可手改完成台账、常驻机制；
- 不动 harness（本 plan 全部代码面在 `scripts/`，dev-only）。

## 2. 交付物与验收

| 交付物 | 位置 | 验收 |
|---|---|---|
| 元模型契约 spec | `openspec/specs/complex-capability-meta-model/spec.md`（经 change 归档进入） | `openspec:validate --strict` 通过；P1–P3 change 以其为准入约束 |
| 声明校验 | `scripts/check-plan-version.mjs` + `scripts/plan-version-lib.mjs` | 九类 fixture 全绿；全仓 plan 零新增告警；`check-plan-version` default/release 双模式通过 |

## 3. 双轨执行纪律

按用户裁定（08-13）：轨道 B（本 plan t1）先行起草评审；轨道 A（3.0.0 收口）由 release
分支承载。**t3 起的实施必须等 t2 放行**——以隔离 cutoff 做一次快速事实调和，确认扫描器/
AGENTS.md/goal 文件相对基线的变化已被本设计覆盖（有偏差则先回填 OpenSpec 再动手）。

## 4. 风险

| 风险 | 控制 |
|---|---|
| 手写解析啃不动声明字段 | 受限解析三形态：行内 `[]`、非空 block-list、折叠/字面块正文判空；零新依赖；CRLF 用 `\r?\n`（b6d3f7a1 教训） |
| goal 目标 id 提取脆弱 | 只认总纲 §0.1 表格**行首列**反引号 id；不扫全文（防其它章节偶现 id 混入合法集）；goal 唯一匹配，零/多份与提取为零均报错 |
| 校验接线在 future 提前返回之后 = 声明 plan 全量假绿 | 校验前置于 continue 之前（D8）+ 顺延 plan 非法声明专项用例锁死 |
| 3.0.0 release 修复触及扫描器 | 逐提交前向传播；t2 表面重跑受影响核对，不整体 merge 分支 |
| 声明校验误伤存量 plan | 未声明零行为 + 全仓回归断言"零新增告警"进单测 |
