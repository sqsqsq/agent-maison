## 硬约束

1. **可信 evidence 后置精修**：t1 只消费通过现有绑定校验与根/级联裁决后的聚合结论，不重复
   读盘、不绕过信任校验、不用“product_actionable 为空”替代明确分类。
2. **无 evidence 行为不变**：普通模式、旧产物、非 testing 的 failure kind 与控制流零变化。
3. **全目标预检、幂等且拒绝半写**：t2 的全部 targets 均为必需输入；missing、不可读、损坏、
   未知 upstream drift 或后验失败均须在写盘前整体拒绝；二次运行验收是全部 targets 字节一致。
4. **零输入优先**：t3 在锁屏身份、键盘容器、数字完整性、几何或冷却状态任一不可信时零输入。
5. **状态迁移不是等待**：允许在确认锁屏后执行一次非秘密上滑来展示 PIN 键盘；禁止用 sleep/
   多轮盲重试掩盖缺失动作。
6. **隐私边界在源头收口**：冷却识别只看认证/Bouncer 子树；UnlockOutcome.note 及其所有事件/
   返回值投影只记录稳定 rule_id 与固定文案，任何 UI 原文、通知内容和凭据都不得进入 notes。

## 探针证据

### A. 锁屏四帧 UI dump

宿主原始文件（2026-07-30）：

```text
D:\1.code\SimulatedWalletForHmos\scratch\unlock-probe\
  layout-0000ms.json          wake 后立即
  layout-0500ms.json          +500ms
  layout-1500ms.json          +1500ms
  layout-stable-keypad.json   手动上滑后 PIN 键盘稳定态
```

关键事实：

1. `0000/0500/1500ms` 三帧均只有 `id=Text_Digital` 的 2×2 时钟数字，集合为
   `["0","1","5","9"]`；等待 1.5 秒不会展示 PIN 键盘。
2. stable-keypad 帧的真实键盘祖先链包含
   `ScreenLockRootComponent → BouncerView → BouncerView_Screen_Lock_Home →
   Digital_PSD_Input_Tip`。数字 Text 节点的 `originalText` 为 0–9，`text/id` 为空，
   每个数字位于可点击 Stack 内。
3. stable-keypad 只有在**手动上滑后**出现，因此现场缺口不是“再等一会”，而是自动流程缺少
   展示 PIN 键盘的非秘密状态迁移动作。
4. `id=numKeyBoard` 的 9 个节点是 ABC/DEF/GHI/JKL/MNO/PQRS/TUV/WXYZ/+ 字母提示层，
   不是数字键。
5. `originalText="未识别成功，双击屏幕重试"` 与
   `"未识别成功，点击此处重试"` 是人脸失败提示；现有裸“重试”正则会误判冷却。
6. 目前没有真实 PIN 惩罚冷却文案样本，因此不能把未知可疑文案直接判为安全；用
   `ambiguous → 零输入` 保留安全边界，禁止故意输入错误 PIN 采样。

fixture 入库前只保留锁屏根、键盘/时钟/认证提示所需最小节点与属性；删除真实通知栏、用户内容、
设备标识及无关子树。另用纯合成通知子树构造“通知正文含重试/retry/disabled”负例，证明其不参与
冷却判定且任何 notes 投影均不含该文本。

### C. patch 脚本误触实证

当前替换：

```js
/(?<!npm run openspec -- )(?<!npm run openspec:validate)(?<![\w-])openspec /g
```

在已 patch 文本 `npm run openspec -- list` 上仍会命中内部 `openspec `，二次运行产生
`npm run npm run openspec -- -- list`。归档动作要求重跑该脚本，因此这是当前 release path
缺陷，不是仅靠操作提醒可接受的风险。
