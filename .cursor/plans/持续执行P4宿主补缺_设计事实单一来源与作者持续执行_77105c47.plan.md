## 4. 长期交付　作者主导持续循环，工具签发证据

**设计单元。** 原设计作者在自己的专用会话内完成设计、调用只读预检、看反馈并修复。从正式接收入口收编出共用的只读准备与校验函数，作者预检和提交事务调用同一函数判定选型、映射与施工投影，反馈一次列出此时可判定的全部缺口。预检使用当前草案和候选，正式写入由已有接收方对当时的绑定重新核对并原子提交。作者可完成的预检已就绪就签发独立质询，把“尚待独立质询”保留为待取得的证据，避免把最终准入 PASS 当成发起质询的前置。独立首审依原需求、参考图及验收查漏。返修仅重开原阻断、缺项和确有影响的业务承诺。新证据表明存在具体产品后果时仍可阻断。 [候选预检与投影](../../harness/scripts/utils/blueprint-skill-projection.ts) · [初设生产入口](../../harness/scripts/utils/initial-design-delivery.ts)

**CU 施工单元。** 同一 CU 的作者在会话内连续运行构建、UT 和真机工具，读正式反馈，修可修项并复验。工具按现有 run、CU、产物和材料身份签发可消费证据，实际工具失败保留 FAIL。协调器及时消费这些证据，按缺口或过期输入补检，已有同输入的可靠结论得以复用。阶段名继续作为 Skill、检查族和人读里程碑。作者退出只是一次交回。独立核验沿用 `9e46c71a` 的适用策略、`verifier_request`、subject、报告与否决复用，在相关证据用于推进或签完成前完成。独立发现带原依据回原作者，作者自述不能签审查、UT、真机或完成。构建、UT、设备、独立 Review、阶段 verifier、设计质询、视觉核验按各自职责取证。各 adapter 共用现有执行入口，同一原生会话按准确 ID 接续，确实不可续时按当前有效材料重建专用会话。 [持续执行入口](../../docs/operations/project-entry.md) · [工作单元协调器](../../harness/scripts/goal-phase-runtime.ts) · [独核签发和复用](跨适配器阶段独立核验_统一签发与执行_9e46c71a.plan.md)

**停止与恢复沿总纲 §2.2 的五个出口。** 它们分别为（1）目标有正式证据并达成，（2）用户时限或取消，（3）真实授权边界，（4）确需人或框架处理的环境或执行依赖，（5）成果保全后的可续无进展暂停。无进展按完成义务和可比较的实际检查结果判断。有确定恢复动作或新依据时执行，有未决独立证据时继续等待其交回，局部故障只挡依赖它的工作。计量数据用于复盘，沿用已有状态、义务、事件与权限机制。
