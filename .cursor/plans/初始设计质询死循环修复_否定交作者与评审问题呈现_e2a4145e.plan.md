## 两条设计路径的路由

遵循 [P2 §4](持续执行重构P2_检查工具与完成同源_b61a90e4.plan.md)。`blueprint-questioning.ts` 的 `parseIndependentQuestioningOutput` 统一调用 `visual-provider-invoke.ts:605` 的 `extractJsonObjectFromText`，取出对象后沿用现有质询结构、独立性和业务校验。必要时把提取函数移至无依赖公共工具，在原模块保留导出。现场回填、恢复复用、历史反馈、进展评估和评审投影凡读取质询返回正文，都走同一解析入口。原始字节按调用保存。

| 质询交回 | 下一步 |
| --- | --- |
| 给出实质否定 | 本轮全部否定及其依据连同机器修复项交给设计作者。先消费否定，无需证明它对最新稿仍然成立。作者可据此改稿，或举证说明已解决、应拒修，再由独立质询复核。已有送达、交回的历史沿原轮次消费，恢复时不把同一份否定反复当成新反馈。 |
| 通过，准备据此准入 | 从真实独立调用的原件取被审稿，以 `blueprintAuthorContent` 比较当前作者稿。运行中修复若同时提交 CU、同批候选或架构草稿，也核对当次交给质询的作者候选内容。排除质询回写和机器元数据；作者内容改变或无法确定被审稿时重新独立质询。其他准入检查及发布事务的并发校验照常执行。 |
| 整段取不出对象，如只返回“我已完成检查” | 原文留在调用目录。第一次交回给原质询方一个明确的补格式机会，继续当前设计稿；缺可信原件时沿既有独立核验路径恢复。历史中的通过不能替代本次交回。 |

**当前性只在用通过结果准入时检查。** 删除逐一核对 `source_ref` 快照及哈希的唯一改动点是 `design-repair-unattended.ts:210–217` 的 `reusableDesignQuestioning` 循环，8 处调用共用这项修改。引用及其变化仍可供独立质询取证。另在 `initial-design-delivery.ts:302–305` 收窄把质询降为 `incomplete` 的条件，先将真实交回中的否定交给作者。初始循环的当前观察、历史评估与恢复按同一分流读原件，避免用“通过是否可复用”筛掉否定。保留调用完成、独立身份、只读写界与发布前并发校验。

**运行中的设计修复事务一并修。** 代码核对表明，有效否定碰到缺失引用时，`evaluationOf` 令 `known=false`、`completed=false`。正常质询交回没有待重建的 provider 会话，`continueRepair` 遂返回 `false`，`repairStop` 以 `execution_scope_unresolved` 结束本轮，作者收不到返修。在 `design-repair-unattended.ts:1012–1013` 对有效快照中的缺项采用 `goal-phase-runtime.ts:4746` 已有的 `{ exists: false, contentHash: '' }` 表示；整个快照采集失败仍是未知。这样有效否定可形成已完成的评估并触发作者续修。

**无改善按 scope 比较。** 两条路径都把有效评估送入 `evaluateCompletionProgress`。沿原 run 重建已送达的否定和作者交回记录；首次否定先送作者。原验收条件相同、作者已交回、相同的被否定 scope 集合再出现且其余验收无改善时，走 `no_progress_guard`。问题与回答的措辞、条目顺序和调用编号不进入质询问题身份。

**重复坏交回如何停下。** 在初始设计 `previousDesignWork` 和设计修复 `questioningPrompt` 中，“上一轮原件”统一选最近一次已完成且可用的质询交回，前稿、未闭合项、差异和原件路径均取自该轮。没有可用交回时保留首次阅读上下文。其后无论出现多少次不可用交回，提示只追加一次固定行“上次质询未交回可用对象，请按既有格式返回。”坏原文、解析位置、次数、新调用编号及路径只留在 run。补格式接回当前质询职责和草稿。评审文档在派质询前重渲，且在质询写界快照内，因此不可用轮次也不得改变其内容、计数或链接。第一次坏交回新增固定诊断；第二次同样坏交回后，下一次准备的指令和业务文件快照均与上次一致，既有 `prepareExecutionContext` 的无新条件出口在派发前暂停。

**跨路径的业务输入收敛判据另起 plan。** 本批只闭合上述两条设计路径，包括无效交回不能靠新的日志路径买到无限重派。普通工作单元、独立 verifier、检查工具的派发比较不在本次范围；不恢复阶段次数或总轮数配额。

## 人读评审文档

在 `blueprint-review-inputs.ts` 与 `blueprint-review-projection.ts` 的现有生成链替换“最近一轮全部条目”表，表仍放在 **G 节参考区**。按同一设计的有效质询顺序对照 `scope_ref`、该 scope 的处置和两次质询所读的作者内容。关闭取后续有效质询对该 scope 的关闭处置；漏项或不可用交回不能证明关闭。

| 现有原件可确认的事实 | G 节呈现 |
| --- | --- |
| 当前为 `blocker` | 列出仍未关闭的范围、问题与依据。 |
| 当前为 `open_decision` | 列出待人决定的事项。 |
| scope 曾被否定，后续关闭；两次质询所读的作者内容有变 | 保留原问题及复核结果，表述为“改稿后关闭”。现有原件只能证明先后顺序，不逐题归因到某一具体改动。 |
| scope 曾被否定，作者内容未变即被后续质询关闭 | 计为质询撤回，只给按 scope 去重的数量和指向相关有效原件的相对链接。 |

例行覆盖项留在原件。缺少处置证据时只呈现能证实的事实。现有记录不能可靠区分“有据拒修”和“同范围换问题”；这两项分类留待用户裁决，本批按上表验收。

现有 `goal-runs/<run>/phases/<质询阶段>/<调用编号>/` 继续保留完整提示、输出、前稿与交回记录，包括格式错误原文。投影只读已有事实，可重建，不另存问题台账，也不参与准入。无关联 run 的仅设计入口仍可从蓝图显示已有问题，缺原件时如实说明。
