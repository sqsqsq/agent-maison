## 3. 设计

### 3.1 facts owner 复用写边界裁决（t1）

`capability-resolution-entry-input.ts:666` 的 code owner 分配：对 `contractFiles ∪ sourcePaths` 里的每个非测试文件，先问写边界——用既有 `resolvePhaseWriteBoundary`（与运行时 `classifyPhaseInvocationChanges` 同一解析，`phase-write-boundary.ts:156/305`；入参与 `resolveFactsPhaseOwnedSources`（`entry-input.ts:237`）同一来源：有效范围的阶段链、track=full、runId、profile）得到 `resolvePhasePathOwnership(resolution, file).owner`；等于 `codeOwner` 且角色含 `source` 即赋 owner，不看后缀。写边界判不归当前实现阶段的文件（需求、契约、facts、模块目录等）保持原状：若它是研究来源仍按 `isHostSourceFile` 筛，筛不过就不赋 owner。`historical.has(file)` 与 `admitted` 收口逻辑不动。test owner 分支不动。

解析退化约定：写边界只在需要扩展 owner 判定时解析一次；`resolvePhaseWriteBoundary` 会经 `loadCodingScope` 读冻结 contracts（`phase-write-boundary.ts:114` → `capability-resolution.ts:598`，无施工绑定即抛错），spec / plan 尚未形成施工绑定是合法状态——解析失败或 `unresolvedSourcePhases` 含当前阶段时**不扩大归属**，沿用既有后缀筛选，异常不逃出 entry-input（与 `resolveFactsPhaseOwnedSources` 的 try/catch 退化同款）。反例：spec / plan 阶段、无冻结 contracts 的 run，facts 校验结果与改动前逐字相同。

效果：string.json 这类产品资源在 coding 写边界内 → owner=coding → `mayAdvanceSource` 为真 → `context-facts.ts:275` 只记 ledgerWarn（"授权内源码已变化但未登记精确 delta"），不阻断；acceptance.yaml / contracts.yaml / context/facts.md 即便被列进 `contracts.files`，写边界也不把它们归 coding → 行为不变。

### 3.2 外部缺席沿生产链一次说清（t2）

同一批结构化事实贯穿五处，各处只消费、不再各自解释：

1. **源头**：`check-testing.ts:5786` provider 缺席投影在既有 `structured` 上补 `evidence_block_owner: 'capability'`（`kind` 仍为 `visual_provider_round`）。`outcome==='invalid'` 分支不补（证据产出失败是内容责任）。
2. **绑定**：`execution-channel-evidence.ts:240` 既有读取器据此给 `unavailableOwner='capability'`，`bindVisualTc` 的 unbound 绑定带 `repair_owner='capability'`。
3. **派生检查**：`testing_channel_evidence_obligation`（`check-testing.ts:5578` 起）在阻断绑定全部 `repair_owner==='capability'` 时，复用 `visual_diff` 同一投影（`status: FAIL, blocking_class: 'externalBlocked', failure_kind: 'capability_missing'`，details 写明"视觉能力缺席，非产品失败"）；任一绑定归 coding / spec 或 kind 为 failed（证据不可用但产品侧）仍按原样 FAIL。`p0-semantic-gates.ts:844 / :935` 两项：逐 TC 评估已把视觉绑定的 verdict detail 带入 `reasons`，本 plan 让评估结果同时带上绑定的 `repair_owner`，并在组装 `acFailures` 文案**之前**完成归属判断，覆盖 `gateFailure`、无关联 TC 的 AC（`:805`）、非视觉失败与 trace 失败；只有当每一条未通过的 P0 TC / AC 都有失败来源且全部是 capability 归属的视觉缺席、trace 侧没有任何 assertion / 执行失败时，这两项检查才用同一投影（空关联集合不得用真空 `every()` 放行）；否则保持 FAIL（TC-004/005 真实失败 + TC-007 视觉缺席并存的本轮形状必须仍是 FAIL）。判据只靠结构化事实，不匹配文案。投影对象抽成 check-testing 内一个小的共用构造，不新建检查 id、不新增公开字段协议（评估结果的 owner 是内部参数）。
4. **报告与负面门禁**：同一份 capability 缺席事实同时进入 writer 的**逐 TC 行与功能轴**：由 capability 归属视觉绑定导致未验证的 P0 TC，行状态记"未验证（能力缺席）"，留在分母、不算通过也不算产品失败；`test-report-writer.ts:438` 的 functional 轴不因这类行判 FAIL（真实失败、absent、trace outcome 非 success 仍 FAIL）；不把这类 TC 列为"待修复产品缺陷"，也不输出"功能完成可推进"的矛盾建议；不得改优先级或移入 `unsupported_gap`。`:489` 把 `visualBlockers` 分成两类：`blocking_class==='externalBlocked' && failure_kind==='capability_missing'` 的只进 `gaps`（文案"视觉轴能力缺席（provider 不可用）：暂缓，非产品失败"），不置 `overall=FAILED`；其余视觉阻断照旧 FAILED。于是仅外部缺席的一轮 `overall=COMPLETE_WITH_GAPS`、`declared_verdict=有条件达标`，`checkNegativeTestingVerdictClosure`（`check-testing.ts:1229`）与裁决词解析不改一字。质量轴复用共享 INCOMPLETE 判据保持未验证、`release_readiness=BLOCKED`，不把轴洗成 PASS。
5. **汇总与最终裁决**：`testing_run_status`（`check-testing.ts:5826-5875`）新增与装机外部阻塞同款的降级：当 `blockerFails` 全部是 `externalBlocked/capability_missing` 时 severity 取 MINOR 并在面板写 `partial_readiness: capability_missing（harness verdict 应为 INCOMPLETE）`；`resolveVerdictFromChecks` 不改，`areBlockersOnlyCapabilityMissing` 自然给 INCOMPLETE。
6. **运行时（不新增探测机制）**：INCOMPLETE + externalBlocked 走既有 `classifyPhaseVerdict` 延迟路径（动作由 dependency policy 决定，不是到链末自动 halt）；`deferred_reason=capability_missing` 对应既有终态 `DEFERRED_CAPABILITY_MISSING`（`phase-transition-policy.ts:418`），其 run_disposition 为 `WAITING(external)`（`run-state-reducer.ts:35`），不是结构终局。承诺改为：**能力恢复后重发同一请求，由既有接续决策接回同 run，原 checker 重新验证**；不声称发生 `external_condition_ready`（它要求带 `probe` 的停机事件，`goal-supervisor.ts:80` / `condition-wait.ts:23` 没有 provider 恢复链，本版不加）。两处必须接通并在回放里断言：①通用 defer 分支（`goal-phase-runtime.ts:10993`）落盘的 outcome / 停机投影须让 `resolveResumeStart`（`goal-runner-phase.ts:1162` 的"最早未完成的 WAITING(external) phase 重新入队"）把 testing 重新入队，而不是算作 done 收成 PARTIAL（复用设备停放的同一投影形状，不加字段）；②goal 侧展示出口（停机说明 / progress / report）点名 provider：把 `visual_diff.suggestion` 接到既有 halt_guidance 展示位，只接线不新建文案源。assess 按 b7d2e9f4 的定义判 deferred；预算按既有 `foldBudgetLineage` 跨会话累计。SKILL（device-testing / testing 报告口径）随实现同步说明"能力缺席 = 有条件达标 + 暂缓 gap"。

### 3.3 返修先复看再交回（t3，不设门禁）
