# execution-reuse-and-report-layering

## Why

Four wastes are visible in the code itself, not just in host telemetry.

**A single UT gate builds the same ohosTest package twice.** `check-ut.ts` calls `checkUtHvigorBuild`, which dispatches `runHvigorBuild(target: ohosTest, task: genOnDeviceTestHap)` per module. The same process then calls `checkUtHvigorTest`, whose `runHvigorTest` **calls the same build again with the same arguments**. Both writes land on `hvigor-ut-build.<module>.log` with mode `'w'`, so after the test stage the compile log and meta of `ut_hvigor_build` have been overwritten by the second build — the first compilation can no longer be shown to have happened. The comment claiming "hvigor cache hits take milliseconds" is unverified: `HvigorRunResult` has no cache field, the diagnostics parser does not read that signal, and no test covers it.

**Inner and outer harness run the same device work twice.** `goal-phase-runtime.ts` runs a harness phase unconditionally after an agent invocation, and the agent already ran the same phase inside its session — including `hdc install -r` and `aa test`. Testing has same-key reuse (`decideReuse`); UT has none.

**A missing derived statistic forces a real device rerun.** `decideReuse` treats `timing_complete !== true` as a refusal, and `report_reconcile_only` puts execution facts (which package, which device, which run, which cases really ran) and derived statistics (a stale timing projection, a report duration cell) into one `issues[]` that is uniformly `FAIL` + `BLOCKER`. Those statistics are recomputable from the trace and the metas. Worse, `FROZEN_RUN_ARTIFACTS` requires **every** frozen file to be present, including the derived `frozen.device-test-timing.json`: losing one timing copy costs a full device rerun.

**Attended runs are told not to ask.** `buildPhasePrompt` expands the unattended block unconditionally, which declares "there is no interactive user", "stopping to ask = task failure", and "this overrides every phase SKILL stop-and-ask". Attended runs go through the executor bridge, where waiting is exactly the designed behaviour. The same block also states that a gate without a ledger line fails phase closure — a veto `check-receipt.ts` retired.

## What Changes

**The ohosTest package is built once per harness call.** `checkUtHvigorBuild` and `checkUtHvigorTest` take an optional per-call collector keyed by `computeHvigorInvocationFingerprint(module, ohosTest, genOnDeviceTestHap, product, test)`; only builds that pass `isHvigorBuildSuccessful` enter it. `runHvigorTest` takes an optional `prebuild` and skips its internal build when it is present. The collector is created by the caller per invocation, so a direct call to the test helper (`check-exit.ts`) keeps today's behaviour verbatim — and therefore does not take part in reuse. No global cache, no manifest, no saving is promised: what is reclaimed is one unconditional process spawn and the overwrite of the compile log and meta.

**UT gets minimal execution-key reuse on the existing testing machinery.** `execution-key.ts` gains a `leg` parameter (`hylyre` / `ut`) that decides the run-directory segment, and an artifact-set parameter so the UT leg can name its frozen files per module. The key is **whole-round**: HAP digests, selected-case digests and invocation fingerprints are each concatenated per module in module-name order and hashed, so any module's change forces the whole round to run for real — no half reuse that would let the suite ratchet see results stitched across rounds. Frozen artifacts are per module (`frozen.ut-result.<module>.json`, `frozen.hdc-test.<module>.log`), which requires `hdc-runner`'s `finalize` to stop writing one fixed `hdc-test.log` that the second ohosTest module overwrites. `resolveExecutionDeviceIdentity` moves down from `check-testing.ts` to `hdc-runner.ts` so both legs share one copy. Reuse is refused when this call produced no successful prebuild, when any input changed, when the newest same-key attempt failed, when an execution-fact frozen file is missing, when device identity is unknown, or on `--force-device`.

**A round records its own outcome before it dispatches.** `decideReuse` only inspects records that exist, so a round that crashed without writing one leaves the *previous success* as the newest record — precisely the whitewash this change forbids. UT therefore writes a non-success attempt **before** dispatch and overwrites it with the real outcome afterwards; if that pre-write fails, the round does not consult reuse at all and says so in the check details.

**Report-only reconciliation separates execution facts from derived statistics.** Execution-fact gaps stay `FAIL` + `BLOCKER`. Derived gaps are **rebuilt first** — timing from trace and metas, report body from the existing generator — and only what still fails to close becomes `status: WARN` (severity stays `BLOCKER`) with `failure_kind: derived_statistic_unavailable` and an explicit "this statistic is UNKNOWN and is not an execution-fact conclusion". No new check id, no new `CheckStatus` member, and no branch may touch a device. `FROZEN_RUN_ARTIFACTS` entries are grouped `execution` / `derived`: a missing execution-fact copy refuses reuse, a missing derived copy goes down the rebuild channel and falls back to a real run only if the rebuild cannot close (fail-closed). Unmeasured values are `null` in data and an em-dash placeholder in the report — never a fabricated `0ms`, and never the literal `UNKNOWN` in a cell the duration parser reads. Performance acceptance criteria are exempt from the rebuild path: a TC whose plan row links an `NFR-*` id declared in `acceptance.performance[]` keeps its duration gaps in the hard bucket.

**The unattended block is injected only for detached execution.** `buildPhasePrompt` takes an optional `attended` flag, fed by the runtime's existing `executorMode`. The block's text is unchanged; only its ownership splits. The mode segment goes to detached only; the gate-integrity red lines and the deterministic-detector segment are injected in both shapes, plus one honest attended line. The retired ledger veto is corrected to "audit trail, not authorization".

## Impact

- **Affected specs**: `harness-gates` (execution-key scope and evidence definition; report-only layering; one ohosTest build per gate), `goal-runner` (unattended prompt injection shape; ledger wording).
- **Affected code**: `profiles/hmos-app/harness/hvigor-runner.ts`, `profiles/hmos-app/harness/ut-host-impl.ts`, `profiles/hmos-app/harness/hdc-runner.ts`, `profiles/hmos-app/harness/execution-key.ts`, `profiles/hmos-app/harness/device-test-timings.ts`, `profiles/hmos-app/harness/test-report-writer.ts`, `harness/profile-host-loader.ts`, `harness/harness-runner.ts`, `harness/scripts/check-ut.ts`, `harness/scripts/check-testing.ts`, `harness/scripts/goal-phase-runtime.ts`, `harness/scripts/utils/testing-trace-gates.ts`, `harness/scripts/utils/execution-channel-evidence.ts`, `MIGRATION.md`.
- **Breaking**: no. Existing records without a key do not take part in reuse; the testing leg's directory layout, key fields and consumers are untouched; `hdc-test.log` becomes `hdc-test.<module>.log` and its only readers were the writer itself and two diagnostic sentences.
- **放弃的准确性**: (1) The test stage no longer implicitly re-confirms the package exists; if the HAP is deleted between the two gates, the failure degrades from "the second build re-produces it" to `hap_not_found`. (2) The UT key uses the HAP digest instead of a test-source fingerprint, so a gratuitous hvigor repack changes the key and costs a real run — hit rate only, never correctness. (3) `timing_complete` carries "derived evidence complete" with a different meaning per leg. (4) Device state can change between two harness calls while the key does not; `--force-device` and the N-round stability contract are the way out. (5) A rebuilt timing is no longer byte-identical to what was collected on the spot — if trace or metas were tampered with, the rebuild computes the error more tidily; the hard bucket still checks package, device and run identity. (6) An operator sees `UNKNOWN` in check details and an em-dash in the report instead of a number. (7) A performance AC whose plan row omits its `NFR-*` id is not recognised and its timing gap is treated as soft — a spec-authoring convention gap this change deliberately does not turn into a new gate. (8) Attended runs produce a sparser `headless-assumptions.jsonl`, which has no gate consumer.
