# attribution-and-prior-review-consistency

## Why

One host run (`20260905T103028Z-79d3fd`, read-only) shows two distinct mis-attributions and one archive gap. All three are reproducible from the code path alone.

**An attempt with no failure fact is labelled `code_regression`.** The spec-i3 verdict carries `verdict=PASS`, `harness_exit=0`, `agent_failed=false`, `stale_summary=false`, `blockers: []` and `advance_blocked=true` / `advance_block_reason=closure_open` — and still `failure_kind_classified: "code_regression"`, mirrored into `reconcile_observation.phase_outcome.failure_kind`. `resolveClosureAdvanceBlock` returns `closure_open` for "script PASS + receipt required + closure not closed", which is a workflow state and says nothing about the product code. The runner nonetheless calls `classifyFailureKind` unconditionally, and with no blocker and no agent-level signal that function runs through to its catch-all. The only gate on the event was `hasEvidence = decisionSummary !== null || hasRuntimeFailureEvidence` — "this round has a summary" was being read as "this round has a failure", so a PASS summary passed the gate simply by being non-null. The existing `PASS && action === 'advance'` erasure in `goal-reconcile-boundary.ts` does not cover this round, because its action is `retry`. The field is not cosmetic: `deriveContinuationFromEvents` reads it back into `--resume`, and `phase_outcome.failure_kind` plus `assess_recommendation.reason` inherit the same value.

**The ui-spec fidelity gate's missing-evidence failures are labelled `code_regression`.** Every FAIL exit of `checkUiSpecFidelityGate` — `unreachable`, `not_probed`, `not_yet`, `mismatch`, and "has visual capability but never checked the reference image" — says that read-back evidence was never established. None points at product source. The classifier's chain has no branch matching that id: the deterministic set does not contain it, the visual-gap predicate wants a `visual_diff` prefix, and the spec-capture-gap predicate accepted only a `capture_completeness` prefix — so it landed on the catch-all. The cost is concrete: `code_regression` triggers the retry guidance "look at files changed since the goal-run start commit and revert last round's debugging changes first", which is the wrong instruction for a spec phase that is merely missing a visual receipt.

**The goal run archive drops the report a closure actually relied on.** Seven consumers of `completed_with_prior_review` were checked one by one; six disclose it honestly. The goal phase snapshot is the exception: it resolves evidence through the current subject only, so a phase closed by reusing a prior PASS archives `verifier_evidence: null` and `verifier.report.md: null` next to a `summary.json` copy that says "closed by reusing a prior PASS, current material not re-reviewed". A downstream reader of the archive alone concludes the phase has no trustworthy verifier conclusion at all. `receipt-scaffold.ts` already contains the exact fallback shape to reuse.

## What Changes

**A round with no failure fact carries no failure attribution.** `buildCurrentAttemptFailureProjection` no longer treats a non-null summary as evidence on its own: the summary must itself state a failure (`verdict !== 'PASS'`, or a non-empty `blockers` list). A summary missing `verdict` is fail-closed and still counts as failure. `hasRuntimeFailureEvidence` — timeouts, API errors, empty output, operator interrupt, `agent_failed`, non-zero harness exit, closure finalization error, actionable defects or unverified items — is untouched and remains sufficient on its own. One change corrects three sinks: the `phase_verdict` event's `failure_kind_classified`, `phase_outcome.failure_kind`, and the halted phase outcome's diagnostic field in the goal report JSON. The local `baseFailureKind` fed to `resolveAssessHaltIncident` is deliberately **not** narrowed: that function's `exhausted` test requires `verdict !== 'PASS'`, so a PASS round always takes its fail-closed branch, and narrowing the local value would drag an unrelated halt attribution into this change.

**`ui_spec_fidelity_gate` is classified as the existing `spec_capture_gap`.** The spec-capture-gap predicate becomes "prefix ∪ exact id", the same shape the capture and toolchain predicates already use. No new `FailureKind` member, no new check id, no new blocker schema field. The alternative route — carrying `CheckResult.failure_kind` into `blocker.classification` — would change four FAIL exits in the profile plus one classifier branch, and all four exits share one attribution, so landing it by id is the shorter equivalent. `spec_capture_gap` is in none of the three halt sets, so fuse, cumulative halt and external-retry responsibility are all unchanged; the blocker stays `agent_fixable`, so feedback and signature filtering are unchanged. The only behavioural effects are the attribution itself and the disappearance of the revert guidance; the four state words B02 writes into `details` / `suggestion` continue to carry the way out and are not promoted into the `FailureKind` vocabulary.

**The goal phase snapshot archives the report the closure relied on.** `snapshotPhaseHarness` tries the current subject first and then `summary.verifier_closure.reviewed_subject_id`, taking the first evidence that passes verification — the shape `receipt-scaffold.ts` already uses. The reused case copies that report as `verifier.report.md` and sets an optional `reused_from_prior_review` on the snapshot evidence, so a downstream reader can tell "current material was reviewed" from "an earlier review was reused". The subject id is already the reused one, so no second subject field is added. The fallback subject is read from the `summary.json` copy the snapshot just wrote, keeping the loader result and the archived file same-source.

## Impact

- **Affected specs**: `goal-runner` (attribution of a round with no failure fact; missing-evidence attribution for the ui-spec fidelity gate), `harness-gates` (a run-level phase archive of a `completed_with_prior_review` closure).
- **Affected code**: `harness/scripts/goal-phase-runtime.ts`, `harness/scripts/utils/goal-failure-classifier.ts`, `harness/scripts/utils/goal-phase-snapshot.ts`, `MIGRATION.md`.
- **Breaking**: no. Old runs keep the field as history; no consumer requires it (`phase_outcome.failure_kind` is not required by the reconcile-observation schema). No halt set, actionability registry, fuse threshold, prior-review reuse policy or B02 four-state verdict changes.
- **放弃的准确性**: (1) A PASS round leaves no kind string at all, so after-the-fact triage relies on `advance_block_reason`, `assess_recommendation.reason` and the blocker list — the cost P1-8 already accepted, now extended to the retry branch. (2) `resolveAssessHaltIncident` still receives `code_regression` as its local value; it is inert on a PASS round, and aligning the literal would change an unrelated halt attribution. (3) `mismatch` and `not_probed` share one kind — at the event layer they are indistinguishable; their difference lives in the blocker's `details` and `suggestion`, both of which are fed back on retry. (4) The gate keeps no actionability registration, so a structurally `unreachable` state is still retried as agent-fixable; the way out ("honestly record `verified: unverified`") is something the agent can execute, and a human-escalation path is a policy question left to a later batch. (5) The blocker's `classification` stays empty because the id lands the attribution rather than the `failure_kind` field, so the retry prompt shows the id with `details`/`suggestion` and no bracketed label. (6) An archived `verifier.report.md` may not describe the current material; `reused_from_prior_review`, the sibling `verifier_closure` and `semantic_not_reverified` disclose that in three places, and the archive file name is unchanged. (7) A malformed `PASS + non-empty blockers` summary still keeps its signature and attribution — deliberately conservative.
