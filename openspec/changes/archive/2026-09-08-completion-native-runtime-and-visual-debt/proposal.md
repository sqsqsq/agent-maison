# completion-native-runtime-and-visual-debt

## Why

Host run `20260908T011803Z-deb77f` (bc-openCard-1) closed all six phases PASS, ran P0 13/13 on a physical device, and had all three visual-diff screens `pass` with zero must_fix — and still ended `PARTIAL` with no feature completion. Replaying `collectCleanPassIssues` on the closed chain gives eleven `needs_fix` issues, none of them a product defect. They come from three writer/consumer gaps:

1. **asset axis** — `resolveAssetAxisInheritance` called `detectRepoLayout(projectRoot)`, which walks upward looking for `harness-runner.ts`; consumer and standalone project roots both sit below it, so the gate-fingerprint recomputation always threw ("重算异常"). Independently, the same function unconditionally pushed "build fingerprint chain not wired (7.2b pending)", so a `PASS` could never be inherited. And `deriveQualityAxes` judged the visual/asset axes `UNVERIFIED` in phases that have no such check at all (ut has no visual check; plan/review/ut have no asset check).
2. **completion only accepts legacy telemetry** — `runtimeFidelityEvidenceIssue` returned "缺 runtime_fidelity" as soon as the evidence doc had no legacy `runtime_fidelity` block; the native Step Outcome v1 trace that the testing gate already validated and the phase manifest already froze was never consulted.
3. **visual debt ledger** — the ledger grouped hits by check id, but `finalizeVisualDiffHits` renames a WARN-only `visual_diff` result to `visual_diff_layout_invariants` (with `structured.kind` still `visual_diff`), so a BLOCKER `visual_diff` debt from an earlier defect round never closed; WARN sources (OCR noise, static heuristic score, top-slice remainder) were entered as open debt and blocked release forever; and the debt pipeline suppressed the visual axis in every phase, so a testing-side leftover contaminated the coding snapshot on backtrack.

## What Changes

**asset axis (D1).** `resolveAssetAxisInheritance` infers the layout from `projectRoot` (`inferRepoLayout`), and no longer adds the 7.2b build-chain issue: build/install HAP fingerprint consistency is already checked by `device_test_install` in the same testing phase (mismatch → testing FAIL, so inheritance is never reached). `deriveQualityAxes` marks a visual or asset axis `NOT_APPLICABLE` when **no check maps to it** in the phase (zero-mapped, not zero-executed — a mapped check that only SKIPs still yields `UNVERIFIED`), except the asset axis in testing, whose zero-check state is exactly the entry condition of `applyAssetAxisInheritance` and stays `UNVERIFIED` for inheritance.

**completion consumes native runtime evidence (D2).** `runtimeFidelityEvidenceIssue` reads the evidence doc, checks the recomputed run/attempt identity against the doc, reads `doc.trace_path` and dispatches on `dispatchHylyreResult(raw).kind`: `v1` → require `artifact_binding` and the testing phase manifest to bind both the evidence doc and the trace (`phaseManifestBindsRuntimeArtifacts`, extracted from the legacy validator); `legacy_unsupported` → run the unchanged legacy validation only when the doc carries `runtime_fidelity`, otherwise "既无 native v1 trace 也无 legacy runtime_fidelity"; `unsupported` (no `schema_version`, or a legacy version that also declares the v1 protocol) → `needs_fix`, never falling back to legacy even when `runtime_fidelity` is present. The native branch does not recompute schema, binding, or HAP: those facts were adjudicated once by the testing gate, frozen by the manifest, and kept fresh by the existing lineage condition.

**visual debt ledger (D3).** For the `visual_diff` source, hits are collected by `structured.kind === 'visual_diff'` as well as by id. Settlement is four-state: a `FAIL` hit, or a `SKIP` hit whose severity is not `MINOR` (a blind-tier source skipped as a whole — the pre-existing fallback, kept because nothing else blocks release when `visual_diff` is skipped entirely), opens or continues the entry; a `PASS` or `WARN` hit with no such FAIL/SKIP closes every historical entry of that source (WARN stays disclosed through the check result, summary, and `visual_debt_disclosure`, but is not debt and does not block); a round with only `MINOR` `SKIP` hits or no hits keeps history unchanged. The B08 special settlement branch for `visual_reference_viewport` is removed (its entry now closes on the next `visual_reference_viewport` WARN by the generic rule); the source registration is kept so an existing open entry remains reachable. `applyVisualDebtPipeline` suppresses the visual axis only when `report.phase === 'testing'`; the ledger is still written in every phase.

**defects FAIL, disclosures WARN (D3(e), implementation review R2).** Four producers used `WARN` to carry an observed defect and relied on the ledger to block release; with WARN no longer entering the ledger they would have stopped blocking. They now report `MAJOR` `FAIL` with severity unchanged: `render_visibility_calibrate` (node present, pixels invisible — the bc-openCard blank-PNG shape), `asset_placeholder_present`, `asset_materialization_sanity` (non-critical branch), `visual_parity_unverified_crop` (non-hard-pixel branch). Because the phase verdict, summary blockers and the quality-axis hard-fail bucket count only `BLOCKER` FAIL, those three are unchanged for these four checks; the `on_violation` lifecycle hook receives them under its BLOCKER/MAJOR contract (`specs/lifecycle-hooks-schema.yaml`) — no such hook is registered in this repo or the hmos-app profile, so there is no behavioural difference today, and a future extension hook returning BLOCKER adjudicates them exactly as any other MAJOR FAIL; the ledger opens the entry and release is blocked at testing exactly as before. Disclosure sources (heuristic score, uncaptured OCR lines, top-slice remainder, degraded multimodal evidence, soft-enforcement parity, minor-only visual-diff rounds) keep WARN.

## Impact

- **Affected specs**: `runtime-step-evidence` (new requirement: completion consumes native runtime evidence), `visual-diff` (new requirement: debt ledger grouping, four-state settlement, testing-only axis suppression; modified: the viewport requirement's B08 "WARN opens debt + special settlement" rule is withdrawn), `feature-artifact-layout` (modified: ledger `closed` now means the source settled — PASS or WARN — rather than only fixed-and-reverified), `harness-gates` (modified: the rendered-visibility observation is a MAJOR FAIL that the ledger blocks and the phase verdict ignores), `verdict-lattice` (modified: zero-mapped visual/asset axes are not applicable; testing asset keeps its inheritance entry).
- **Affected code**: `harness/harness-runner.ts`, `harness/scripts/utils/quality-axes.ts`, `harness/scripts/utils/verify-feature-completion.ts`, `harness/scripts/utils/runtime-step-evidence.ts`, `harness/scripts/utils/visual-debt.ts`, `profiles/hmos-app/harness/render-visibility.ts`, `profiles/hmos-app/harness/coding-visual-parity-check.ts`, `MIGRATION.md`.
- **Not changed**: the testing gate; `finalizeVisualDiffHits` id renaming (B07 attribution consumes it); `detectRepoLayout` semantics; lineage rules; device authenticity caps; no new fields on `device-test-evidence.json` or the ledger; no migration of existing ledgers; no writer for `runtime_fidelity`.
- **Breaking**: no. A feature whose upstream summaries were closed before this change keeps its on-disk snapshots; the existing independent-harness re-closure path refreshes them without re-running agents. Nothing forces a full-chain rerun.
- **放弃的准确性**: (1) inheritance no longer re-verifies the HAP; HAP↔source binding is non-cryptographic and rests on the review attestation (source unchanged) plus the B03 single-package ut build — cryptographic binding stays in 7.2b (3.1.0). (2) Completion trusts the testing gate's native validation and the frozen manifest instead of recomputing schema/binding/HAP. (3) WARN-level visual gaps (uncaptured OCR lines, static heuristic score, top-slice remainder, minor layout invariants) no longer block release; FAIL sources still do — and the four defect-class observations now show as FAIL rather than WARN in reports and phase summaries (they were never phase-blocking and still are not). (4) Upstream phases no longer reflect testing-side open debt on their own visual axis.
