# vision-evidence-material-binding

## Why

The `vl_multimodal` sign-off binds two different things to a single agent invocation, and both bindings cost whole rounds without buying accuracy.

**The capability proof competes with the product output for the same final message.** The runner issued a random inline canary inside the spec prompt and required the answer lines near the **end** of the invocation's final output. Host run `20260905T103028Z-79d3fd` spec-i4 is the receipt: the agent closed the phase, the completion probe observed `closure_status=closed` and tree-killed the process after the 5s grace, the answer was never written, `resolveCanaryCacheDecision` saw a non-zero exit and refused to mark the paper, and no capability receipt was issued. `verifyVlSigningChain` then rejected the sign-off — although all three reference images had been read and the refs receipt was `complete`. What was refused was the proof that *this call* could see images, not the material evidence. Cost: one wasted 6.7-minute round plus a 3.4-minute re-run.

**The material evidence is bound to the invocation too, so a closure-only round has to re-read every image.** Run `20260815T070732Z-013297` shows the other half: a closure round that did not re-read produced a partial refs receipt, the sign-off was structurally refused, and the phase ended `content_retry_exhausted`. The prompt therefore had to order "read EVERY authoritative reference image" one line after telling the agent the artifacts are FROZEN — two instructions that read as contradictory to a weak model.

**A same-name file counted as read.** `produceSpecRefsReceipt` matched a Read event against a reference image by absolute path **or basename**, then hashed the reference image itself. Reading `tmp/1-home.png` therefore signed `ux-reference/1-home.png`'s bytes.

## What Changes

**Capability truth falls back to the run-level probe canary; the invocation-level canary chain is deleted.** `buildInlineCanaryBlock`, the runner's per-invoke question/render/marking block, `capability-receipt.json` and its type/reader/writer/path, the `invocation_bound` capability scope and the `capability_receipt` event are removed. `verifyVlSigningChain` resolves capability through the existing `resolveEffectiveVisionContext` instead, and requires `scope=run_probed` **and a probe-sourced axis** — `evidence.canary_probed_at` present. That last clause matters: the `image_input_override` branch returns `run_probed` without ever reading a canary, and preflight skips probing whenever the override is set, so accepting `run_probed` alone would sign off a run holding zero measurement evidence and disclose it as "measured". The preflight probe's question, render, TTL and admissibility predicates are untouched; so are the completion probe, the grace/kill path and the separate visual provider.

**The reference-read receipt is addressed by material, not by invocation.** `spec-refs-receipt.json` goes to schema `1.1`: the top-level `invoke_id` is dropped, each ref gains `read_at_invoke`, and production merges instead of re-computing from zero — a previous round's `read` is inherited only while the image's content hash is unchanged, and a replaced image is invalidated immediately. The loader accepts **only** `1.1`; a `1.0` residue is treated as "no receipt" (its `goal_run_id` matches on a same-run resume, so only the version test can stop it). Read matching drops the basename fallback and compares normalized full paths. Verification loses the exact `invoke_id` equality and the `events.jsonl` anchor plus `receipt_sha256` comparison; it keeps run/adapter identity, empty `unread`, the manifest-recomputed denominator and the per-image hash check.

**A round that produced no invocation audit does not sign one.** Phase log paths are fixed per phase, so an attended round would otherwise re-audit the previous detached round's `agent-events.jsonl` and combine it with the current image hashes into a receipt that looks new. Receipt production now also requires `executorMode === 'detached'`; an attended round emits `spec_refs_receipt_produced` with `status: skipped`, `reason: attended_no_invoke_audit` and writes nothing. Because the gate's only reliable in-machine attended signal is run-control's `owner.kind === 'session'`, the runtime entry additionally rejects `attended` executor paired with a `process` owner — it previously rejected only the `session` + `detached` pairing, leaving the reverse open as a bypass.

**Refusals name which of four states applies.** `verifyVlSigningChain` labels every failure `unreachable` / `not_probed` / `not_yet` / `mismatch`, and `ui_spec_fidelity_gate` picks its wording and its way out from the most severe one. "No receipt" is no longer conflated with "this execution shape cannot produce one": receipts are signed after the invocation ends, so the in-phase harness of a perfectly reachable first round always sees none, and telling it to self-downgrade taught the model to abandon a reachable sign-off.

**Carrying a previous round's read is disclosed, not hidden.** `produceSpecRefsReceipt` returns `carriedOver`, the runner puts `carried_over` on the existing event, and `goal-report.md` renders one more note row of the kind it already renders. No new check id, no new WARN, no new summary field.

## Impact

- **Affected specs**: `visual-capability-routing` (capability source; sign-off evidence), `goal-runner` (closure prompt; the inline canary requirement is removed), `harness-gates` (receipt binding and the four-state wording), `feature-artifact-layout` (`capability-receipt.json` no longer produced).
- **Affected code**: `harness/scripts/utils/vision-canary.ts`, `harness/scripts/utils/effective-vision-context.ts`, `harness/scripts/utils/critic-receipt-producer.ts`, `harness/scripts/goal-phase-runtime.ts`, `harness/scripts/utils/goal-report-generator.ts`, `harness/scripts/check-spec.ts`, `profiles/hmos-app/harness/spec-ui-spec-check.ts`, `skills/feature/spec/SKILL.md`, `skills/feature/spec/reference/ui-spec.md`, `MIGRATION.md`.
- **Breaking**: no. `vision/capability-receipt.json` simply stops being produced and has no readers left; a stale one is inert. A `1.0` refs receipt is recomputed on the next round — the receipt is a derived artifact whose recomputation costs one event-log parse, so no migration script exists.
- **放弃的准确性**: (1) capability evidence drops from "this call can see images" to "this run measured that it can" — a mid-run switch to a blind model is no longer caught at signing time; the existing `pin_verify_mismatch` telemetry and `vision_output_counterevidence` product counter-evidence remain. (2) A user who sets `vision.image_input_override` cannot reach `vl_multimodal` at all (override skips probing, so no probe evidence exists); the way out is to delete the override and let preflight measure once, or to honestly record `verified: unverified`. (3) Order-trust forgery detection is gone with the event anchor — a receipt fabricated inside the invocation window is no longer exposed by it; the denominator is still recomputed from the frozen manifest and every image is still hash-checked. (4) A later round that changed the product without re-reading the images still carries the signature; the content hash invalidates it only when an image itself changes. (5) On Windows two real files differing only in case are treated as the same image (NTFS is case-insensitive by default, so this is not constructible); Linux keeps strict equality. (6) The closure prompt no longer talks the agent out of skipping a re-read, so a replaced image costs one extra round — the hash mismatch still refuses the sign-off.
