# reuse-evidence-binding-and-reference-derivation

## Why

Host run `20260907T063800Z-26c3b0` (bc-openCard-1, B07 re-acceptance) ended `HALTED / no_progress_visual_gap / TERMINAL` after i1 FAIL→retry, i2 PASS→retry, i3 FAIL→halt. B07's own behaviour held (minor signals produced no coding candidate in any round). The stop came from three framework-side gaps plus one attribution slip, none of them product defects.

**A same-key reuse round can neither write nor be trusted for device evidence.** i2's outer harness reused run `070508Z-350` by execution key (33 s). `writeDeviceTestEvidenceIfEligible` returned empty because `installExecuted` is defined as "executed and not reused", and the collector's `validateDeviceTestEvidenceBinding` additionally required a real install in this round and a run meta window inside this attempt's harness window — but reuse restores the reused run's frozen meta, whose timestamps are necessarily outside the window. Every reuse in goal mode was therefore refused as `unverifiable_must_fix` and cost one retry; the B03 reuse gain was zero in goal mode.

**The install-reuse branch returned no full HAP digest, so the execution key alternated.** `execution-key.json` records alternated between `hap_sha256_full=null` (agent-side `harness-runner --phase testing`, install reused) and a real digest (outer gate, real install). `decideReuse` only looks at the newest record; each side saw "newest run is another key" and ran the device again — four real device runs in one hour for one HAP.

**Full-page reference images were excluded in three independent places and stayed pending.** `add_bank_card_expanded` (1320×4350) and `all_banks` (1320×8312) against a 1320×2120 viewport were dropped by the capture layer, the delegated provider and the check — each with its own copy of the judgement — so the verifier never finalized them and P0 coverage failed. The authored remedy (model the long page as several screens) did not happen in the host spec, and its repeatable-scroll precondition cannot be met for long lists. The user ruled (2026-09-07) that the framework derives the **top viewport slice** by machine.

**`PASS + retry` carried `failure_kind_classified=code_regression`.** `hasRuntimeFailureEvidence` counted `unverified.length > 0` as a failure fact, although unverified means "evidence identity incomplete, re-capture pending".

## What Changes

**Reuse rounds write device evidence and are trusted by execution-key identity.** The writer's gate becomes two facts: *install fact known* (real install succeeded, **or** install reused for the same HAP with the full digest returned by the provider) **and** *device execution fact present* (real run or same-key reuse with the trace on disk). The evidence doc gains optional fields `install_reused`, `reused_by_execution_key`, `execution_key`, `reused_run_dir` (schema stays 1.1; a doc without them is a non-reuse doc and is validated exactly as before). On the collector side the record identity predicate is extracted from `decideReuse` into `isExecutionRecordReusable` (same key, `outcome=success`, trace on disk, execution-group frozen artifacts present — derived-group gaps and `timing_complete=false` are not refusals, they take the rebuild channel) and shared by both; a `reused_by_execution_key` doc must name a `reused_run_dir` whose record passes that predicate with the doc's `execution_key`, and skips the real-install and run-meta-window checks; `trace_path` consistency and the `written_at` window stay. An `install_reused` doc is checked against the current on-disk HAP full digest, computed by the goal runtime from the existing `device-test-install.meta.json` (`hapPath` / `hapMtimeMs` / `hapSizeBytes` / 12-hex `hapSha256` as prefix) plus the file bytes — any mismatch or missing meta yields "current HAP digest not verifiable".

**The install-reuse branch returns the current HAP's full sha256 from the same source as the real-install branch.** No short-fingerprint fallback (`hapSha256` in the install meta is 12 hex), no skipping of `hap=null` records in `decideReuse` (that would hide a newer failure behind an older success). Old null records stay on disk and cost at most one ordinary real run.

**Same-width taller references are compared by their top viewport slice; five consumers share one entry point.** `resolveCompareReference` in `image-toolkit.ts` classifies a reference as `direct` / `top_slice` / `incompatible` using the existing `referenceViewportIncompatible` (×1.15) **and** `ref.w === shot.w`; for `top_slice` it re-crops the top `shot.h` pixels every time (overwrite, no cache check) into `device-testing/device-screenshots/_derived-ref/<ref_id>.top<shotH>.png`. Capture invalidation and pixel metrics, the delegated provider's target assembly and prompt, the check's pre-gate and comparison index (OCR text placement), and the spec-phase pre-gate all consume it; attestation crops and reference receipts keep the original image. Comparison scope is decided by the ui-spec **declared** normalized bboxes only (`splitMustHaveByTopSlice`: `y+h ≤ ratio` in scope, `y ≥ ratio` out of scope, crossing or undeclared undetermined — no layout dump, no locator results); the provider's coverage pre-check and `visual_diff_region_attest` both take the in-scope subset as expected. Out-of-scope and undetermined must_have elements are neither missing nor passed: they are disclosed as unverified through a `visual_reference_viewport` MINOR WARN line (`N out of scope / M undetermined`) and a new `visual_reference_viewport` visual-debt source; `visual_diff` details and reference notes say "compared by the top slice; the rest is unverified". `capture_completeness_external`'s denominator is untouched. A derived slice that does not match the entry-state screenshot takes the existing pixel/OCR ratchet to WARN/FAIL — nothing is washed green.

**Unverified entries no longer constitute a runtime failure fact on their own.** The `unverified.length > 0` term is removed from `hasRuntimeFailureEvidence`; the other nine terms and the `unverifiableOnly` retry logic are verbatim. In its place the narrower fact "trusted device root failures exist" (`trustedDeviceRootClassifications` non-empty — evidence binding passed and root cases failed, including the `test_contract` / `environment` / `unknown` classifications that take the unverified route) stays a failure fact, because the existing requirement "Test-contract attribution survives retry and resume" persists `test_contract` through `failure_kind_classified`. A round whose only signal is identity-incomplete unverified entries (the host i2 shape: evidence binding refused) carries no `failure_kind_classified` / `blocker_signature`; any other failure fact in the same round keeps the attribution.

## Impact

- **Affected specs**: `goal-runner` (evidence binding for reuse rounds; unverified is not a failure fact), `harness-gates` (install-reuse digest — stacked into the in-flight `execution-reuse-and-report-layering` delta, which already MODIFIED that requirement), `visual-diff` (top-slice derivation, shared judgement, scope split, unverified disclosure).
- **Affected code**: `harness/scripts/check-testing.ts`, `harness/scripts/goal-phase-runtime.ts`, `harness/scripts/utils/device-test-evidence-shared.ts`, `harness/scripts/utils/visual-debt.ts`, `profiles/hmos-app/harness/execution-key.ts`, `profiles/hmos-app/harness/providers/device-test-install.ts`, `profiles/hmos-app/harness/image-toolkit.ts`, `profiles/hmos-app/harness/image-jimp-worker.cjs`, `profiles/hmos-app/harness/visual-diff-capture.ts`, `profiles/hmos-app/harness/visual-provider-review.ts`, `profiles/hmos-app/harness/visual-diff-check.ts`, `profiles/hmos-app/harness/fidelity-snapshot-check.ts`, `MIGRATION.md`.
- **Not changed**: execution-key inputs (no golden, no time); frozen-artifact groups and derived rebuild; retry/backtrack budgets; T8, measurement, verifier templates; attestation / reference receipts (original image); `capture-completeness-check.ts`; old `hap=null` records (not migrated, not deleted, not skipped).
- **Breaking**: no. Docs gain optional fields; a `visual_reference_viewport` WARN and a debt entry appear for same-width taller references instead of a FAIL and an excluded screen; `_derived-ref/` files appear under `device-screenshots`.
- **放弃的准确性**: (1) A reuse round is trusted on "reused record identity + execution frozen artifacts + equal key", not on this round's install and time — hand-edited frozen artifacts can fool it; tamper resistance is not a priority. (2) The install-reuse digest is the current file's bytes, same source as a real install; there is no fallback. (3) Only the entry-state slice is covered; elements outside or undetermined carry zero evidence and are disclosed as unverified (blocking release through the existing debt policy until the page is modeled per segment or the asset becomes a single-viewport image). Scope trusts the declared bbox: a misdeclared bbox puts an element in the wrong bucket (out of scope = one element unverified; in scope = a possible false missing) and is corrected by the existing defect review. A long image not cropped from the page top yields an explicit WARN/FAIL rather than a silent exclusion. (4) A round with only unverified entries carries no attribution; attribution survives whenever another failure fact is present.
