### 7.2 需要处置的差异（不自行兼容，先记账）

**D1（已裁决，plan/OpenSpec 已按此修订；不再阻断）** —— `step-outcome-v1.md` §6.1 新增的
「native（provider 侧解析）路径的 resolution」与 plan §2.1 的硬条件冲突：

| 观测事实 | request kind | 冻结包规定的 `resolution.state` |
|---|---|---|
| 目标在场 | `by_id` / `by_key` | `unique`，`selected.id` = 结构化身份 |
| 目标在场 | 其它（如 `by_text`） | **`not_attempted`**（provider 解析了它，Hylyre 没看到节点身份） |
| 目标不在场 | 任意 | `not_found` |
| provider 无法作答 | 任意 | `not_attempted` |

plan §2.1 与 T2 写的是「最终裁决 = `resolution.state=unique && candidate_count=1 && selected.id`」。
照 plan 原文实现，**native 路径上一个完全成功的 `by_text` 步骤会被判失败**（它的 resolution 是
`not_attempted`/null/null）——整片 by_text 误杀。冻结包同时明确：步骤成败由 `observation` 承载，
`not_attempted` 的 resolution **不掩盖失败**。

**裁决（用户 2026-08-31）**：契约是对的，plan 落后于契约——native 表禁止"身份不可见时报 unique"，
背后是冻结包 §3.3 的**反回填**原则，与杀死 0.4.1 `selected_id=请求id` 那个病是同一条原则。已先改
plan 与 active change，再动生产代码。最终判据：

1. 步骤成败由 `outcome`+`observation` 裁决；`selector.resolution` 是身份事实，**不是第二个成功状态**。
2. **不得**写成按 `request.kind` 的固定旁路——语义取决于执行路径：native provider 侧解析
   `by_id`/`by_key` 目标在场 → `unique`+真实结构化身份；native 侧身份不可见（典型 `by_text`）→
   合法 `passed + not_attempted`；Hylyre resolver 自己解析到文本节点 → `by_text` 也可能
   `unique`，且 `selected.id=null` + `bounds` 非空合法。
3. `unique` 严格条件：`candidate_count=1`、`selected` 非空、`id`/`bounds` 至少一个非空、
   禁止把 `request.value` 回填成 `selected.id`。
4. `not_attempted` = 无身份证据：既不改判 passed 为 failed，也不给 identity credit；
   下游的身份要求保持**未证明**，但不得篡改 outcome。
5. `not_found` 是 resolver 确认零候选的事实，**通过的 absence 断言**正是该形态。
6. `ambiguous`/`unresolvable` 按冻结契约与判定表消费，不据 resolution 另造 status。
7. ui-spec miss 仍只 WARN；runtime 不得因 canonical ui-spec 为空拒绝一个契约合法的真实运行结果。
8. **身份护栏**：P0 required/forbidden 的身份证据必须由 `by_id` 断言承载，`by_text` 的 observation
   成功不得替代身份证明（`required_element_ids` 本就是 id）——防止把身份检查换成文本断言洗掉
   identity binding。

**D2（记录，不阻断）** —— `infrastructure` 细码：冻结包为
`infrastructure.device_unavailable` / `infrastructure.transport_unavailable`；需求文 §5.4 写的是
`infrastructure.transport_failure`。Maison 按 `domain` 路由、不按细码，故无实现影响；但若哪天写死细码会踩空。

**D3（记录，不阻断）** —— 需求文 P0-12 要求「顶层 `additionalProperties` 默认关闭」，冻结包
trace root 实际是 `additionalProperties: true`（`stepResultV1`/`outcomeV1`/`pre_run_reject` 等
协议对象确实关闭）。Maison 不依赖 root 封闭，记录备查。

## 八、Phase 0 冻结包对 8 问的答案（M1 已固化）

| # | 问题 | 冻结包答案 |
|---|------|-----------|
| Q1 | `selected.bounds` 的能力事实 | **由两次修订共同解掉**。`selectorSelectedV1` 现为 `anyOf(id \| bounds)`：两字段各自可空，**至少一个非空**；contentless `selected` 与"把 request 回填进 selected"均非法。再叠加 §6.1 native 表：native 下只有 `by_id`/`by_key` 会给出 `unique`+身份。故 Maison 的硬条件应写「selected 至少有一个非空 identity」，而不是「bounds 必须非空」——原先的两难消失。最终运行时判据见 §7.2-D1（已裁决） |
| Q2 | `result_protocol` / `schema_version` 位置 | **完全解决**。root 两者都在：`schema_version` enum 四档，`result_protocol` 由条件式 allOf 在 `0.4-p0` 下强制且 const；`0.3-p0`/`0.1-p0`/`0.2-p4` 下**禁止出现**。`environmentV1.required` 另含 `trace_schema_version`(const `0.4-p0`)、`result_protocol`、`hylyre_version`、`hypium_version`、`selector_engine`。两处都在且须一致 |
| Q3 | `pre_run_reject` 是否带 `schema_version` | **完全解决：不带，且 `additionalProperties:false` 不允许带**。required 恰为 `result_protocol/command_status/phase/rejection` |
